DEE

검은 머리깃 · 흰 뺨 · 둥근 몸. 얼굴 근육이 없는 마스코트 — 감정은 전부 박새가 실제로 하는 행동으로 말한다.

SPECIES / Poecile atricapillus ROLE / 길잡이 · 저장고 관리자 STATES / 7 + LIFER DEPS / 0
01

정지 상태는 조용하게, 기쁨은 움직임에. Dee는 화면에 상주하지만 기본값은 완전 정지다. 즐거움은 전환·피드백·기록의 순간에서만 나온다. T1 클론 코딩처럼 10~20분 머무는 화면에서 Dee의 움직임은 0이며, 이때 Dee는 배경의 일부다.

00

실루엣 검증 — 16px에서 살아남는가

대비 구조는 검은 캡 / 흰 뺨 / 검은 턱받이 3단. 그라디언트·스트로크 없이 플랫 도형만 쌓았다. 16·24px에서는 눈·다리를 지우고 뺨을 16% 키운 소형 마크로 교체한다.

A · 표준 도판 (16px·24px는 소형 마크 자동 적용)

B · 미조정 축소 — 왜 소형 마크가 필요한가

C · 어두운 UI — 캡을 #4C463C 로 올린다 (검정 캡은 배경에 먹힌다)

D · 스퀸트 / 실루엣 테스트

판정 기준 — ① 32px 블러 1.1px 에서 검정–흰–검정 3단이 분리되어 보일 것 ② 단색 실루엣만으로 “둥근 몸 + 큰 머리 + 짧은 부리 + 긴 꼬리”가 새로 읽힐 것 ③ 16px에서 흰 뺨이 최소 2×2 픽셀 이상을 차지할 것. 뺨 확대 계수 --dee-cheek-k 는 이 세 번째 조건을 맞추기 위한 값이다.

01

해부 — 원 · 쐐기 · 삼각형

도형 8개. 눈은 검은 캡 안에 묻혀 있어 사실상 보이지 않는다 — 실제 박새가 그렇다. 그래서 Dee는 표정을 지을 수 없고, 그 제약이 이 시스템의 출발점이다.

06

버린 대안

설계에서 실제로 만들었다가 지운 것들. 지운 이유가 곧 이 시스템의 경계다.

✕눈·눈썹으로 표정 짓기검은 머리깃이 실제로 눈을 삼킨다. 해부학적으로 불가능하고, 16px에서 가장 먼저 뭉개지는 것도 눈이다. 표정을 못 만드는 제약이 오히려 “행동으로 말하기”라는 규칙을 강제했다.
✕정답 컨페티하루 10~25분을 몇 달 반복하는 성인에게 컨페티는 3일이면 소음이다. 남는 건 다시 볼 수 있는 것뿐 → 도감 카드 기록으로 대체.
✕하트 · 목숨 게이지틀리는 걸 벌로 만들면 「놓쳤어요」를 아무도 안 누른다. 이 앱의 핵심 기능이 죽는다. 난이도는 목숨이 아니라 dee 개수(= 남은 반복 횟수)로 표현.
✕오답 시 화면 흔들기 / 빨간 플래시벌처럼 읽히고, 감축 모드에서 정보가 0이 된다. 대신 고개 스냅(알아챔) + 정적으로도 남는 밑줄.
✕상시 날아다니는 마스코트본문을 읽어야 하는 화면에서 움직이는 것은 언제나 이긴다. Dee는 가지에 앉아 있고, 기본값은 완전 정지.
✕말풍선으로 말하는 Dee텍스트가 늘어나면 본문과 주의력을 두고 경쟁한다. Dee는 말하지 않는다. 설명은 UI 한 줄이 한다.
✕그라디언트 · 광택 · 아웃라인 스트로크16px에서 실루엣이 붕괴한다. 플랫 3색 + 클립만 사용. 스트로크는 다리 하나뿐이고 그마저 소형 마크에서는 지운다.
✕「놓쳤어요」에 슬픈 Dee단 한 번의 실망 표현이 버튼을 안 누르게 만든다. 반대로 갔다 — 거꾸로 매달려 “아래를 같이 보자”. 박새의 시그니처 동작이면서 동시에 “안 보이던 아랫면을 본다”는 뜻이 된다.
✕선행 개념 = 강등 애니메이션 (아래로 떨어짐)추락은 실패의 문법이다. 박새는 혼합 무리를 이끄는 길잡이다 — Dee가 먼저 내려가고 동료가 160ms 뒤에 따라온다. 같은 이동, 정반대 의미.
✕진행률 바 상시 애니메이션항상 움직이면 아무것도 강조되지 않는다. 진행 피드백은 세션 완료 시 1회, 저장고 순차 점등으로 몰아준다.
✕감축 모드 = 애니메이션 전부 제거그러면 “거꾸로 매달림”이 사라져 정보까지 사라진다. 채택안: 전환만 없애고 최종 포즈는 유지한다. 감축 모드에서도 Dee는 뒤집혀 있다.
✕리그 · 랭킹 · 연속 기록 압박자기 코드를 교재로 쓰는 앱에 비교 대상은 없다. 연속 기록은 숫자로만 조용히 표시하고, 끊겨도 아무 연출을 하지 않는다.
