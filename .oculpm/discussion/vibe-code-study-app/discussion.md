## 문제 정의

AI가 대신 짜준 코드(바이브 코딩)로 앱은 만들어졌지만, 만든 사람이 그 코드를 이해하지 못한다. 이 격차를 메우는 학습 프로그램을 만들려고 한다.

표면적 요구는 "내 코드를 공부한다"지만, 실제 통증은 셋으로 갈린다 — **(a) 못 읽음**(구조·흐름 파악 불가, 디버깅 불가), **(b) 못 씀**(읽으면 이해되는데 백지에서 재현 불가), **(c) 판단 못 함**(AI의 기술 선택이 옳은지 평가 불가). 사용자는 셋 다 해당하며, 추가로 **프로그래밍 문법 자체를 모르는 상태**다.

핵심 설계 난제는 "코드를 설명해주는 도구"를 만들면 실패한다는 점이다. 그건 이미 Claude Code에게 물어보면 된다. 별도 도구를 만들 가치는 **설명**이 아니라 **강제된 능동 출력**에 있다. 읽기는 인식(recognition)이지 지식이 아니며, (b)와 (c)는 읽어서 낫지 않는다.

결정해야 할 것: 학습 메커니즘의 구성, MVP 범위, 실행·배포 형태, 에디터, LLM 의존도, 제품 톤.

## 후보 해결 방안

채택 여부(정본은 「결론」): **A 채택**(T0+T1+T2, T3 유보) · **B Tauri 채택** · **C 채택**(LLM 부가) · **D D-2 채택** · **E 채택** · **F 폐기**(시각 컨셉; 가독성 엔지니어링만 이식) · **G 채택**(최종 시각 방향).

### 방안 A — 학습 트랙 구성 {#opt-tracks}

**상태: 채택** — MVP = T0+T1+T2, T3 는 인터페이스 자리만(결론 §2).

같은 코드 한 조각에서 4개 층이 뽑힌다. 사용자 레벨에 따라 어느 층을 낼지 고른다.

| 트랙 | 대상 | 채점 방식 | 실행 필요 |
|---|---|---|---|
| T0 문법 | 문법을 모르는 초보 | 객관식·지목·빈칸 | ❌ |
| T1 클론 코딩 | 초·중급 | 원본과 diff 비교 | ❌ |
| T2 구조 | 중급 | 커밋 정답지·그래프 계산 | ❌ |
| T3 심화 | 중상급 | 테스트 실행(버그 수리·재구현) | ⭕ |

- 장점: T0~T2가 모두 실행 없이 채점되므로 **전 언어 지원이 실제로 가능**하다. T3만 언어별 테스트 러너 어댑터를 요구한다.
- 단점: T3(자료구조·심화)를 미루면 상급 학습자에게는 당장 값이 없다.
- 비용: T0+T1 < T2 < T3 순으로 급증. T2 추가 시 작업량 약 2배.

### 방안 B — 실행·배포 형태 {#opt-shell}

**상태: Tauri 데스크톱 채택** — VS Code 포크 기각, Monaco 는 분리 배포본 사용(결론 §5).

| 형태 | 에디터 품질 | 비용 | 유지보수 | tree-sitter |
|---|---|---|---|---|
| 로컬 웹앱(Next.js) | Monaco 가능 | 낮음 | 없음 | WASM |
| **Tauri 데스크톱 앱** | Monaco 가능 | 중간 | 없음 | **네이티브(Rust)** |
| VS Code 확장 | 100% 진짜 | 중간 | 없음 | WASM |
| VS Code 포크 | 100% + 주변부 | 매우 높음 | 영구 리베이스 | 네이티브 |

- VS Code 포크 검토 결과: 로컬 클론은 v1.137.0 / 커밋 164,424개 / 1.7GB / `src` 아래 TS 8,905개 파일. 미빌드 상태이며 Node 요구 버전(24.18.0)과 설치 버전(26.7.0)이 불일치.
- 결정적 사실: **VS Code의 에디터는 이미 `monaco-editor`로 분리 배포된다.** "VS Code 에디터"라는 요구는 포크 없이 충족된다. 포크가 추가로 주는 것은 에디터가 아니라 파일 탐색기·터미널·확장 호스트 등 주변부다.
- Tauri의 결정적 이점: 이 앱의 제1 의존성인 **tree-sitter가 Rust 본진**이다. 언어 추가가 크레이트 한 줄이고, `git2`·`rusqlite`도 네이티브. WASM 판은 언어당 `.wasm` 로드가 필요하고 대형 리포에서 느리다.

### 방안 C — LLM 의존도 {#opt-llm}

**상태: 채택** — LLM 은 사다리 4단만, 빈자리는 YAML 문법 사전(결론 §5).

오픈소스 배포 시 "시작하려면 API 키를 넣으세요"는 최대 채택 장벽이다. 트랙별로 따지면 MVP의 거의 전부가 LLM 없이 성립한다.

- LLM 불필요: T0 문법 요소 추출·지목형·빈칸형, T1 전체, T2 책임 배치·영향 반경·의존성 방향.
- LLM 선택: T0 의미형, T1 "왜" 설명 채점(채점 없이 기록만 해도 성립), 심화 설명 4단.
- LLM을 뺀 자리는 **언어별 문법 사전(YAML)** 이 채운다. 기여 표면이 코드가 아니라 데이터가 되어, 언어 커버리지를 커뮤니티가 늘릴 수 있다.

### 방안 D — 제품 톤 {#opt-tone}

**상태: D-2 채택** — 코딩계의 듀오링고, 단 하트·리그·스트릭 해금은 버림(결론 §3).

- **D-1 조용한 작업실**: 따뜻한 중성 회색 + 단일 앰버 액센트, 게임화 최소. 매일 써도 안 지치지만 **얌전하고 고리타분**하다.
- **D-2 코딩계의 듀오링고**: 경로(path) 중심, 촉각적 피드백, 캐릭터·유머, 채도 높은 팔레트.
- 듀오링고의 실패 모드를 반드시 차단해야 한다 — 1000일 연속인데 회화를 못 하는 문제. 특히 **하트/목숨 시스템은 이 앱의 핵심을 죽인다**: 틀리는 것이 벌이 되면 사용자가 "모르겠어요"를 누르지 않고 아는 척하고 넘어간다.

### 방안 E — 해당 언어가 처음인 사용자 커버 {#opt-newcomer}

**상태: 채택** — E-1~E-5 전부(결론 §4). 산출 알고리즘은 `docs/03` §3.6·`docs/02` §6.

T0의 「모르겠어요 → 선행 개념으로 내려가기」는 **선행 사슬이 사용자가 아는 층에 닿는다**고 가정한다. 그 언어가 처음이면 사슬이 끝없이 내려가 **사다리가 바닥을 뚫는다.** 상황은 셋으로 갈리며 처방이 다르다 — ①이 언어가 처음·프로그래밍은 해봄(가장 흔함) ②프로그래밍 자체가 처음 ③다른 언어를 잘 앎.

핵심 오해를 먼저 제거해야 한다: **내 코드에 기초 개념이 없는 게 아니라 묻혀 있다.** 리포 어딘가에 `const MAX = 10` 같은 단순한 줄이 반드시 있다. 문제는 부재가 아니라 가장 단순한 사용처를 먼저 보여주지 않는 것이다. 따라서 해법은 합성이 아니라 **순위 매기기**다.

- **E-1 최소 미지 개념 우선 (핵심)** — 개념마다 내 코드의 각 사용처에 *아직 모르는 개념 개수*를 매기고 가장 낮은 것을 첫 노출로 쓴다. `const [c, setC] = useState(0)`은 미지 4개(구조 분해·배열·훅·제네릭 추론)라 부적격, `const MAX = 10`은 1개라 적격. 숙련도가 오르면 미지 수가 줄어 같은 개념의 더 복잡한 사용처가 나중에 열리므로 **난이도 곡선이 파생된다.** 「내 코드가 교재」 정체성이 유지된다.
- **E-2 경로를 위상 정렬로** — 유닛(기능) 순서는 학습 순서와 무관하다. 개념 그래프의 선행 관계로 정렬하면 뿌리(변수·함수·조건)부터 시작한다. 언어가 처음일 때만 **「0장 — 이 언어의 바닥」** 프롤로그를 앞에 붙인다.
- **E-3 개념 전이** — 개념에 *보편 / 언어고유* 표시를 단다. 보편 개념을 이미 익혔으면 표기 차이만 가르친다("반복문은 이미 아시네요. 파이썬은 `for x in xs`, TS는 `for (const x of xs)` — 개념은 같고 표기만 다릅니다"). 개념 단위 숙련도 스키마라 추가 구조가 거의 필요 없다.
- **E-4 합성 예제는 진짜 바닥에만** — 내 코드에 정말 없는 개념(문법 구멍 지도가 식별)에만. **반드시 "곧 네 코드 어디에서 이걸 보게 된다"를 함께 예고**할 것 — 없으면 앱이 일반 튜토리얼로 변질된다.
- **E-5 별도 배치고사를 만들지 않는다** — 초보는 자기 레벨을 못 고르고 시험은 최악의 첫인상이다. 첫 세션에서 미지 개념이 가장 적은 카드부터 던지고 정답률·「모르겠어요」로 바닥을 추정한다.

- 한계: **프로그래밍이 완전히 처음인 사용자**는 커버 대상이 아니다. 「변수」라는 개념 자체가 없으면 바닥 아래에 또 바닥이 있고 이 앱의 재료(내 리포)로는 만들 수 없다. 앱이 그렇다고 **말하고** 외부 입문 자료를 권해야 한다 — 억지로 커버하는 척하면 둘 다 못 한다.

### 방안 F — 「도감(Field Guide)」 컨셉 {#opt-fieldguide}

**상태: 폐기(시각 컨셉)** — 사용자 반려. 아래 「측정 가능한 가독성 규칙」 중 본문 엔지니어링(행 길이·13px·행간·keep-all·7:1·조사)만 방안 G 로 이식했고, 「색은 의미에만」「정적 장식 0」「활자 대비 2배」「구문 강조 제거」는 철회(결론 §6).

C 「목차」 목업 검토 후 **가독성 부족** 피드백이 나왔다. 진단: 네 방향 모두 *코드* 가독성은 조건으로 걸고 실측까지 했으나 **본문(한국어 설명) 가독성은 아무도 챙기지 않았다.** 사용자는 문법을 모르는 초보라 읽어야 할 문장이 많은데(개념 설명·오답 진단·4단 사다리 해설), 그 문장이 원색 블록과 초대형 활자 사이에 끼어 있었다. C의 무기였던 "11px과 160px이 같은 줄에 선다"는 **3초 훑어보는 잡지 표지의 문법**인데, 이 앱은 **매일 25분 읽는 물건**이다 — 매체를 잘못 골랐다.

**해결: 책 은유를 유지하되 「표지」를 빼고 「본문 조판」을 남긴다.** 나아가 마스코트가 박새이므로 **조류 도감**으로 특정한다. 도감은 어두운 숲에서 3초 안에 종을 판별해야 하는 물건이라 **가독성에 극단적으로 최적화된 형식**이다 — 큰 그림, 짧은 문장, 2단 조판으로 강제된 짧은 행 길이, 색은 판별 표시에만, 한 페이지 한 종. **컨셉을 지키면 가독성이 구조적으로 따라온다.**

매핑: 카드=도감 한 페이지 · **지시선(leader line)으로 판별 포인트를 짚는 것 = T0 지목형 문제** · **미기록 종 = 문법 구멍** · 관찰 기록 = 숙련도 · 다시 보러 가기 = 간격 반복 · **「놓쳤어요」 = 「모르겠어요」**(탐조에서 새를 놓치는 건 일상이라 부끄러움이 은유 차원에서 제거된다) · 도감의 차례 = 학습 경로(C의 목차 은유 계승) · **Dee = 길잡이**(박새가 실제로 혼합 무리를 이끄는 습성).

「미기록 종」이 C의 「정오표」보다 우월하다 — 정오표는 *내 잘못 목록*이지만 미기록 종은 *앞으로 만날 것 목록*이고, 탐조인에게 가장 강력한 동기다.

**기쁨과의 긴장은 실재하지 않는다.** 듀오링고 화면도 사실 조용하다 — 여백이 크고 요소가 적으며, 기쁨은 정지 화면이 아니라 **순간**(전환·피드백·보상)에서 온다. 원칙: **정지 상태는 조용하게, 기쁨은 움직임에.** 최대 보상 모먼트는 탐조의 **lifer**(처음 보는 종을 기록하는 순간)에 대응시킨다.

**측정 가능한 가독성 규칙** (「가독성 좋게」는 지시가 아니라 소원이므로 수치로 고정):

| 항목 | 규칙 |
|---|---|
| **본문 행 길이** | 한글 **35~45자** (`max-width` 필수) — 종전 설계에 전무했던 최대 결함 |
| 본문 크기 | 16px 이상 · UI 라벨 최소 13px (11px 금지) |
| 본문 행간 | 1.7 이상 |
| 한글 줄바꿈 | `word-break: keep-all` 전역 (어절 단위) |
| 코드 | 16px / 행간 1.85 / 줄번호 |
| 대비 | **7:1 (AAA) 목표** — 4.5:1은 최소 기준이지 좋은 기준이 아님 |
| 다크 배경 | 순흑 금지, 따뜻한 근접흑 (할레이션 방지) |
| 색 | **의미에만** — 트랙·정답/오답·미기록 종. 장식 색 0 |
| 동시 정보 | 한 화면에 **한 가지 일** |
| 장식 | 상호작용 요소에만(버튼 두께). **정적 장식 0** |

### 방안 G — 「잉크」(리소그래프) + 박새 {#opt-ink}

**상태: 채택 (사용자 결정)** — 방향 4안 중 B 「잉크」를 사용자가 원했고, 최종 시각 방향으로 확정(결론 §6·§7). 기준 시안은 `design/legacy/dir-b-riso.html`, 완성 화면은 `design/ink-home.html`·`design/ink-session.html`.

- 은유: 경로 홈 = 인쇄 대지(스티커 시트) · 숙련도 = 잉크 겹(배울수록 새가 선명해진다) · 세션 = 교정쇄 · 정답/오답 = 정합/어긋남 · 모르겠어요 = 다시 찍기.
- 장점: 리소는 잉크를 겹쳐 찍고 박새는 명확한 색면의 새라 매체와 소재가 원래 궁합 · 마스코트가 곧 진행 표시 · 「다시 찍기」와 「거꾸로 매달리기」가 부끄러움을 은유 차원에서 제거 · 로고(사용자 제공 SVG)를 그대로 판 변수로 켜서 마스코트와 하나가 됨.

## 결론

2026-09-02 기준, **지금 유효한 결정만** 적는다. 이전 결론(「목차」 → 「도감」 시각 컨셉)은 사용자 반려로 폐기됐고 로그에만 남아 있다.

### 1. 제품 정체성

- **이름 Chickadee(박새) · 마스코트 Dee.** 바이브 코딩으로 앱은 만들었지만 자기 코드를 이해하지 못하는 사람을 위한 학습 프로그램. **남의 예제가 아니라 내가 만든 코드가 교재**이고, 리포마다 학습 지도가 달라진다.
- 가치는 설명이 아니라 **강제된 능동 출력**이다. 설명은 이미 Claude Code 가 한다. 읽기는 인식이지 지식이 아니다.
- 통증 3종을 다 겨냥한다 — (a) 못 읽음 (b) 못 씀 (c) 판단 못 함 — 그리고 문법 자체를 모르는 상태까지. **프로그래밍이 완전히 처음인 사용자는 대상이 아니며 앱이 그 사실을 정직하게 말한다.**

### 2. 학습 트랙과 코어 루프

| 트랙 | 문제 | 채점 | 상태 |
|---|---|---|---|
| **T0 문법** | 의미형 · 빈칸형 · 지목형 (내 코드 한 줄 + 앞뒤 맥락) | 객관식·지목 — 실행 없음 | MVP |
| **T1 클론 코딩** | 3단계 페이딩(보고 치기 → 뼈대만 → 백지) | 원본과 줄 단위 동등 판정 — 실행 없음 | MVP |
| **T2 구조** | 책임 배치 · 영향 반경 · 흐름 추적 · 의존성 방향 | 실제 커밋 정답지 · import 그래프 — 실행 없음 | MVP |
| T3 심화 | 버그 수리 · 재구현 | 테스트 실행 | **유보** (스키마 자리만) |

T0~T2 가 실행 없이 채점되므로 **전 언어 지원이 실제로 가능**하다. 한 유닛(내 리포의 기능 하나) 안에서 T0·T1·T2 가 병렬로 붙는 것은 구조적 사실이고, 경로가 이를 표현한다.

**코어 루프**: 내 리포의 커밋 diff → tree-sitter 파싱 → 개념 카드 생성 → 하루 세션(오늘의 인쇄, 기본 15분 · 10~25분 범위, 새 판 하루 2장, 하루 경계 04:00) → 개념 단위 숙련도 누적(파일이 아니라 **개념** 단위 — 리포가 바뀌어도 자산이 남고 덱 폭발을 막는다) → FSRS 간격으로 다시 노출 → 경로 해금은 **숙련도로만**.

**숙련도 = 잉크 겹 0~4.** 0 미인쇄 · 1 애벌 · 2 먹판 · 3 +청판 · 4 +진홍판(완성). 겹은 맞힌 횟수가 아니라 **시간을 두고 다시 맞힌 횟수**로 쌓인다. 명문화: 하루 최대 +1 · 다시 찍기 정답은 잃은 겹의 **회복만** · 「모르겠어요」의 −1 은 같은 날 다시 찍기로 회복만 · T1 은 3단계(백지) 통과에서만 4겹 · T2 진급 85 / 재도전 65. 다음 인쇄 간격 라벨(오늘 안에 · 내일 · 3일 · 9일 · 3주)은 FSRS 가 계산한 값의 근사 표기다.

### 3. UX 불변 규칙 (모든 화면에 적용)

1. **「모르겠어요」= 다시 찍기.** 벌이 아니라 공정. 하트·목숨 금지. 맞혔을 때도 노출. 누르면 한 겹 내려가고 인쇄가 오늘로 당겨지는 것을 **이득으로 표시**. 4단 사다리 — ① 사전 3층 ② **아래층 진단 → 선행 판으로 점프, 마치면 자동 복귀, 돌아오면 「방금 배운 것과 이어보기」 문단이 새로 열림** ③ 내 리포의 같은 문법 다른 자리 ④ 자유 질문(LLM, 키 없으면 프롬프트 생성 — 담는 것은 이 줄과 앞뒤 4줄뿐, 디렉터리 경로·리포명·커밋 메시지·작성자는 제외하고 파일 이름만 허용). 1~3단은 LLM 불필요. 트랙별 대응: T0 사다리 · T1 원본 잠깐 보기(횟수만 기록) · T2 힌트 3단 — 셋 다 감점 없음.
2. **오답 진단은 「틀렸다」가 아니라 「당신이 고른 그것이 참이 되는 조건」** + 실제로 터지는 최소 코드(가장 날카로운 자리). 한 번 어긋났다고 겹이 바닥까지 떨어지지 않는다 — 대신 다시 찍기 판이 오늘 큐에 들어간다.
3. **피드백 슬롯은 미리 비워 둔다** — 답해도 위 글이 0px 도 밀리지 않는다.
4. **세션은 전체화면 오버레이.** 이탈 경로는 Esc 하나, 확인 모달 없음, 진행은 저장되어 이어 찍는다. 입력 중이면 Esc 는 먼저 입력을 빠져나간다.
5. **진행바는 시간 비례.** T0 30초 칸과 T1 9분 칸이 같은 크기면 남은 양이 거짓말이 된다. 다시 찍기·아래층 판이 생기면 칸이 늘어난다.
6. **LIFER** — 새 개념을 처음 기록하는 순간의 최대 보상. 컨페티가 아니라 **영구 기록**(도장 + 일련번호 + 채집지). 배경은 흐려지되 지워지지 않고, 아무 키나 누르면 닫히며, 세션당 3회 상한.
7. **버릴 것** — 하트/목숨 · 리그/랭킹 · 스트릭이 진도를 여는 것(스트릭은 숫자로만, 끊겨도 연출 없음) · 결제 유도 · 상시 애니메이션 · 화면 흔들기/빨간 플래시 · 슬픈 마스코트. 목업의 상시 애니메이션 3건(오늘 스탬프 blink · 현재 노드 spin · Dee peek)은 유한화하고 잠긴 노드 흔들기도 뺀다.
8. **키보드 완결** — 카드 한 장은 고르기 → Enter → Space 세 번. `1~4` 고르기(사다리가 열려 있고 포커스가 사다리 안이면 단 선택) · `← →` 짚기 · `?` 다시 찍기 · `B` 위로 · `H` 힌트 · `` ` `` 홀드 원본 · `⌘↵` 채점 · `Esc` 나가기.
9. **한 화면에 한 가지 일.** 정지 상태는 조용하게, 기쁨은 움직임에(최대 720ms, LIFER 1.36s 예외; 타이핑·읽기 중 모션 0; 감축 모드는 전환만 없애고 최종 포즈는 유지).

### 4. 언어가 처음인 사용자

별도 입문 과정·배치고사를 만들지 않는다. **최소 미지 개념 우선**(각 사용처의 「아직 모르는 개념 개수」가 가장 낮은 줄을 첫 노출로 — `const MAX = 10` 은 적격, `const [c, setC] = useState(0)` 은 부적격) → 난이도 곡선이 파생된다. 개념 그래프 **위상 정렬**로 뿌리부터, **개념 전이**(보편/언어고유 표시)로 아는 것은 표기 차이만. 합성 예제는 문법 구멍이 식별한 진짜 바닥에만 쓰고 반드시 「곧 네 코드 어디에서 본다」를 예고한다.

### 5. 스택 · 배포

- **Tauri 데스크톱.** 얇은 Rust(tree-sitter 파싱 / git2 diff·커밋 / rusqlite, 500~1500줄 크레이트 호출 껍데기) + 두꺼운 TypeScript(카드 생성 · FSRS · 개념 그래프 · 전 UI). 에디터는 **Monaco**. VS Code 포크는 하지 않는다.
- **LLM 은 부가 기능이지 의존성이 아니다.** 모든 핵심 루프가 API 키 없이 동작. 빈자리는 **언어별 문법 사전(YAML)** — 기여 표면이 데이터라 커뮤니티가 언어를 늘린다.
- T1 채점: 문법 있는 언어는 **tree-sitter AST 비교**, 없으면 정규식 정규화 폴백(공백·따옴표·세미콜론·주석·변수명 1:1 일관 치환, 바꾼 이름이 원본에 있으면 「이름 맞바꿈」으로 불인정). 점수 분모는 비공백 줄, 진급 85(20줄 미만 소블록은 `min(85, 100−200/total)`).
- 오픈소스 **MIT**, GitHub Actions + `tauri-action` 3-OS 빌드. 서명·공증은 뒤로. 데이터는 로컬 sqlite 에만, 코드는 전송하지 않는다.
- 「선택의 왜」(왜 AI 가 하필 이걸 썼나)는 생성 시점 기록만이 답한다 → ocul-pm 일지·세션 로그 연동을 MVP 로.

### 6. 시각 디자인 시스템 — 「잉크」(리소그래프) + 박새 (사용자 결정)

- **은유**: 경로 홈 = 인쇄 대지(스티커 시트) · 유닛 = 내 리포의 기능 = 시트 한 장 · 노드 = 스티커 · 숙련도 = 잉크 겹 = **새가 선명해진다** · 오늘의 인쇄 = 오늘 할 카드 · 세션 = 교정쇄 · 정답 = 정합(in register) · 오답 = 어긋남(off register) · 모르겠어요 = 다시 찍기 · 판이 없는 문법 = 내 코드엔 있는데 아직 안 찍은 문법. **모든 은유 옆에 평문을 병기한다.**
- **원칙 한 줄: 본문은 조용하게, 나머지는 잉크답게.** ① 읽어야 하는 텍스트 위에는 잉크를 얹지 않는다 ② 장식은 본문 단 밖에만 ③ 활자 대비 제한은 본문 스케일에만 ④ 13px 미만 활자 토큰은 아예 정의하지 않는다 ⑤ 코드 구문 강조는 지우지 않는다(판독 보조).
- **측정 규칙**: 본문 행 길이 한글 35~45자(`--measure:36em`, 선택자로 강제) · 본문 16px 이상 · 행간 1.7(코드 1.85, 줄번호) · `keep-all` + `line-break:strict` · 대비 7:1(잉크 배지 위 글자는 AA 허용) · 조사 헬퍼(`josa`) · 순흑 금지.
- **토큰**: 종이 `--paper/--paper-2/--paper-3/--stock` · 먹 `--ink/--ink-soft`(텍스트는 이 둘만) · 잉크 면 `--blue #1250C8 · --pink #FF2E7E · --yellow #FFC400` + 글자용 7:1 변형(황 글자는 주간 `#664300`, 야간 `#FFD866`) · 판정 색 별칭 `--verdict-exact/-equiv/-differ`(진홍/청/황-deep) · 트랙 별칭 **T0 청 · T1 진홍 · T2 황**(컴포넌트는 별칭만 쓴다). 야간반은 반전이 아니라 다른 공정(어두운 판지 `#1F1915` + 더 뜨거운 형광, `screen` 블렌드, 글로우). 「부속 숨김」 스위치(등록표시·기울기·질감 끄기, 기본 보임 — Linux WebKitGTK 만 기본 숨김). 최소 창 1000×680.
- **성능**: `filter:drop-shadow` 금지 → `box-shadow`, 블렌드는 워드마크·도장에만. Chromium 49노드 p95 8.5ms 확인, WebKit 미측정.

### 7. 로고 · 마스코트 (확정)

- **로고 = `design/logo/chickadee-logo.svg`, 사용자 확정, 변경 금지.** 검은 링 + 진홍·머스터드 어긋난 링, 가지 위 박새, 진홍 바닥. 파생만 허용: 배지(링 밖 투명) · 정사각 · 머리 크롭 파비콘(16px 3단 통과) · PNG · ico (`design/logo/README.md`).
