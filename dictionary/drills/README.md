# 작은 문제 층 (D186 ⑧ · D187 ①)

0부(값과 식)를 **값 적기**로 배운 사람이, 그 값이 필요한 **다섯 줄짜리 프로그램**을 실제로
써서 돌리는 층이다. 표준 입력으로 글을 받고 표준 출력으로 답을 내며, 판정은
`packages/grading/src/stdin-runner.ts` 가 케이스마다 나온 글을 견주어 한다.

## 저작권 — 문제는 우리가 쓴다

대회 사이트(백준 · LeetCode · Codeforces)의 **지문도 케이스도 복제하지 않는다.**
가져온 것은 「첫 단계가 입출력 → 사칙연산 → 조건 → 반복 → 배열 → 문자열이다」라는
**주제 순서** 하나뿐이고, 그 순서는 저작물이 아니다. 이 저장소는 MIT 로 나간다.

## 한 문제의 모양

```
drills/<id>/
  drill.yaml      문제
  reference.py    참조 풀이 — 케이스의 답을 내는 것
```

`drill.yaml` 의 열은 이렇다.

| 열 | 뜻 |
|---|---|
| `id` | 디렉터리 이름과 같아야 한다 |
| `topic` | `io` · `arithmetic` · `branch` · `loop` · `list` · `text` — **이 순서가 곧 배치 순서다** |
| `statement.ko` / `.en` | 세 문장 이내. **한국어가 정본**이고 영어를 병기한다 (D117·D118) |
| `needs` | 0부 개념 id 들. 이 문제가 나오려면 먼저 서야 하는 것 (`common/`·`cs/`) |
| `langs` | 이 문제를 낼 수 있는 언어 — `py` · `ts` · `java` |
| `cases[]` | `stdin` 과 `stdout` 셋에서 다섯 |

## 답을 사람이 안 적는다

`cases[].stdout` 은 **`reference.py` 를 돌려서 얻은 것**이다.
`packages/cards/src/drill.test.ts` 가 케이스마다 같은 참조 풀이를 다시 돌려 기록된 값과
대조하므로, 답이 어긋나면 CI 가 빨개진다 — 사람이 손으로 적은 기댓값은 한 칸도 없다.

## 나온 글은 언어에 안 매인다

케이스의 출력은 **정수와 글자만** 쓴다. 실수를 찍으면 언어마다 표기가 갈리기 때문이다 —
같은 `3.0` 을 파이썬은 `3.0` 으로, 자바스크립트는 `3` 으로 찍는다. 실수는 **입력과 판단**에만
쓰고(`float-not-exact` 가 `yes`/`no` 를 내는 것이 그 예다), 출력에는 안 싣는다.

## 0부의 함정을 밟는다

문제마다 케이스 하나 이상이 0부에서 틀리기 쉬운 값을 정확히 밟는다.

| 문제 | 밟는 것 |
|---|---|
| `floor-divide` | `-7 / 2` 의 방향 — 내림인가 0 쪽인가 |
| `big-product` | `2147483647 × 2` 가 32비트에 안 들어간다 |
| `float-not-exact` | `0.1 + 0.2 ≠ 0.3` |
| `sum-to-n` | `n = 100000` 의 합이 32비트를 넘는다 |
| `median-of-odd` | 가운데 자리 `n / 2` 가 정수여야 한다 |
| `reverse-text` | 한글 한 자는 바이트 하나가 아니다 |
| `sign-of` | `-2147483648` 의 부호 |
| `count-down` | `n = 0` 이면 아무것도 안 찍는다 |
