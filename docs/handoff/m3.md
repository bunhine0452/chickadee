### 밟으면 터지는 자리
- **`store_batch` 는 op 를 미리 만들어 보낸다.** batch 중간에 생긴 id 를 TS 가 알 방법이 없다 —
  잇는 UPDATE 는 SQL 안에서 `last_insert_rowid()` 를 써야 하고, **그러면 순서가 계약이 된다**
  (D77). `appeal`·`why_answer` 도 `review_log.id` 를 참조하므로 같은 함정을 그대로 만난다.
  `buildPlateDoneTx` 에 붙일 때 **INSERT 를 그 앞에 끼우지 마라**.
- **`UPDATE … pos = pos + 1` 한 문장으로는 큐를 못 민다.** SQLite 는 행마다 UNIQUE 를 검사해
  `p → p+1` 이 아직 살아 있는 `p+1` 과 부딪힌다. `session.shift_park`/`shift_unpark` 가
  음수로 옮겼다 되돌린다.
- **판을 걸면 포커스가 `article.ps` 에 있다.** 이벤트는 위로만 버블하므로 자식 컴포넌트의
  `onKeyDown` 까지 **안 내려간다**. `1~4` 를 `T0Plate` 가 document 에서 받는 이유이고,
  T1 의 `⌘↵`·`` ` `` 홀드도 같은 자리에서 받아야 한다.
- **채점하면 고른 요소가 `disabled` 가 되고 그 위의 포커스는 죽는다.** 06 §2 의 「매 단계
  `activeElement !== body`」가 깨진다 — 채점 뒤 포커스를 다음 동작으로 옮겨라.
- **`user.keyboard` 는 `disabled` 요소에 이벤트를 안 보낸다.** 테스트에서만 키가 죽는 것처럼
  보인다(브라우저는 포커스를 옮겨 준다).
- **RTL 자동 정리가 안 걸린다.** 루트 `vitest.config.ts` 가 `globals: false` 라 `cleanup()` 을
  손으로 불러야 하고, 안 부르면 「같은 이름 요소가 둘」로 깨진다.
- **첫 정답이면 LIFER 베일이 뜨고 그 뒤 모든 키를 먹는다.** Space·Esc 가 안 먹는 것처럼
  보이는데 베일이 먼저 닫히는 것이다(05 §2.3). 테스트에서 먼저 치워야 한다.
- **`packages/ui` 의 `Track` 은 `t0|t1|t2` 이고 `store-sql` 의 `Track` 은 `t3` 를 포함한다.**
  화면에 넘길 때 한 번 좁혀야 한다(`SessionScreen.asViewTrack`).
- **`exactOptionalPropertyTypes`** 때문에 zod 출력(`{x?: T | undefined}`)을 02 §8.2 타입
  (`{x?: T}`)에 넣으려면 경계에서 좁히는 캐스트가 필요하다. `rows.ts` 가 그 관용구를 쓴다.
- **실제 앱을 띄우면 테스트가 못 보는 것이 나온다.** M2 끝에 처음 띄웠더니 세 개가 한꺼번에
  터졌다 — `ingest_start` 인자 모양(구조체 하나를 펼쳐 보냄), `facts.run_finish` 인자 9개 누락
  (`drop()` 이 오류를 삼킴), blame 의 200 op 미분할(`BAD_INPUT` 이 배경 `catch` 에 먹힘).
  전부 M1 코드였고 전부 초록이었다. **TS 테스트는 `ipc` 를 모의하고 Rust `pipeline.rs` 는 잡
  러너를 직접 부른다** — 어느 쪽도 Tauri 의 명령 디스패치를 지나지 않는다. 새 명령을 붙이면
  한 번은 진짜로 띄워 봐라.
- **`derive.ts` 의 `siteKey` 에는 진짜 제어 문자(NUL·SOH)가 아니라 이스케이프가 들어 있다.**
  M2 에서 하위 세션이 이것을 「32비트 해시 버그」로 오독했다 — 바이트는 그대로고 표기만
  읽을 수 있게 고쳤다. 비슷한 자리를 보면 `od -c` 로 먼저 확인해라.
- **`packages/ui` 의 테스트는 `// @vitest-environment jsdom` 주석이 필요하다.** 루트 설정이
  `node` 라서 없으면 DOMPurify 가 죽는다.
- **`cargo fmt --all --check` 를 커밋 전에 돌려라.** M3 는 `parse_snippet` 으로 Rust 를
  건드린다 — CI 의 `lint-type-unit` 은 워크스페이스 전체를 본다.
- **cargo #6313** — 루트의 `[profile.release] panic = "abort"` 때문에 벤치가 간헐적으로
  E0308 로 죽는다. `scripts/bench.sh` 가 그 안에서만 우회한다.

## 규칙
- 정본 > 설계 문서 > 내 판단. 문서와 어긋나는 것을 발견하면 코드를 문서에 맞추고, 문서를
  바꿔야 하면 `docs/00-overview.md` §4.2.1 에 **D83…** 행을 먼저 추가한 뒤 해당 문서를 고친다.
  체크리스트 항목 제목은 바꾸지 않는다(플랜이 제목으로 참조).
- 얇은 Rust: 상한 **2,300**(D68). 지금 2,050 이고 **M3 가 쓸 수 있는 것은 `parse_snippet`
  약 25줄**이다(D67). 도메인 어휘 금지·SQL 리터럴 금지·`println!` 금지.
  `bash scripts/check-rust-budget.sh` 를 자주 돌린다.
- 게이트 스크립트: `pnpm check:rust` · `pnpm check:contrast` · `pnpm check:motion` ·
  `pnpm design:check` · `pnpm catalog:build`(statement 를 고치면 **반드시**).
- **리포에 절대 쓰지 않는다.** 인제스트 전후 트리 해시가 같은지 테스트가 고정하고 있다.
- 로그 금지 필드(01 §6): 파일 내용·코드 조각·캡처 excerpt·**사용자 답안**·절대 경로.
  T1 은 필사 초안을 다루므로 이 규칙이 M2 보다 위험하다 — `@chickadee/ipc-client` 의 `log`
  를 써라(이름으로 거른다). `console` 은 그 파일 밖에서 금지다.
- 디자인 결정은 사용자 것이다. 로고와 목업 시각은 바꾸지 않는다. T1 화면은
  `design/ink-session.html` 과 `design/src/ink/t1.js` 가 정본이다.
- 병렬 하위 세션이 필요하면 `model: "opus"` 로 띄우고 각자 필요한 절만 읽게 한다. **M2 에서
  효과가 있었던 분배**: 기계적인 작업(컴포넌트·생성기·골든)은 하위 세션, 경계 판단
  (스키마·트랜잭션 순서·의존 방향)은 직접. 하위 세션에는 **담당 파일 집합을 못박고 검증
  명령의 실제 출력을 보고하게** 하라. M2 에서 세 세션이 서로 다른 디렉터리만 만져 충돌이
  0이었다 — 같은 `package.json`·`vitest.config.ts` 를 두 세션이 고치면 워크스페이스가 깨진다.
- 작업 단위마다 `journal_write` + `plan_update`(AGENTS.md).
- 검증 없이 완료라고 말하지 않는다. 실패한 테스트·미측정 항목은 그대로 보고한다.
- **표면 언어(D61).** 커밋 메시지·PR·`.github/**`·`README` 류·**코드 주석·식별자는 영어**가
  아니라 — 주석은 **한국어**, 식별자·클래스명은 영어다(기존 파일의 관용구를 따라라).
  앱 UI 문구·오류 문구·사전 YAML 은 한국어. `docs/**`·`.oculpm/**` 도 한국어.
- 커밋은 `<type>: <description>` 형식(영어). **AI 말투 금지(D62)** — 목록은 루트 `CLAUDE.md`.
- **CI 를 빨간 채로 두지 않는다.** `lint-type-unit`·`audit`·`integration`·`build-3os` 4잡.
  `gh run watch <id>` 로 끝까지 보고 간다.

## M2 가 다 못 한 것 (M3 가 물려받는다)
- **WKWebView 실측은 끝났고 프레임만 예산을 넘는다 (D80).** `frame_p95` **18 ms**(예산 12,
  노드 384개) · `home:paint` 106 ms(400) · `session:mount` 4 ms(50) · `t0:grade` < 1 ms(30) ·
  `theme:switch` 48 ms(100) · `lifer:open` 13 ms(50). 05 §10 의 강등 사다리(윈도잉 →
  판번호 어긋남 끄기 → 결 op 0)를
  **밟을 단은 윈도잉 하나로 정해졌다(D81)** — 아래 두 단은 재 봤더니 3 ms 밖에 못 줄인다.
  자리는 M4 `m4-05-dependency-map` 앞이고 **M3 은 홈을 건드리지 않는다**.
  정본 §6 은 **사용자 승인으로 실측 문구가 됐다**(2026-09-03) — 「Chromium 49노드 p95 8.5ms ·
  WebKit(WKWebView) 384노드 p95 18ms 확인 — 예산 12ms 초과, 윈도잉으로 내린다」.
  **M2 가 남긴 열린 질문은 이제 없다.**
  다시 재는 법은 `devtools/audit.ts` 의 `HOW` 에 있다 — `VITE_PERF=1` 로 빌드해 격리된
  `HOME` 으로 띄우면 하네스가 혼자 돌고 `perf_sample` 에 남는다. 두 가지를 조심해라:
  ① **창을 앞에 세워 둬야 한다** — 가려진 WKWebView 는 `requestAnimationFrame` 을 멈춰
  프레임이 0개로 나오고, 그것이 「빠르다」로 보인다. ② **하네스는 화면을 클릭해서 답한다** —
  `answerPlate` 를 직접 부르면 LIFER 의식이 사는 자리를 건너뛰어 `lifer:open` 이 안 재진다.
- **`m2-06-q5-audit-port` 는 `in_progress` 이고 M5 에 둔다 (확정).** `devtools/gates.ts`
  (fonts·contrast·measure) · 모션 정적 게이트 · allowlist 만료 검사는 있고, **Playwright
  `tests/gates/` 7게이트 하네스가 없다**. 하네스의 진짜 비용은 브라우저가 아니라 **IPC 모의
  픽스처**(`mockIPC`)이고 그것이 `m5-05-e2e-visual` 의 항목이다 — 두 번 만들 이유가 없다.
  `dee()`(16px 실루엣)도 그때 같이 옮긴다.
  **대신 M3 이 감당할 몫이 하나 있다**: 「키보드 완결」은 T1 에서 가장 깨지기 쉽다(Monaco 가
  키를 공격적으로 먹는다). 브라우저 없이도 되는 **jsdom 키보드 테스트**를 `T1Plate` 에
  붙여라 — `SessionScreen.test.tsx` 가 그 본보기다(고르기 → `⌘↵` → 다음).
- **홈의 「이 판 찍기」·「판 만들기」는 M3 이 **먼저** 붙인다 (확정).** 02 §5.5 의
  `role='manual'|'gap'` 삽입 경로(`manualAt`)는 `packages/scheduler` 에 있고 화면 배선만 없다
  — `App.tsx` 의 `onMake`·`onPick` 이 지금 토스트만 낸다. 흘러넘친 **M2 몫**이고 반나절이다.
  T1 보다 먼저 하는 이유 둘: ① 「판이 없는 문법」 패널이 지금 아무 일도 안 하면서 뭔가
  할 것처럼 보인다 ② `manual`·`gap` 역할에 **테스트가 0건**이라 `insertPlate` 의 그 갈래가
  한 번도 안 돌아 봤다.

  씁니다 …」)가 없다. 아무것도 잠그지 않는다는 것이 규칙이므로 문구 한 줄이 전부다.

- **설정 화면과 identity 선택 UI 가 없다**(03 §1.2 의 `suggestIdentities` 는 있다).
