### 밟으면 터지는 자리
- **`gradeFor` 에 `pct` 를 안 넘기면 조용히 Again 이 된다.** `finishPlate` 는 T0 만 보고
  쓰였던 함수라 `pct` 를 안 실었고, 100 % 답안이 `pct ?? 0` → 0 으로 읽혀 등급 1 이 됐다.
  FSRS 간격이 통째로 무너지는데 **테스트 하나가 우연히 잡았다**(`data/t1.test.ts` 의
  「한 단계 쉽게」 케이스). T2 도 `grade: { pct, assists }` 를 반드시 넘겨라.
- **`document` 에서 키를 받으면 `e.target` 이 `Element` 가 아니다.** 판을 걸면 포커스가
  `article.ps` 에 있고 아무것도 안 잡았으면 `e.target === document` 라 `closest` 가 없다 —
  `target instanceof Element` 로 좁혀라. T1 에서 `TypeError` 로 터졌다.
- **`React.lazy` 컴포넌트는 첫 프레임에 없다.** jsdom 테스트에서 `getByLabelText` 는 실패하고

- **`build-catalog.ts` 의 statement 이름 정규식은 그룹에 `_` 를 허용하지 않는다.**
  `why_answer.insert` 는 거부되고 `why.insert_for_item` 이 된다.
- **`last_insert_rowid()` 는 INSERT 하나만 집는다** (D77·D84). 0~n 행을 쓰는 자리(`appeal`)는
  `session_item_id` 부속질의로 원장 행을 되찾는다. T2 「이것도 맞다」도 같은 statement 를 쓴다.
- **`chickadee_parse::Ast` 는 `Serialize` 만 갖는다.** Rust 테스트에서 되읽으려 하면
  `Deserialize` 가 없어 컴파일이 깨진다 — 대조는 글(pretty JSON)로 한다.
- **`pipeline.rs` 의 `spec()` 은 쿼리 하나만 고정해 갖고 있다.** 시스템 쿼리(`_imports`·
  `_blocks`)가 필요하면 **`real_spec()`** 을 써라. `spec()` 으로 인제스트하면 캡처가 0건이고,
  파일 수만 보고 있으면 그것을 눈치채지 못한다(M3 에서 30분을 여기 썼다).
- **`cargo clippy` 는 함수 100줄을 넘기면 error 다.** 테스트도 대상이다.
- **`vitest` 를 두 번 겹쳐 돌리면 유령 실패가 난다.** 골든 스냅샷을 `UPDATE_GOLDEN=1` 로

  pos + 1` 한 문장으로는 큐를 못 민다**(`session.shift_park`/`unpark`) · **채점하면 고른

  싣는데 필사는 그 대부분을 쓰지 않는다. `vs/editor/edcore.main` + 필요한 기여만 고르는
  쪽으로 바꿔 보고 다시 재라. **넘어야 할 숫자는 314 이고 목표는 250 이다.**
- **`frame_p95` 는 여전히 예산을 넘는다 (D80·D81).** 답은 **윈도잉**으로 정해져 있고
  **자리는 `m4-05-dependency-map` 앞**이다. `DependencyMap` 이 같은 SVG 렌더 문제를 다루므로
  그때 홈의 윈도잉을 함께 넣는 것이 원래 계획이다. D81 이 재 봤듯 강등 사다리의 아래 두
  단(판번호 어긋남 끄기 · 결 op 0)은 3 ms 밖에 못 줄인다.
- **T1 은 갓 등록한 리포에서 안 열린다.** 04 §3.1 순위 ②(모르는 문법 ≤ 3개) 때문이고 규칙의
  뜻 그대로이지만, **아무 안내도 없다** — 홈의 T1 자리가 그냥 비어 있다. 「필사는 이 리포의
  문법을 조금 익힌 뒤에 열립니다」 한 줄을 어디에 둘지는 화면 결정이라 사용자에게 물어야
  한다(아래 「사용자가 정해야 할 것」).
- **사전에 `why_gate` 가 한 항목도 없다.** 04 §6 ①(사전 문항 + 3지선다)이 데이터가 없어서
  안 돈다 — 지금 모든 왜 게이트가 ④ 일반 템플릿(「이 줄이 없으면 무엇이 달라질까요?」)이다.
  스키마와 렌더러와 린트는 다 있으니 `dictionary/ts/*.yaml` 에 `why_gate` 를 채우면 켜진다.
  쓸 수 있는 변수는 넷뿐이다 — `file` · `file.base` · `site.line` · `site.text`.
- **3단계 스펙 카드의 `mustHold(source:'user')` 가 비어 있다.** 04 §3.3 ①은 「2단계 통과
  직후 이 함수가 지켜야 할 것 2~4줄 입력」인데 **그 입력 화면이 없다**. `why.for_card`
  statement 와 `buildSpec({whyOwn})` 은 있으니 화면 하나가 남았다.
- **이의의 「규칙 제안」을 보여줄 화면이 없다.** `appeal.pattern_counts`·`suggest()` 는
  있는데 설정 화면 자체가 없다(M5 몫). `issueUrl` 도 부르는 자리가 없다.
- **`fallback` 스위치를 자동으로 켜지 않는다.** 지금은 `stage === 1` 로 고정이다. 실측을
  보고 켜는 배선(예: `perf_sample` 의 마지막 `t1:monaco` 를 읽어 판단)은 안 만들었다.
- **`swift`·`dart` 문법 크레이트가 없다.** 03 §2.1 은 요구한다. 04 §9 골든에도 그 두 언어는
  없어서 M3 이 미뤘다.
- **`m2-06-q5-audit-port` 는 여전히 `in_progress` 이고 M5 에 있다.** Playwright
  `tests/gates/` 7게이트 하네스가 없다 — 진짜 비용은 `mockIPC` 픽스처이고 그것이
  `m5-05-e2e-visual` 의 항목이다. M3 은 그 대신 jsdom 키보드 테스트를 붙였다
  (`screens/session/T1Plate.test.tsx` 12건 — T2 도 같은 틀로 붙여라).

## 사용자가 정해야 할 것 (M4 착수 전)
1. **T1 이 안 열리는 동안 홈이 무엇을 말할까.** 지금은 조용히 빈다. 한 줄 안내를 둘지,
   둔다면 어디에(「오늘의 인쇄」 패널 아래 / 「판이 없는 문법」 옆) 둘지.
2. **`t1:monaco` 를 250 으로 내리는 데 얼마를 쓸까.** Monaco 기여 집합을 줄이는 것은 반나절
   ~하루이고 실패하면 textarea 로 더 물러서야 한다(2·3단계까지). 아니면 314 를 받아들이고
   05 §10 의 그 행을 고칠지 — **예산을 고치는 것은 사용자 결정이다**(D80 때와 같다).
3. **`--verdict-differ-face` 토큰을 추가할까.** M3 의 하위 세션이 「어긋남」 태그의 **면**
   색으로 `--t2`/`--on-t2` 를 빌려 썼다(값은 목업과 같다). 판정 색을 트랙 색에서 떼어 놓자는
   05 §4.2 취지대로라면 별칭 하나가 필요하다 — 토큰 추가는 디자인 결정이다.
