## 사용자가 이미 정한 것 (다시 묻지 마라)

1. **영어는 사전까지 전부.** 앱 문구만이 아니라 `dictionary/**` 57 YAML 까지 영문화하고
   `concept.name_en` 을 `ALTER ADD COLUMN` 한다. **정정** — `name: { ko, en }` 은 57 중
   55 파일에 **이미 채워져 있다**. 남은 것은 `one_liner`·템플릿·문항 산문(한글 약 2.7만 자)
   이라 P3 의 6일은 그대로다. D118 이 문자열마다 `{ ko, en }` 유니온을 열되 스칼라는 ko 로
   읽으므로 기존 57 파일은 손대지 않아도 통과한다.
2. **리포는 서가 화면 신설 + 마스트헤드 스위처 둘 다.** 홈은 그대로 활성 리포 하나를 본다.
3. **클론 코스는 일일 큐(D12 10~25분) 밖 별도 모드.** 예산 규칙을 건드리지 않고 결과만
   `review_log` 로 개념 겹에 반영한다.
4. **착수 순서** — `chickadee-i18n` P1(뼈대) → `chickadee-settings-gaps` →
   `chickadee-repo-shelf` → `chickadee-i18n` P2·P3 → `chickadee-clone-course`.
   이유는 하나다: i18n 뼈대를 먼저 깔아야 뒤 세 플랜이 만드는 새 문구가 처음부터 `t()` 로
   들어가고 번역 대상이 두 번 늘지 않는다.

결정은 **이미 났다.** 남은 것은 등록부 행 문안을 올리고 문서에 반영하는 절차뿐이다 —
D117(로케일 축, D61 을 개정한다) · D119(서가 화면) · D120(큐 밖 코스) · D118(사전 이중
언어). D120 은 정본 §2 트랙 표에 코스 행이 필요하므로 `docs/00` §4.3 절차를 따른다.

## 밟으면 터지는 자리 (계획과 구현이 실제로 밟은 것)

### 병렬로 돌릴 때

- **워크트리가 상위의 최신 커밋에서 갈라진다는 보장이 없다.** 네 갈래 중 둘이 팬아웃 직전
  커밋보다 **앞에서** 갈라졌다. 그래서 한 갈래는 상위가 이미 만든 규약(카탈로그 영역 분리)을
  못 보고 같은 문제를 다른 모양으로 다시 풀었고, 다른 갈래는 `docs/00-overview.md` 에서 자기
  결정 행을 찾지 못했다. **갈래를 띄운 직후 `git log --oneline -1` 로 베이스를 확인하고,
  어긋났으면 그 자리에서 알려라.**
- **워크스페이스 의존이 늘면 병합 직후 `pnpm install` 이 필요하다.** 한 갈래가
  `packages/{ui,cards,grading}` 에 `@chickadee/i18n` 을 더했고, 병합한 트리에서 **81개 테스트
  파일이 한꺼번에 깨졌다**. 심링크가 없어서다 — `pnpm install` 한 번에 초록으로 돌아온다.
  테스트가 무더기로 깨지면 코드를 읽기 전에 이것부터 의심해라.
- **병합이 열려 있을 때 `git commit` 을 하면 그 병합이 닫힌다.** 다른 일로 커밋 한 번을
  끼워 넣었더니 제목은 그 일인데 내용은 병합인 커밋이 남았다. 병합 중에는 `git status` 로
  `MERGE_HEAD` 를 먼저 봐라.
- **`eslint .` 는 `.claude/worktrees/` 안까지 훑는다.** 리포 전체의 사본이라 `design/**` 같은
  경로 기반 무시가 안 먹고 오류 100건이 돌아온다. 지금은 무시 목록에 들어가 있다.
- **모듈 상수로 얼린 문장은 `setLocale()` 보다 먼저 굳는다.** 카탈로그로 옮길 때 `const` 를
  함수로 바꿔야 한다(`GENERIC_WHY_Q` → `genericWhyQ()`). 갈래 하나가 그렇게 바꿨고 다른
  갈래는 옛 이름을 계속 import 해서, **병합은 깨끗한데 `tsc` 만 잡았다**.
- **마이그레이션 시드는 「바로 앞 판 + 새 마이그레이션」이다.** `0002` 를 못 본 갈래가
  `v0003.db` 를 `v0001 + 0003` 으로 구웠고, 그 시드에는 `name_en` 열이 없었다.

- **워크트리는 `main` 이 아니라 엉뚱한 ref 에서 잘린다 — 0.3 에서 세 갈래가 **전부** 그랬다.**
  0.2 는 넷 중 둘이었는데 0.3 은 셋 중 셋이고, 모두 같은 커밋(`f0fd6f7`, 18 커밋 뒤)이었다.
  그 베이스에는 `data/clone.ts`·`0003_clone.sql`·영역별 i18n 카탈로그·`screens/repos/` 가
  **없다** — 코스 갈래는 데이터 층을 통째로 다시 지을 뻔했고, 문구 갈래는 문구를 넣을 데가
  금지된 조립기밖에 없었다. **팬아웃 브리프의 첫 줄을 `git log --oneline -1` 로 베이스 sha 를
  대조하는 것으로 시작해라.** 그리고 대조만 시키지 말고 **`git merge --ff-only <sha>` 를
  갈래가 직접 돌릴 권한을 미리 줘라** — 상위가 손으로 고치면 한 번 더 부팅해야 한다.
  sha 대조보다 나은 것은 **파일 존재 검사**다(「이 셋이 없으면 베이스가 틀린 것이다」).
  갈래가 낡은 베이스에서도 「있는 줄 알았던 것이 없네, 내가 만들자」로 새지 않는다.
- **생성물은 팬아웃 전에 재생성해서 커밋해 둬라.** `packages/store-sql/src/catalog.ts` 가
  `queue.sql` 의 주석 한 줄만큼 뒤처져 있었고, 병합 검증의 `catalog:build` 가 그제야 잡았다.
  드리프트 자체는 무해했지만(주석), 병합 중에 생성물이 흔들리면 그것이 갈래 탓인지 원래
  그랬는지 가리는 데 시간이 든다.
- **`vite preview` 는 실행 사이에 살아남아 옛 `dist` 를 계속 낸다.** `playwright.config.ts`
  가 `reuseExistingServer: !CI` 라서다. `pnpm build` 뒤 `test:gates`·`test:e2e-ui` 전에
  **`lsof -ti tcp:4173 | xargs kill -9`** 를 넣어라. 넣지 않으면 소스에도 `dist` 에도 있는
  버튼이 화면에 없다 — 0.3 에서 한 갈래가 여기에 세 번을 태웠다.
- **`test:gates` 가 부하를 받으면 흔들린다.** 한 갈래의 첫 실행이 motion·keyboard·silhouette
  에서 31건 실패했고, 이어진 세 번은 108/108 이었다. 빨간 게이트를 회귀로 읽기 전에 한 번
  더 돌려라.
- **자기 몫이 아닌 자리는 「빼고 재고 보고」가 맞다.** 0.3 의 문구 갈래가 `TimeQueue` 를
  이름 붙인 상수 하나로 재는 자리에서만 빼고(`NOT_MINE`) 지우는 법까지 주석에 적어 넘겼다.
  상위가 그 파일을 고치고 상수를 지웠다. 갈래가 남의 파일을 고치는 것보다 이쪽이 싸다.

- **로케일 기본값이 OS 추정이라 하네스가 러너를 탔다.** `test:e2e-ui` 가 영어 화면을 보고
  2건 실패했다. 시드가 `ko` 를 심어 고정한다. 하네스에서 언어를 바꾸려면 시드를 바꿔라.
- **등록부 번호는 읽는 순간 낡는다.** 계획을 세울 때 다음 번호가 D114 였는데 착수 시점에는
  D114~D116 이 다른 세션 것으로 차 있었다 — 로케일 축은 D117, 사전은 D118 이 됐다.
  **행을 쓰기 직전에 다시 세라.** D119(서가)·D120(코스)은 예약이고 아직 올라가지 않았다.
- **이 리포에는 세션이 여럿 붙는다.** 커밋 전에 `git log --oneline -5` 와 `git status` 로
  남의 변경이 섞였는지 갈라라. `git add -A` 전에 반드시 본다 — 남의 일지까지 딸려 간다.

- **Rust 줄 예산 2,300/2,300 — 여유 0.** 실측했다(`bash scripts/check-rust-budget.sh`).
  **네 플랜 모두 Rust 추가 0줄로 설계했다.** 한 줄이라도 더하려면 D68 을 다시 여는 사용자
  결정이 먼저다. 코스가 `repo_glob_read` 같은 새 명령을 부르고 싶어지면 그 자리에서 멈추고
  `file_read_lines` 로 되돌아와라.
- **원장은 열을 풀 수 없다.** `review_log.session_id`·`session_item_id` 가 NOT NULL 이고
  `02` §2.2 가 원장 변경을 `ALTER … ADD COLUMN` 으로만 허용한다. 그래서 「큐 밖 모드」인
  코스도 결과를 남기려면 **실행마다 `session` 행 1개 + 조각마다 `session_item`** 을 만들어야
  한다. `session_item.role` 은 CHECK 목록(`review·new·retry·prereq·manual·gap`)에 갇혀 있으니
  `manual` 을 재사용하고, 코스 소속은 `clone_step.review_log_id` 로 가른다. SQLite 는 CHECK 를
  ALTER 로 못 고친다 — 새 role 값을 추가하려 들면 원장을 다시 만들어야 한다.
- **행 길이 게이트는 한국어 전제다.** `05` §9 의 본문 30~45자(좁은 패널 22)를 영어에 그대로
  걸면 `tests/gates/design.spec.ts` 가 통째로 거짓 실패한다. D112 가 05 §9 를 이 규칙의
  정본으로 지정했으니 거기부터 고치고 `06` §2 를 따라 맞춘다.
- **조판이 한국어를 전제한다** — `word-break: keep-all` · `--measure` 36em · `josa` 헬퍼.
  정본 §6 의 조판 규칙 자체가 그렇다. en 은 세 개를 다 다시 정해야 한다.
- **골든 픽스처가 한국어 문구를 담고 있다.** `packages/cards`·`packages/grading` 의 골든은
  생성 문구를 그대로 박제한 것이라, 문구를 `t()` 로 옮기면서 **하네스가 로케일을 ko 로
  고정**하지 않으면 골든이 전부 깨진다. 깨진 골든을 다시 녹화하지 마라 — 로케일을 고정하고
  diff 0 을 확인하는 것이 맞다.
- **`concept.name_ko` 는 컬럼 이름이다.** 스키마가 언어를 이름에 박아 뒀다. `name_en` 을
  더하는 쪽이 맞고, `name_ko` 를 `name` 으로 바꾸는 개명은 원장 규칙상 못 한다.
- **`packages/dictionary` 의 번들은 Vite `import.meta.glob`** 이라 Playwright 프로세스에서
  열리지 않는다(m6 의 그 항목이 그대로 적용된다). 사전을 영문화해도 이 경계는 그대로다.
- **리포 등록의 유일한 문은 네이티브 폴더 대화상자다.** 그래서 E2·E3 이 못 쓰였고(m6 §③),
  서가의 「리포 추가」도 같은 한계를 물려받는다 — E2E 로 덮지 못하니 단위·게이트로 덮어라.
- **마스트헤드의 죽은 버튼에는 CSS 와 aria 가 이미 있다**(`.repo-switch`,
  `aria-haspopup="listbox"`). 새로 만들지 말고 `disabled` 를 떼고 목록을 붙여라.
- **설정 화면에는 「저장」 버튼이 없다** — 칸을 바꾸면 그 자리에서 `settings` 로 내려간다.
  새 칸도 그 규약을 따라야 한다.

## 이번 회차가 남긴 것 (다음 세션이 집을 것)

플랜 넷은 닫혔다. 아래는 **그 안에서 발견됐지만 그 범위가 아니었던 것**이고, 대부분 사람의
결정이 하나씩 필요하다. 위에서부터 값이 크다.

### 사전에 한국어가 남아 있는 두 자리 (영문화가 반쯤이라는 뜻이다)

1. **`edge.code` — 29 파일에 한국어 176줄.** D118 이 산문을 `{ko,en}` 으로 열었지만
   `edge[].code` 는 코드라서 `z.array(z.string())` 그대로다. 그런데 그 코드 **주석**이
   한국어다 — `setN(n + 1) // 바깥의 n 을 읽는다`. 그래서 en 으로 열어도 「가장 날카로운
   자리」 패널은 한국어를 보여 준다. **스키마를 열어야 고쳐진다**(`code` 도 `{ko,en}` 으로
   갈지, 주석만 따로 뽑을지가 결정이다).
2. **`result.value` — 14 파일.** 03 §4.3 은 이 칸을 「코드 조각을 끼운 템플릿」으로 규정하는데
   실제로는 한국어 산문이 들어 있다(`이름 두 개` · `아직 돌지 않은 함수`). 그 YAML 이
   템플릿을 쓰도록 고치거나 칸을 열거나 둘 중 하나다.

### 영어로 열어도 한국어가 나오는 자리

3. **`packages/cards/src/t1-spec.ts:236` 이 `concept.name.ko` 를 박아 읽는다.** T1 스펙 카드가
   `one_liner` 를 렌더할 때다. 사전은 이제 영어가 있는데 이 한 줄이 ko 를 고른다.

### 게이트가 못 보는 것

4. **`dict:lint` 에 ko/en 템플릿 변수 대조가 없다.** `checkText` 는 변수가 허용 목록에
   있는지만 본다. en 에서 변수를 빠뜨리면 **두 언어가 다른 코드를 인용**하는데 린트는 초록이다.
   0.3 의 사전 갈래가 자기 프리플라이트로 1,004쌍을 직접 검사해 통과시켰지만, 그 검사는
   리포에 남지 않았다 — 규칙으로 넣을 자리다.
5. **`--ink-mute`·`--ink-faint` 는 `check-contrast.mjs` 가 「검사 대상 아님」으로 건너뛴다.**
   본문에 쓰면 정적 게이트를 **전부** 통과하고 브라우저에서 4.65:1 로 걸린다. `--desk` 배경이
   빠진 것과 같은 종류의 구멍이다(위 「화면·조판」).
6. **시드의 `file.line_count` 가 전 파일 0 이다.** IPC 덤프에서 구운 것이라 줄 수가 없고,
   앱에서는 `crates/parse` 가 채운다. `clone.course_files` 가 `line_count > 0` 으로 거르므로
   **시드 위의 코스 테스트는 목차가 항상 빈다.** 0.3 의 브라우저 스펙 둘이 그 한 칸만
   `MAX(block.line_end)` 로 복원해서 돌았다. m6 의 「시드를 키운다」 항목에 같이 넣어라 —
   `test:gates` 8건과 `test:e2e-ui` 12건의 skip 이 여전히 같은 구멍이다.

### 프리미티브의 함정

7. **`FlatButton` 은 프롭 목록이 고정이라 `className`·`aria-label` 을 삼킨다.** 넘겨도 조용히
   버려지고 **TS 도 잡지 않는다**(`aria-label` 쪽). 접근 이름은 children 에 넣고, 클래스가
   필요하면 감싸라. 프롭을 늘리는 쪽이 맞는지는 결정이 필요하다.

## 사용자가 정해야 할 것

1. **사전 영문화를 누가 검수하는가.** 1,004쌍이 기계 번역이 아니라 용어집에 고정된 번역이지만
   사람이 읽은 적은 없다. 위 1·2번(`edge.code`·`result.value`)은 그 검수의 일부로 같이 본다.
2. **`ts/template-literal` 의 한국어 본문이 `undefined` 를 「여덟 글자」라고 한다 — 아홉이다.**
   번역 갈래가 틀린 수를 옮기지도, 정본을 말없이 고치지도 않고 보고했다(en 은 「글자들로
   보인다」로 우회). **정본은 사용자 것이므로 고칠지 말지가 결정이다.**
3. **위 1·3·4·7번은 각각 D126~ 가 필요한 변경이다.** 등록부 다음 번호는 **D126** 이지만
   **쓰기 직전에 다시 세라** — 0.2 에서 계획할 때 D114 였던 것이 착수 때 D117 이 되어 있었다.
4. **D68(Rust 예산)** — 이번 회차도 **0줄**로 끝났다. 여전히 2,300/2,300 이고 M6 의
   `repo_glob_read` 는 못 들어간다.

## 규칙

- 정본 > 설계 문서 > 내 판단. 문서를 고치기 전에 `docs/00-overview.md` §4.2.1 에 행을 먼저
  올린다. **D117(로케일 축) · D118(사전 이중 언어)은 올라갔고, D119(서가) · D120(코스)은 각
  플랜의 P0 가 올린다 — 그 밖의 새 결정은 D121 부터.** 체크리스트 항목 제목은 바꾸지 않는다.
- 표면 언어(D61): 커밋·PR·`.github/**`·README 류는 영어, 앱 UI 문구·`docs/**`·`.oculpm/**`
  는 한국어. **D117 이 이 규칙의 「앱 UI 문구」 부분을 개정한다** — 개정 뒤에도 정본은 ko 다.

- 얇은 Rust 상한 2,300(D68) — 지금 정확히 차 있다. 도메인 어휘·SQL 리터럴 금지.

  `check:motion` · `design:check` · `test:gates` · `test:e2e-ui` ·
  `catalog:build`(statement 를 고치면 **반드시**).
