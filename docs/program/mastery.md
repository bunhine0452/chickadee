# 진도와 평가 — 챕터 통과 판정

결론부터 — **잉크 겹을 진도 표시에서 내리고 챕터 단(段)으로 갈아 끼운다. FSRS 는 버리지 않고
자리를 옮긴다.** 전제는 `PROGRAM.md` §2 — 챕터 = 기능 하나(`entryUnits` 폐포, D160), 안은 다섯 단.

---

## 1. 지금 것이 무엇을 재나

| 부품 | 재는 것 | 어디 |
|---|---|---|
| 잉크 겹 0~4 | **개념 하나**를 시간을 두고 다시 맞힌 횟수. 「그날의 천장」 하나로 R1~R5 를 표현 | `reducer.ts` |
| FSRS-5 | 언제 다시 낼지 — S·D·`due_at` | `fsrs.ts` |
| 큐 | 만기 ≤ 20 + 새 T0 2 + T1 주 2 + T2 이틀 1, 예산 15분 | `plan.ts` `LIMIT` |
| 원장 | 판 하나 = `review_log` 한 행 (FSRS 열 15개 포함) | `0001_init.sql:351` |

**측정 단위가 개념이다.** `mastery` 의 기본키는 `concept_id` 하나이고 리포·대지·기능은 그 표에 없다.
「`ts/optional-chaining` 이 3겹」은 답할 수 있고 **「로그인을 이해했는가」에 답할 행은 어디에도 없다.**
겹을 다 합쳐도 안 나온다 — 합은 어휘의 양이지 기능의 이해가 아니다.

`EVALS.md`(D149)가 절반을 드러냈다. `ledger` 9개 중 통과 0, 그중 **L5 가 `t1`·`t2` 원장 0건**이고
학습 성과를 재는 게이트는 `gates` 13개 중 0개다.

## 2. 왜 안 맞나 — 그리고 버리면 무엇을 잃나

간격 반복은 **짝**을 잰다. 「`@PostMapping` 이 무슨 뜻인가」는 짝이다. 「버튼을 누르면 어느 파일 어느
줄이 순서대로 도는가」는 짝이 아니다 — 답이 다섯 파일에 걸친 순서라 짧게 다시 물어도 안 짧아진다.

| 어긋나는 자리 | 지금 규칙 | 코스가 요구하는 것 |
|---|---|---|
| 축이 하나다 | 겹 0~4 한 줄 | 5단은 축이 아니라 **다른 질문들**이다. 3단 예측을 못 하면서 1단 읽기를 4겹까지 쌓을 수 있고, 그때 홈은 「완성」이라고 쓴다 |
| 진도를 하루 한 칸으로 묶는다 | R1 하루 최대 +1 | 챕터를 오늘 끝까지 이해해도 겹은 한 칸이다 |
| 만기 전에는 안 오른다 | R2 `now ≥ due_at − 12h` | 이어서 파고드는 것이 조기 인쇄로 처리된다 |
| 트랙이 진도 축을 겸한다 | T0·T1·T2 | 트랙은 **채점기의 이름**이지 학습 깊이가 아니다 |

**버리면 잃는 것.** D149 가 박은 간격 효과 근거는 진짜다 — 같은 날 몰아친 반복은 즉시 성능만 올린다.
챕터를 하루에 통과시키면 그 통과는 **그날의 성능**이다. 잃는 셋:

| 잃는 것 | 없으면 |
|---|---|
| **시간 축** (같은 날 두 번 = 한 번) | 통과가 벼락치기와 구별되지 않는다 |
| **개인화된 재출제 시각** (S·D) | 고정 일정표는 SM-2 의 「쉬운 카드가 어려운 카드와 같은 간격」으로 돌아간다 |
| **흐려짐** (02 §3.4) | 4겹 영구 배지가 홈에서 거짓말한다 |

셋 다 챕터에도 필요하다. 그래서 §4 에서 두 자리로 옮긴다.

## 3. 새 판정 — 챕터 하나를 통과했다

### 3.1 어디까지가 필수인가

| 단 | 필수 | 채점 | 실행 |
|---|---|---|---|
| 1 읽기 | **필수** | 지목·의미·빈칸 (지금 T0 그대로) | 없음 |
| 2 추적 | **필수** | 순서 맞히기. 정답지는 `import_edge`(`kind='http'`)·MyBatis 매퍼 간선·`exec/order` | 없음 |
| 3 예측 | **필수** | 4지선다. **정답지가 코드 자체**다 | 없음 |
| 4 수정 | **조건부** — 문항을 구울 수 있을 때만 | AST 제약 질의 | 없음 |
| 5 재구현 | **아니다** | T1 3단계로 근사, 게이트 아님 | 필요 |

**5단을 게이트에서 빼는 근거.** 실행 없이 재구현을 채점하면 줄 단위 비교가 되고 그건 이해가 아니라
필사다(정확히 지금의 T1 이다). `t3_run` 은 언제나 `NOT_IMPLEMENTED` 를 돌려주고(`commands/app.rs:52`)
막는 것은 Tauri `shell` 스코프와 샌드박스다(`t3-adapter.ts`). **못 재는 것을 통과선으로 쓰지 않는다.**

**4단이 실행 없이 되는 이유.** 정답이 여럿이라 줄 비교가 아니라 **제약**을 본다. 표본 리포의 실제 자리:

```java
// BACK/.../service/AuthService.java:78-84
User user = userDao.findByLoginId(request.getLoginId())
        .orElseThrow(() -> new ResourceNotFoundException("사용자를 찾을 수 없습니다."));  // → 404
if (!passwordEncoder.matches(request.getPassword(), user.getPassword())) {
    throw new UnauthorizedException("비밀번호가 일치하지 않습니다.");                    // → 401
}
```

문항은 「없는 아이디와 틀린 비밀번호가 서로 다른 코드를 준다. 둘 다 401 이 되게 고쳐라」. 제약 셋 —
① `login` 안에 `ResourceNotFoundException` 이 없다 ② `UnauthorizedException` 이 둘 ③ `findByLoginId`
호출이 남아 있다. AST 질의로 판정되고 정답 문자열은 하나가 아니다.

### 3.2 통과선

| 단 | 문항 수 | 통과선 |
|---|---|---|
| 1 읽기 | 경로 위 개념 수 (6~12) | 개념 전부가 **1겹 이상** |
| 2 추적 | 1 | 순서 **전부** 맞음 (부분점수 없음) |
| 3 예측 | 3~5 | 4/5 |
| 4 수정 | 1~2 | 제약 **전부** 충족 |

2단에 부분점수가 없는 이유: 다섯 중 넷을 맞혀도 틀린 하나가 `JwtAuthenticationFilter` 라면 「무엇이 언제
도는가」를 놓친 것이다 — 그 필터는 컨트롤러가 import 하지 않아 **읽어서는 안 보이고 순서로만 보인다**
(D160 이 「런타임 배선은 못 본다」로 잰 31파일이 여기 있다).

**챕터 통과** = 1·2·3 ∧ (4단 문항이 있으면 4도). 통과가 하는 일 둘 — 다음 챕터가 열리고 재검 일정이 잡힌다.

### 3.3 부분 통과와 되돌림

부분 통과가 **곧 단이다.** 진도는 정수 하나(`stage_reached` 0~5)이고 3 이면 「예측까지」다. 겹 0~4 를
이 자리에 재사용하지 않는다 — 겹은 시간 축, 단은 깊이 축이고 한 숫자에 담으면 §2 의 첫째 행이 돌아온다.

| 언제 | 무엇이 내려가나 |
|---|---|
| 3단에서 틀린 이유가 1단이 다룬 개념일 때 | **그 개념의 판**만 큐 앞에 끼운다. `stage_reached` 는 안 내린다 |
| 재검에서 추적을 틀렸을 때 | `stage_reached` −1. **유일한 챕터 되돌림** |

챕터를 내리면 앞으로 못 가고, 그것이 정본 §3-7 이 하트를 버린 실패 모드다. 재검만 예외인 이유는 시간이
지나 잃은 것이 진도가 아니라 사실이기 때문이다.

## 4. 복습을 어디에 두나

주 루프에서 내리되 **두 자리에 남긴다.** 없애지 않는 근거는 §2 의 「잃는 셋」이다.

**① 1단 안쪽 — 겹과 FSRS 를 어휘 판정기로 강등한다.** `@PostMapping` 이 무엇인지는 낱개 사실이고 간격
반복이 재는 바로 그것이다. `mastery`·`review_log`·`reducer.ts`·`fsrs.ts` 는 한 줄도 안 고치고, 바뀌는
것은 보이는 자리뿐이다 — 진도는 챕터 단이 말하고 겹은 「어휘 12개 중 4개가 애벌」 한 줄로 줄어든다.

**② 챕터 재검 — FSRS 를 챕터에 그대로 건다.**

| | 내용 |
|---|---|
| 문항 | **새로 안 만든다.** 그 챕터의 2단 추적 1 + 3단 예측 1 을 다시 낸다 |
| 일정 | `chapter` 행에 `mastery` 와 **같은 열**(S·D·`due_at`)을 두고 `fsrs.ts:makeScheduler` 를 그대로 부른다. 새 알고리즘 0 |
| 등급 | 둘 다 맞음 Good(3) · 예측만 틀림 Hard(2) · 추적 틀림 Again(1) |
| 간격 | 기본 파라미터로 3일 → 9일 → 3주 (02 §3.5 궤적) |
| 실패 | Again 이면 `stage_reached` −1 |
| 예산 | 만기 재검은 안 뺀다 — 「부채를 미루지 않는다」(`plan.ts` 머리말)를 챕터로 승계 |

이 하나가 「배웠다」의 **직접 증거**다. 3일 뒤에도 추적하고 예측하면 배운 것이고, 아니면 그날의
성능이었다. `EVALS` L2 의 `elapsed_days ≥ 1` 이 여기서 자연히 지켜진다 — 같은 날 재검을 안 낸다.

**③ 없애는 것.** 겹을 진도 표시로 쓰는 것, 그리고 겹의 하루 상한(R1·R2)이 챕터 진행을 묶는 것. 챕터
안에서는 하루에 몇 단이든 오르고, 시간 축은 재검이 지킨다.

**하루 15분** — 만기 재검(3~4분) → 오늘 챕터의 다음 단. 예산이 넘치면 다음 단을 자르고 재검은 남긴다.
재검은 미루면 간격이 무너지고, 다음 단은 내일 그 자리에 그대로 있다.

## 5. 막힘

지금: `pressDunno`(`session-flow.ts:589`) → `dunno_event`(판당 1회, `UNIQUE(session_item_id)`) → 사다리
4단(`ladder_event.action` = `open`·`jump`·`back`·`return`·`prompt_built`·`copied`). 아래층 점프는 **깊이
1** 이다(`jumpPrereq` 가 `shouldInsertPrereq(plate.role)` 로 막는다). 단마다 처방이 다르고, 새 `action`
값 없이 채운다.

| 막힌 단 | 방향 | 무엇을 하나 | 기록 |
|---|---|---|---|
| 1 읽기 | **뒤로** | 지금 그대로. 선행 판으로 깊이 1 점프 | 그대로 |
| 2 추적 | **옆으로** | 경로를 **접어서** 다시 묻는다 — 5칸(프론트 → 컨트롤러 → 서비스 → DAO → 매퍼)을 3칸으로. 선행 개념이 모자란 게 아니라 경로가 안 보이는 것이다 | `rung=2, action='jump'`, `target_card_id` = 접은 판 |
| 3 예측 | **뒤로** | 그 줄의 1단 개념 판을 큐 앞에 끼운다 (§3.3) | 그대로 |
| 4 수정 | **밖으로** | 사다리 4단 — 프롬프트를 만들고 사람이 들고 나간다 | `prompt_built` · `copied` |

**4단의 창이 지금 규격으로 모자란다.** 정본 §3-1 ④ 는 「이 줄과 앞뒤 4줄」만 담는데, §3.1 의 수정 문항은
메서드 하나(7줄)와 예외 두 종의 이름이 있어야 질문이 성립한다. 제안은 **창을 「고칠 메서드 하나」로
넓히고 나머지 제외는 그대로**(디렉터리 경로·리포명·커밋 메시지·작성자 제외, 파일 이름만). 정본을
넓히므로 §8 의 결정 행이 먼저다.

**3회 막히면 챕터를 접는다.** 한 세션에서 같은 챕터의 `dunno_event` 가 3건이면 그날 그 챕터를 닫고 앞
챕터의 재검으로 돌린다. 벌이 아니라 순서 재조정이다 — 위상 정렬이 안 맞았다는 신호이고, 계속 밀면
정본 §3-7 이 경계한 「1000일 연속인데 회화를 못 하는」 자리가 된다.

## 6. 무엇을 기록하나

### 6.1 기존 표로 되는 것 — 손대지 않는다

| 표 | 새 모델에서 |
|---|---|
| `review_log` | 1단 어휘 판정 전부. 열 하나 안 바뀐다 |
| `dunno_event` · `ladder_event` | 막힘 전부. 2단 옆걸음도 기존 `action='jump'` 로 담긴다 |
| `session` · `session_item` | 재검은 `role='review'`, 단 문항은 `role='new'` — CHECK 에 값을 안 더한다 |
| `unit` · `unit_file` | 챕터 = 대지. N:M 이 이미 기본키다(`(unit_id, file_id)`, D160) |
| `card` | 2·3단은 기존 `kind`(지목·의미), 4단은 T1 입력 판. **새 트랙도 새 kind 도 없다**(D151·D158 선례) |
| `mastery` | 개념 겹. 그대로 |

### 6.2 새로 필요한 것 — 표 둘, 마이그레이션 한 장

```sql
-- 0007_chapter.sql (user_version = 7)
CREATE TABLE chapter (              -- 챕터 진도. unit 과 1:1
  unit_id        INTEGER PRIMARY KEY REFERENCES unit(id) ON DELETE CASCADE,
  origin         TEXT    NOT NULL CHECK (origin IN ('entry','dir')),
  stage_reached  INTEGER NOT NULL DEFAULT 0 CHECK (stage_reached BETWEEN 0 AND 5),
  passed_at      INTEGER,
  -- 재검 일정: mastery 와 같은 열이라 fsrs.ts 를 그대로 부른다
  state          INTEGER NOT NULL DEFAULT 0 CHECK (state IN (0,1,2,3)),
  stability REAL, difficulty REAL, due_at INTEGER, last_review_at INTEGER,
  reps INTEGER NOT NULL DEFAULT 0, lapses INTEGER NOT NULL DEFAULT 0,
  deferred_day   TEXT,                         -- 3회 막혀 접은 날 (day_key)
  applied_log_id INTEGER NOT NULL DEFAULT 0,   -- 재생 커서
  updated_at     INTEGER NOT NULL
);

CREATE TABLE stage_log (            -- 단 하나를 판정한 순간. review_log 의 챕터판
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  unit_id    INTEGER NOT NULL REFERENCES unit(id),
  session_id INTEGER NOT NULL REFERENCES session(id),
  stage      INTEGER NOT NULL CHECK (stage BETWEEN 1 AND 5),
  kind       TEXT    NOT NULL CHECK (kind IN ('first','recheck')),
  asked      INTEGER NOT NULL, correct INTEGER NOT NULL,
  passed     INTEGER NOT NULL CHECK (passed IN (0,1)),
  grade      INTEGER CHECK (grade IN (1,2,3)),   -- recheck 만. FSRS 로 간다
  elapsed_days REAL NOT NULL DEFAULT 0,
  reviewed_at INTEGER NOT NULL, day_key TEXT NOT NULL,
  duration_ms INTEGER NOT NULL, detail_json TEXT NOT NULL
);
CREATE INDEX ix_stage_unit ON stage_log(unit_id, reviewed_at);
```

| 왜 이렇게 | 근거 |
|---|---|
| `mastery` 를 재사용하지 않는다 | 기본키가 `concept_id REFERENCES concept(id)` 다. 챕터를 개념으로 위장하면 `concept` 에 가짜 행이 생기고 사전 린트(`dict.test.ts`)가 잡는다. 열은 베끼되 표는 나눈다 |
| `stage_log` 가 `review_log` 와 별개다 | `review_log` 한 행은 **판 하나**이고 `s_after`·`d_after`·`due_after` 가 NOT NULL 이다. 단 하나는 판 여러 장의 합이라 그 열을 못 채운다. 억지로 넣으면 `EVALS` L1~L9 의 SQL 이 오염된다 |
| `unit.source` 를 안 건드린다 | `'entry'` 를 CHECK 에 더하려면 표를 다시 만들어야 하고(SQLite 는 CHECK 를 ALTER 못 한다), 0005 가 한 「외래키 끄고 아홉 표 확인」 절차를 다시 부른다(D146) |

## 7. EVALS 갱신

**`gates` 13 — 전부 산다.** 학습을 안 재기 때문이다. 하나만 다시 잰다: **G3·G4 의 래칫**(유형 쏠림
76.5% · 정답 위치 45%) — 2·3단 문항이 붙으면 분포가 바뀐다.

**`ledger` 9 → 7 생존 · 5 신설.**

| 옛 | 판정 | 새 자리 |
|---|---|---|
| L1 겹이 쌓이나 | 산다, 축소 | 1단 어휘 판정에만. 진도 지표가 아니게 된다 |
| L2 「시간을 두고」 | **산다, 이사** | 대상이 개념 → **챕터 재검**. `stage_log WHERE kind='recheck' AND elapsed_days >= 1` |
| L3 첫 노출 정답률 | 산다 | 1단이 그대로 T0 다 |
| L4 0장 완주 일수 | **죽는다** | 0장이 챕터 0 이 된다 → C1 |
| L5 트랙 커버리지 | **죽는다** | 트랙이 진도 축이 아니게 된다 → C2 |
| L6 사다리 | 산다 | 그대로 |
| L7 아래층 점프 효과 | 산다, 확장 | 2단 옆걸음(경로 접기)을 같은 SQL 이 센다 |
| L8 예산 채움 · L9 재출제 간격 | 산다 | L9 는 챕터 재검 간격으로 이사 |

신설 다섯. 전부 `stage_log`·`chapter` 만 읽는다 — 「지표를 발명하지 않는다」(D149)를 지킨다.

| # | 재는 것 | 통과선 |
|---|---|---|
| C1 | 첫 챕터 통과까지 며칠 (`MIN(passed_at)` − 첫 세션) | ≤ 10일 |
| C2 | 단 커버리지 — `stage_log` 에 1·2·3·4 가 각각 있나 | 각 `n ≥ 1` |
| C3 | 2단 추적 **첫 시도** 정답률 | 0.30~0.70 |
| C4 | 3단 실패로 되돌린 개념의 다음 정답률 | ≥ 0.6, `n ≥ 10` |
| C5 | **재검 유지율** — `kind='recheck'` 의 `passed` 비율 | ≥ 0.7, `n ≥ 20` |

C3 의 상한 0.70 이 D138 의 경계를 계승한다 — 추적 문항이 너무 쉬우면 추적이 아니라 읽기 확인이다.
하한 0.30 은 경로가 너무 길다는 신호다. **C5 가 이 문서의 결론을 판정한다** — 0.7 을 못 넘으면 통과선이
그날의 성능만 잡은 것이고 재검 간격을 좁혀야 한다.

**`human` 4 → 3 생존 · 2 신설.**

| # | 판정 |
|---|---|
| H1 | **다시 쓴다** — 「로그인 챕터를 1단부터 4단까지 밟는다」. 볼 것 넷: ① 2단이 `JwtAuthenticationFilter` 를 실제로 묻는가 ② 3단 진단이 「그것이 참이 되는 조건」인가 ③ 4단 제약이 화면에서 읽히는가 ④ 마쳤을 때 그 기능을 남에게 설명할 수 있는가 |
| H2 오답 진단 형식 | 산다, 그대로 |
| H3 여덟 개념의 판 | 죽는다 (그날의 일이었다) |
| H4 | **다시 쓴다** — 챕터 화면(단 표시·재검 배지·접힌 경로) |
| **H5** 신설 | 4단 제약이 **다른 옳은 고침을 틀렸다고 하는가**. 기계는 제약 충족만 본다 |
| **H6** 신설 | 3회 막혀 챕터를 접었을 때 그것이 **벌로 읽히는가** |

**`blocked` 4 → 3 생존 · 1 신설.**

| # | 판정 |
|---|---|
| B1 어떤 레포도 읽는다 | 산다. 사전 커버리지가 여전히 축이다 |
| B2 구조를 이해한다 | **죽는다** — 챕터 2·3단이 바로 그것을 재고 C3·C5 가 수를 낸다. blocked 였던 이유(T3 가 `NOT_IMPLEMENTED`)가 5단을 게이트에서 빼면서 사라진다 |
| B3 장기 파지 | 산다, 축소. C5 가 3주까지는 잰다 |
| B4 「배웠다」의 주관 | 산다 |
| **B5** 신설 | **5단 재구현**. 실행 없이 못 잰다. `t3_run` 이 막혀 있는 한 통과선을 못 세우고 기록만 한다 |

## 8. 사용자 결정이 필요한 것

| 무엇 | 왜 내가 안 정하나 |
|---|---|
| **프롬프트 창을 「앞뒤 4줄」에서 「메서드 하나」로 넓힌다** (§5) | 「코드는 컴퓨터 밖으로 안 나간다」의 경계를 넓힌다. 정본 §3-1 ④ 의 수치가 바뀐다 |
| **4단을 못 굽는 챕터는 3단까지가 통과인가** (§3.1) | 통과선이 챕터마다 달라진다. 대안(「4단이 없으면 그 챕터를 안 낸다」)은 낼 수 있는 챕터를 줄인다 |
| **겹을 화면에서 얼마나 지우나** (§4 ①) | 잉크 겹은 시각 시스템의 은유 축이다(정본 §6 — 새가 선명해진다). 어휘 판정기로 강등해도 그림은 남길 수 있고, 그 판단은 디자인 결정이다 |
