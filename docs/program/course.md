# 코스 구조 — 리포 하나에서 코스 한 벌

**결정 등록부** D162(코스) · D160(기능 = 진입점 폐포) · D159 · D147·D136(0장) · D12 · D161 · **D177(정식 코스 3부 — §3.3)**.

정하는 것은 넷이다 — 챕터 경계 · 챕터 순서 · 언어 어휘가 끼는 자리 · 길이와 끝. 다섯 단의
내용은 다른 문서가 정한다. 표본은 `MonggleMonggle`(Spring + Vue + MyBatis + FastAPI)이다.
아래 수치는 `entryUnits`·`routeHit`·자바 import 해석기를 그대로 옮겨 다시 돌린 것이고,
D160 이 적어 둔 값과 **전량 일치한다**(코드 121파일 · 기능 8 · auth 18 · 폐포 밖 31 · 겹침 13).

## 1. 챕터를 무엇으로 자르나

### 1.1 기본 — 폐포 하나가 챕터 하나

| 기능 | 파일(java+js) | 파일(오늘 읽히는 전부) | 요청 수 |
|---|---|---|---|
| auth | 18 | 19 | 6 |
| dream | 17 | 19 | 6 |
| dreamResult | 16 | 18 | 5 |
| fortune | 13 | 13 | 2 |
| image | 6 | 6 | 2 |
| monthlyAnalysis | 27 | 32 | 5 |
| notice | 27 | 31 | 10 |
| ranking | 7 | 8 | 1 |

「요청 수」는 진입 파일에서 나가는 `kind='http'` 간선 수다(전체 37개). **이것이 챕터 안의 진짜
단위다** — §5 가 예산을 파일이 아니라 요청으로 잡는 이유다.

### 1.2 진짜 문제 — 폐포 밖 31파일

한 덩어리가 아니다. 재 보니 여섯 종류이고 종류마다 처분이 다르다.

| 종류 | 수 | 실물 | 왜 밖에 있나 |
|---|---|---|---|
| 런타임 배선 | 2 | `SecurityConfig` · `JwtAuthenticationFilter` | 컨트롤러가 import 하지 않는다. Spring 이 엮는다 |
| 부트·설정 | 4 | `FinalProjectApplication` · `Web/WebClient/SwaggerConfig` | 아무도 안 부른다 |
| 횡단 규약 | 4 | `GlobalExceptionHandler` · `ErrorResponse` · `CustomException` · `InsufficientCoinException` | 모든 챕터가 던지고 여기서 받는다 |
| 비-HTTP 진입점 | 2 | `CoinSchedulerService`(`@Scheduled`) · `CoinService` | 규칙의 구멍이지 잡동사니가 아니다 |
| 프론트 상태·부트 | 13 | `stores/` 4 · `composables/` 3 · `router` · `main.js` · `utils` · `constants` · 배럴 · 빌드 설정 | 폐포는 **아래로만** 간다. 이것들은 진입 파일의 **위**다 |
| 죽은 갈래 | 5 | `EmotionController`·`Service`·`Dao`·`EmotionScore`·`EmotionListResponse` | 프론트가 `GET /emotions/stats` 를 부르는데 서버에는 경로 없는 `@GetMapping` 하나뿐이라 `/api/emotions` 만 있다 |

(+ 시험 1파일은 코스 밖이다.)

**.vue 를 넣으면 밖에 있는 것이 31 → 64 로 는다.** Vue 24장 13,546줄이 통째로 어느 챕터에도
안 든다. 사용자가 물은 「뷰는 백엔드와 어떻게 통신하는가」·「CSS 정의는 어떻고」가 그 파일들이다.

### 1.3 붙이는 규칙 다섯 — 순서대로, 첫 매치가 이긴다

| # | 규칙 | 실측 효과 |
|---|---|---|
| **R0** | **진입점을 늘린다** — `kind='http'` 외에 `@Scheduled` | 9번째 챕터 「코인」. 2파일 회수 |
| **R1** | **위로 한 단** — 진입 파일을 **직접** import 하는 프론트 파일은 챕터 본문 | 13파일 회수(밖 64 → 53). 챕터 5개가 화면을 갖는다 |
| **R2** | **막간** — 아래로 어떤 챕터의 파일에 닿으면 그 챕터 뒤 한 판 | `SecurityConfig` → `JwtAuthenticationFilter` → `JwtUtil` → **auth 막간** |
| **R3** | **부록** — 아래로 닿는 챕터가 셋 이상이면 | `GlobalExceptionHandler` 가 6챕터에 닿는다 |
| **R4** | **남은 것은 남긴다** — 「기타」로 접지 않고 **보고한다** | Emotion 5파일 · `imageService.js` |

**R1 의 깊이를 1로 고정한 근거는 측정이다.** 깊이 2 면 auth 가 19 → 31 파일이 되고
`LandingView.vue`(1,528줄)가 네 챕터에 동시에 든다. 무한히 올라가면 37파일이다 — `authStore` 를
안 쓰는 화면이 없다. 화면을 자동으로 고르는 규칙도 재 봤고 **안 된다**: `.vue` 24장 중 8장은
어느 기능에도 안 닿고 7장은 넷 이상에 닿는다.

**R2 가 서려면 자바 간선 하나가 더 필요하다.** 같은 패키지면 `import` 를 쓰지 않아
`JwtAuthenticationFilter → JwtUtil`·`DreamResultService → CoinService` 가 안 보인다. 같은
디렉터리의 클래스 이름 참조를 간선으로 더하면 **20간선**이 생기고 폐포 밖이 31 → 28 로 준다.
대가도 쟀다 — package-by-layer 라 서비스끼리 번져 dream 이 17 → 27 파일이 된다.
**막간·부록 판정에만 쓰고 챕터 본문 폐포에는 안 쓴다.**

R4 가 남긴 둘은 잡동사니가 아니라 **발견**이다. 죽은 서버 갈래(Emotion 5파일)와 죽은 프론트
갈래(`imageService.js`)는 §5 의 졸업 과제가 된다.

## 2. 챕터 순서

### 2.1 커밋 시간은 못 쓴다 — 재 보고 버렸다

254커밋이 있어도 순서 정보가 거의 없다. **121파일 중 79(65%)가 첫날 태어났고**, 커밋 #2
(`chore: backend initial setting`) 하나가 백엔드 대부분을 만들었다. 기능별 생성 커밋의 중앙값은
auth·dream·dreamResult·monthlyAnalysis 가 **전부 #2 로 동점**이고, 진입 파일도 넷이 같은
커밋(#3 `feat. login and logout and signup`)에서 나온다. 갈라지는 것은 notice(#26) ·
ranking(#31) · image(#6) 셋뿐이다. 바이브 코딩 리포는 대개 이 모양이다 — 한 번에 쏟아붓고 뒤에
붙인다. **커밋 시간은 마지막 동점 처리에만 쓴다.**

### 2.2 쓰는 축

| 축 | 실측 | 쓰나 |
|---|---|---|
| 다른 챕터가 쓰는가 | `api.js` 8/8 · `SecurityUtil` 7/8 · `ApiResponse` 6/8 | **1번 고정** |
| 새로 여는 파일 수 | 아래 표 | **2번부터의 정렬 키** |
| 파일 수 · 의존 깊이 | 6~32파일 · 깊이 2~4 | 참고만. 깊이는 거의 다 3이라 안 가른다 |
| 커밋 시간 | §2.1 | 동점 처리만 |

**auth 를 1번으로 고정한다.** 나머지 일곱이 전부 컨트롤러 첫 줄에서
`SecurityUtil.getCurrentUserId()` 를 부른다 — 로그인을 모르면 다른 챕터의 첫 줄이 안 읽힌다.
사용자가 직접 물은 것도 로그인과 JWT 다.

| 2 | image | 6 | 3 | 3 |
| 3 | ranking | 7 | 6 | 1 |

## 3. 언어 어휘가 코스 어디에 끼나

### 3.1 지금 0장은 이 리포에서 일하지 않는다

0장은 그 언어 `essential` 중 선행 깊이 ≤ 2 인 것을 최대 24판 담는다(D147). 재 보면:

- **자바 사전은 8개뿐이다**(class·variable·assignment·arithmetic·boolean·comparison·if·method).
  상한 24가 자바에서는 아무 일도 하지 않는다.
- **그 8개로 1장 첫 파일이 안 열린다.** `AuthController.java` 104줄에 나오는 것은 넷뿐이고,
  못 읽히는 것은 **애너테이션**(백엔드 718회 · 49종 · 이 파일에만 7종) · **제네릭**(111회 ·
  `ResponseEntity<LoginResponse>`) · `import` · 접근 제어자 · Lombok 이 지운 생성자다.
  사전에 항목이 **없다**.
- **언어가 챕터마다 다르다.** 문법 8종인 리포에서 파이썬 프롤로그를 맨 앞에 두면 40일 뒤 6장에서 쓴다.

### 3.2 0장을 잘라 챕터 앞에 붙인다 — 「어휘 관문」

0장은 코스 밖 별도 대지에서 내려와 **챕터마다 앞에 붙는 관문**이 된다. 담기는 것은
`essential` 이 아니라 **그 챕터의 파일이 실제로 쓰는데 아직 0겹인 개념**이다.

| | 상한 | 내용 |
|---|---|---|
| ~~관문 0~~ | ~~12판~~ | **폐기 — 정식 코스 1·2부가 흡수했다 (D177)** |
| **관문 1~9** | 챕터당 6판 | 그 챕터가 새로 여는 어휘. 6장 앞에서 파이썬이, 부록 앞에서 CSS 가 열린다 |
| **코스 전체** | **40판** | D136·D147 의 「튜토리얼로의 변질」 방벽을 코스 규모로 옮긴 것 |

정렬(① 내 코드 사용처 먼저 ② 선행 깊이 ③ 미지 ④ id)과 끝 조건은 `zeroChapterPlates` 의 것을
그대로 쓴다. **상한 40판이 테스트로 못박히는 자리다**(`packages/course/src/curriculum.test.ts`).

### 3.3 관문 0 이 없어진 자리 — 정식 코스 3부 (D177)

관문 0 은 「자바를 읽는 최소치 12판」이었다. 그 자리를 **정식 자바 코스 1·2부 29판**이
가져갔다(`docs/curriculum/java.md` §2). 바뀐 것 셋이다.

**① 담기는 목록이 리포에 매이지 않는다.** 관문 0 은 「그 챕터가 쓰는데 0겹인 것」이라 리포에
없는 문법은 영영 안 들어왔다. 실측이 그 크기를 준다 — `MonggleMonggle` 자바 99장에서
`for (;;)` **0곳** · for-each **1곳** · 배열 **1곳** · `abstract class` **0곳** ·
제네릭 경계 **0곳** · `equals`/`hashCode` 재정의 **0곳**이다. 1·2부는 이것들을 합성 예제로
가르치고 「네 코드엔 없다 + 왜 없나」를 함께 낸다.

**② 순서가 리포가 아니라 개념 그래프에서 온다.** 부 안에서 선행이 먼저다(위상 정렬).

**③ 관문은 뺄셈이 된다.** 챕터 관문은 이제 **부가 안 가르친 어휘**만 센다
(`chapterGates` 의 `taught`). 자바 리포에서 자바 어휘는 부가 다 흡수했으므로 관문에 남는 것은
js · SQL · 규약(`proto/`) · 기계(`cs/`)다.

**아는 것은 건너뛴다.** 첫 실행의 한 문항(「프로그래밍이 처음이신가요?」)과 원장을 함께 보아
1부를 통째로 접는다(`foldsPart1`). **배치고사는 여전히 만들지 않는다**(D147 · 정본 §9) —
레벨을 재는 시험과 대상 경계를 묻는 한 문항은 다르다. 다른 언어를 아는 사람에게 실제로
걸리는 길은 **개념 전이**(D4)다: `universal` 이 같은 개념은 겹을 물려받으므로 파이썬을 아는
사람의 `java/if-statement` 는 배우기 전에 이미 1겹이고, 1부가 전부 1겹이면 접힌다.

## 4. 언어가 여럿인 챕터

로그인 한 챕터에 js · java · xml(안에 SQL)이 있고, 화면까지 넣으면 vue 와 CSS 가 붙는다.
지금 앱에 답이 없는 자리다.

**① 판 하나에 언어 하나.** 판이 여러 파일을 보여도 묻는 것은 한 언어의 것이다.
**② 언어 순서는 요청이 흐르는 순서다** — js(호출) → java(컨트롤러·서비스·DAO) → xml/SQL(매퍼)
→ java(응답 DTO) → js/vue(저장·표시). 층으로도 언어로도 안 자른다.
**③ CSS 는 읽기 단에서 뺀다.** 셋째의 근거는 셋이다 — CSS 는 요청 경로에 없다 · 실측 사용처가
css 6,524 대 java 577 로 자릿수가 달라 순위 셋째 키가 사용처 수인 한 CSS 가 전부 이긴다(D161) ·
Vue 24장 13,546줄 중 **7,671줄(57%)이 `<style>`** 이라 SFC 를 통째로 열면 챕터의 절반이 CSS 가 된다.
CSS 는 **부록 「모양」** 한 장으로 뺀다. 거기서는 밀도가 문제가 아니라 재료다.

## 5. 코스의 길이와 끝

### 5.1 예산 — 하루 15분(D12)은 그대로 두고, 읽는 단위를 바꾼다

**파일을 다 읽으면 안 된다.** 8챕터를 화면까지 다 읽으면 읽기만 700분 = 47일이다. 읽기 단의
단위를 파일이 아니라 **요청 한 줄기**(전체 37개)로 잡고, 그 요청이 지나는 5~7파일의 해당
메서드만 한 판에 담는다. 값은 `EST_MIN`·`t1Est`(02 §5.1, 실측 EMA)에서 끌어온다.

| 단 | 단위 | 분 | 근거 |
|---|---|---|---|
| 1 읽기 | 요청 하나 | 4 | `t0_new` 2.1 × 2 (한 판이 파일 여럿에 걸친다) |
| 2 추적 | 챕터 하나 | 8 | `t2_new` 4 × 2 |
| 3 예측 | 요청 하나 | 2 | `t0_new` 2.1 |
| 4 수정 | 챕터 하나 | 16 | `t1Est` 상한 |
| 5 재구현 | 챕터 하나 | 7~16 | `t1Est` = clamp(7,16, 줄 수 × 0.65) |

**8챕터 = 542분 = 36일.** 관문 40판(6일) · 막간 2 · 부록 3 · 졸업 2 를 더해 **약 51일 ≈ 7주**다.
챕터 하나는 3~7일이다.

**그 앞에 부 셋이 선다 (D177).** 1부 13판 · 2부 16판 · 3부 15판 = 44판이고 하루 새 판 2장(D12)이라
**23일**이다. 코스 전체는 **74일 ≈ 10주**. 1부를 접는 사용자에게는 7일이 빠져 **67일**이다.
부를 넣어 늘어난 23일이 D177 이 산 것의 값이다 — 그 대신 이 리포에 0곳인 개념 넷
(`for-loop`·`abstract-class`·`generic-bound`·`equals-hashcode`)을 가르칠 수 있게 된다.

### 5.2 「끝났다」

지금 앱에는 끝이 없다. 셋으로 정의한다.

| 무엇 | 끝난 조건 |
|---|---|
| **관문** | 담긴 개념이 모두 1겹 이상 (D136 조건 ①) |
| **챕터** | 다섯 단을 통과하고, 5단에서 그 챕터의 컨트롤러 한 장을 도움 없이 다시 쓴다 |
| **코스** | 모든 챕터가 끝나고 **졸업 과제**를 통과한다 |

**졸업 과제는 앱이 답을 모르는 문제다.** 이 리포에서는 R4 가 남긴 것이 그대로 문제가 된다 —
프론트가 부르는 `GET /emotions/stats` 가 서버에 없고(5파일이 통째로 죽어 있다),
`imageService.js` 는 어떤 화면도 import 하지 않는다. **이 둘을 스스로 찾아 진단하면 끝이다.**
그래프가 이미 찾아 놓았으므로 채점은 되고, 답은 코스 어디에도 안 적혀 있다.

끝은 **그 시점의 리포**에 대한 것이다. 새 커밋이 새 기능을 만들면 챕터가 늘고 코스가 다시 열린다.
