# 학습 프로그램 — 코스

**결정 등록부** D162. 사용자 요청: 「문제를 푸는 방식, 코스 이런 거 다 완전 새로 만들어서
학습 프로그램을 만들어 달라」.

앱은 **간격 반복 플래시카드**였다. 낱개 개념을 하루 2장씩 뿌리고 잉크 겹에 숙련도를 쌓는다.
사용자가 물은 것은 그 종류가 아니었다 — 「로그인 기능은 **어떻게 이루어지며**」,
「이 기능 하나를 만들려고 **어떤 코드들이 유기적으로 연결되어 있는가**」.
낱장을 다 외워도 경로가 안 보인다.

이 폴더는 그 교육 층을 다시 짠 것이다. **파싱·그래프 층은 그대로 쓴다.**

| 문서 | 무엇 |
|---|---|
| [`exercises.md`](./exercises.md) | 문제를 푸는 방식 — 유형 16개, 무엇을 버리고 무엇을 살리나 |
| [`course.md`](./course.md) | 코스 구조 — 챕터를 어떻게 자르고 어떤 순서로, 몇 주인가 |
| [`mastery.md`](./mastery.md) | 진도와 평가 — 잉크 겹·FSRS 를 어디로 내리나 |
| [`chapter-login.md`](./chapter-login.md) | 첫 챕터 실물 — 로그인을 5단 끝까지 |
| [`fundamentals.md`](./fundamentals.md) | **기초 문항의 형식** — 4지선다를 버리고 값을 적게 한다(`value`·`step`·`table`·`build`). 열 언어 공통 |
| [`pedagogy.md`](./pedagogy.md) | **근거** — 프로그래밍 교육 연구에서 재현된 것 20개와 다섯 단·형식 넷의 대조. 언어별 문서가 「이 언어 특유」를 주장할 때의 시험 셋 |

## 1. 프레임

**코스의 단위는 기능이다.** 낱개 개념이 아니라 `entryUnits`(D160)가 낸 폐포 — 로그인·꿈 기록·알림.

**챕터 안은 다섯 단이다.** 「침팬지를 공학자로」가 이 사다리다.

| 단 | 묻는 것 | 유형 수 | 통과 필수 |
|---|---|---|---|
| 1 읽기 | 이 줄이 무엇인가 | 3 | ✅ |
| 2 추적 | 무엇이 언제 도는가 | 4 | ✅ |
| 3 예측 | 바꾸면 무엇이 달라지나 | 3 | ✅ |
| 4 수정 | 이렇게 되게 만들어라 | 3 | 문항을 구울 수 있을 때만 |
| 5 재구현 | 빈 파일에서 다시 | 3 | ❌ — 아래 §3 |

어휘·기계(`cs/`)·규약(`proto/`)·판단(`arch/`)은 트랙이 아니라 **한 단에서 물을 수 있는 것의 종류**다.

## 2. 네 문서가 합의한 것

**갈림길은 「무엇을 재나」가 아니라 「정답지가 어디서 나오나」였다.** T0 세 종은 전부 **사전**에서
나오고 실행 추적·T1·T2 는 **리포**(파스 트리·커밋·그래프)에서 나온다.
그래서 **T0 의미형을 버린다** — 모든 값이 사전의 치환이라
「`deleted_date IS NULL` 을 지우면 누가 로그인되나」를 **적을 수가 없다**. 리포마다 답이 다르다.
이것이 지금 앱이 사용자의 물음에 답 못 하는 구조적 이유다.

**살린다**: T1 페이딩 3단(→ 5단 뼈대) · **T1 동등 판정 사다리** · 왜 게이트 · 이의 루프 ·
실행 추적(D151) · T2 책임 배치.
사다리를 재활용하는 근거가 날카롭다 — 그 사다리의 오류가 **한쪽으로만** 난다(보수적이라 거짓
동등은 안 나고 거짓 어긋남만 난다). 4·5단에서는 그 방향이 맞다.

**잉크 겹·FSRS 를 버리지 않고 강등한다.** 1·2단의 어휘 판정기로 남고 `mastery`·`review_log`·
`reducer.ts`·`fsrs.ts` 를 한 줄도 안 고친다. 복습은 **챕터 재검**(3일 → 9일 → 3주)으로 옮겨
`fsrs.ts` 를 그대로 부른다 — 새 알고리즘이 0이다.

**「테스트 통과」의 대안은 커밋 원장이다.** `fix:` 커밋의 diff 가 실측 정답지다.
4단 문항이 실제 커밋 `dc37666`·`22c85de` 로 만들어졌다 — 사람이 실제로 고친 것이라 지어낼 필요가 없다.

## 3. 5단을 통과 조건에서 뺀다

`commands/app.rs:53` 이 `Err(not_implemented("T3"))` 다. 실행 없이 재구현을 채점하면
**이해가 아니라 필사**(지금의 T1)가 된다. 문항은 내되 게이트에는 안 넣는다 —
**못 재는 것을 통과선으로 쓰지 않는다.**

뜻: 「침팬지를 공학자로」가 한 칸 앞에서 멈춘다. 「만들 수 있다」는 T3 가 깨어나야 판정된다.
유형 16개 중 실행이 필요한 것은 `handoff` **하나**뿐이라, T3 를 여는 값은 그 한 칸이다.

## 4. 실물이 잡아낸 것 — 프레임의 결함 셋

**① 경로의 단위가 파일이면 안 된다.** `LandingView.vue` 는 1,527줄인데 로그인 관련은 **48줄(3%)** 이다.
지금 `entryUnits` 는 파일을 통째로 넣으므로 학습자에게 1,479줄의 잡음을 준다.
원소를 `(파일, 바이트 범위)` 로 내려야 한다 — **D160 을 고치는 자리다.**

**② 자바는 같은 패키지면 `import` 를 안 쓴다.** `JwtAuthenticationFilter:25` 가 `JwtUtil` 을
import 없이 쓴다(둘 다 `…finalproject.security`). 이런 간선이 **20개** 안 보이고,
**그것이 `SecurityConfig` 가 어느 챕터에도 못 붙던 진짜 이유다.**
`_imports.scm` 이 `import_declaration` 만 잡는 탓이라 고칠 수 있다.

**③ 커밋 시간은 챕터 순서 축으로 못 쓴다.** 121파일 중 **79(65%)가 첫날** 태어났고 커밋 하나가
백엔드 대부분을 만들었다. D160 이 커밋 클러스터를 안 고른 판단이 여기서 두 번째로 확인됐다.

## 6. 코스의 크기

관문 0 + 9챕터 + 막간 1 + 부록 3 + 졸업. 요청 한 줄기 37개.
`EST_MIN`·`t1Est` 에서 유도해 **약 51일 ≈ 7주**.

0장은 코스 앞 한 번이 아니라 **챕터마다 붙는 어휘 관문**으로 잘랐다 —
관문 0 = 12판, 관문당 6판, 코스 전체 상한 40판(D136·D147 의 방벽을 이식).

CSS 는 **읽기 단에서 뺐다**. 사용처가 css 6,524 대 java 577 이라 넣으면 나머지를 덮는다
(D161 이 잰 밀도 문제가 코스에서는 이렇게 풀린다).

## 8. 검증 못 한 것

- **이 코스를 사람이 실제로 통과하는지 안 재 봤다.** 51일은 `EST_MIN` 에서 유도한 값이고 실측이 아니다.
- 기계로 잰 것은 있다 — `MonggleMonggle` 로그인 챕터에서 2단 14 · 3단 5 · 4단 3 · 5단 3 장이 구워진다(D172, `packages/course/src/measure.test.ts`). 1단 `twin` 과 `cs/` 는 개념 캡처가 든 덤프가 없어 실리포에서 못 쟀다.
- 4단 「제약 채점」이 실제 답안에서 거짓 어긋남을 얼마나 내는지 안 쟀다. T1 사다리의 실측(골든)은
  필사 기준이라 편집 기준으로는 다시 재야 한다.
- 병렬 넷이 서로를 안 보고 썼다. 겹치는 판단(예: 4단의 필수 여부)은 이 문서가 조정했지만
  **문서 안의 세부는 아직 서로 안 맞을 수 있다.**
