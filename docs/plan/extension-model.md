# 확장 모델 — 언어 하나를 더할 때 무엇을 새로 짜는가

> 병렬 조사 넷 중 **뼈대**를 맡은 문서다. F1(러스트)·F2(파이썬)·F3(JS 프레임워크)가 각 축을
> 조사하고, 여기는 축이 아니라 **축을 늘리는 비용**을 잰다. 목차는 [`README.md`](./README.md).
>
> 근거: 정본 §5(범용성 세 티어) · `docs/curriculum/feature-paths.md` §6 ·
> `docs/00-overview.md` §4.2.1 의 D156·D157·D159·D174~D180 · `docs/01-architecture.md` §2.
> 측정은 전부 2026-09-05 의 작업 트리(HEAD `3245f54` 위 병렬 브랜치)에서 잰 값이다.

## 0. 요약 — 세 줄

1. **언어 하나를 더할 때 손대는 자리가 29곳**이고, 그중 **필수는 8곳**이다. 나머지 21곳은
   빠뜨려도 앱이 안 죽지만 하나씩 기능이 조용히 꺼진다 — 무엇이 꺼지는지는 §1 의 표에 적었다.
2. **정본 §5 의 「티어 A 로 내려앉는다」는 지금 참이 아니다.** 안 덮은 언어만 있는 리포는
   내려앉는 게 아니라 **아무것도 안 남는다**(파일 0장 · 사용처 0 · 챕터 0 · 카드 0). 죽지는 않고
   빈 화면과 함께 「이 리포로는 코스가 서지 않습니다」를 띄우는데, 그 문구가 대는 이유 셋
   어디에도 **「이 언어를 아직 안 덮었다」가 없다** (§2).
3. 가장 싸게 효과를 내는 순서는 **① 배관을 한 자리로 모으고 ② 언어 센서스를 만든 뒤 ③ 축별
   사전**이다. ①·②를 먼저 하면 F1·F2·F3 이 각자 고칠 자리가 20곳에서 **3곳**으로 줄고,
   사용자 리포 10개 중 코드가 있는 7개에서 주 언어가 읽히는 비율이 **4/7 → 7/7** 이 된다 (§5).

### 1.2 표에서 나온 것 셋

**① 확장자 → 언어 표가 여섯 벌 있다.** `session-flow.ts` 하나가 정본이어야 하는데, 화면 다섯이
각자 `if (ext === '.py') …` 를 다시 쓴다. 여섯 벌 중 자바를 아는 것은 둘뿐이고, 나머지 넷은
`.java` 를 `typescript` 로 그린다. 언어 하나를 더할 때 이 여섯을 다 찾아야 하고, 못 찾으면
증상이 「강조가 이상하다」라 리뷰에서 안 걸린다.

**② 그리고 하나는 이미 어긋나 있다.** `ReimplPlate.tsx:37` 이 `grammar === 'java'` 에서
`'java'` 를 돌려주는데 `MONACO_LANGUAGES` 는 여섯(`typescript`·`javascript`·`python`·`go`·
`rust`·`sql`)뿐이고 `ClonePad.tsx` 도 그 여섯만 싣는다. 같은 파일 34행의 주석은 「여섯 밖이면
typescript 로 그린다」고 적혀 있으나 코드는 그러지 않는다 — **5단 재구현 판의 자바 코드는
문법 강조 없이 plaintext 로 그려진다.** `monacoOptions.ts` 의 주석이 경고한 바로 그 버그다.
(이 문서의 범위 밖이라 고치지 않았다. 자바 축 세션 몫이다.)

**③ 러스트 예산이 31줄 남았다.** `bash scripts/check-rust-budget.sh` → **2,769/2,800**.
`LANGS` 항목 하나가 3줄이므로 **새 문법 열 개를 링크하면 예산이 끝난다.** 다행히 열 언어
중 여섯(`typescript`·`javascript`·`python`·`sql`·`go`·`rust`, 여기에 `java`·`xml`·`css`)은
**이미 링크돼 있다** — Go·Rust 는 문법이 서 있고 사전만 없다. 남은 넷(C·C++·C#·Swift)과
사용자 리포에 실제로 있는 Astro·Ruby 만 Rust 를 건드린다.

### 1.3 파이썬이 싼 이유, 자바가 비싼 이유

| | 파이썬 (D152) | 자바 (D159·D156·D166·D177) |
|---|---|---|
| 배관 | **이미 있었다** — `grammarSchema`·`resolvePy`·`t1-block` 의 `#` 주석·`langs.rs` | 없었다 — `73648b0` 이 1·2·8·12 를 깔았다 |
| 첫 커밋 | 사전 15파일 · 553줄 · 개념 2 | 배관 10파일 · 간선 148줄 |
| 지금 | 개념 8 · 1,787줄 · 골든 **0장** | 개념 29 · 6,920줄 · 골든 187파일 |
| 개념 한 장 | 평균 203줄 | 평균 219줄 |

**골든은 선택이다.** `fixtures/golden/` 아래 디렉터리는 `ts`·`tsx`·`sql`·`java`·`t1`·`t2`
여섯뿐이고 **`py` 가 없다** — 파이썬 개념 여덟은 골든 없이 서 있다. 대신 개념 YAML 의
`examples[]` 를 `pnpm dict:test` 가 실제 파이프라인에 돌린다. 골든이 잡는 것은 「문법 크레이트를
올렸을 때의 조용한 실패」이고, 그것은 그 언어를 오래 유지할 때 드는 비용이지 여는 비용이 아니다.

### 1.4 프레임워크(티어 B)는 따로 센다

`dictionary/java/_imports.scm` **148줄 중 120줄 남짓이 스프링 규칙**이다 — `@RequestMapping`
클래스 기본 경로, 메서드 애너테이션 다섯 × 경로 있음/없음 = 열, `@Scheduled` 진입점,
`webClient.uri()`. 여기에 `dictionary/spring/` 15개념 1,461줄과 `mybatis/` 배관이 얹힌다.
정본 §5 가 「프레임워크마다 규칙 하나씩이라 개수가 안 끝난다」고 적은 자리가 정확히 이 파일이고,
**언어를 여는 비용과 프레임워크를 여는 비용은 서로 대체되지 않는다.**

## 2. 「내려앉음」 실측 — 참이 아니다

정본 §5 는 「안 덮은 스택에서 앱은 죽지 않고 **A 로 내려앉는다**」고 적었고,
`feature-paths.md` §6 은 「Django 리포라면 티어 A 전부 + 파이썬 import 그래프까지 된다」고
예를 들었다. **후자는 참이고 전자는 거짓이다.** 파이썬은 덮은 언어라서 되는 것이지 내려앉아서
되는 게 아니다.

### 2.1 무슨 일이 나는가 — 코드 경로

`.go`·`.rb`·`.astro` 만 든 디렉터리를 인제스트하면 이렇게 된다.

```
langSpecs(dict)                 ← packages/dictionary/src/load.ts:262
  .filter(extensions>0 && queries>0)   ← 쿼리 없는 문법은 여기서 사라진다
        ↓ 확장자 15개만 남는다
extension_map(spec)             ← apps/desktop/src-tauri/src/jobs.rs:484
  표에 없는 확장자 = 파일 행을 안 만든다
        ↓ file 0장
deriveRepo → 사용처 0 · 블록 0 · 간선 0
        ↓
assignUnits([])  = { units: [], byPath: {} }   ← 「기타」도 안 생긴다
entryUnits([],[]) = []
buildCourse([])   = []
requestPaths([])  = []
```

실행해 확인했다(`npx tsx`, 순수 함수 넷). **예외를 던지는 자리는 없다 — 전부 빈 배열이다.**

**파서가 읽는 확장자는 오늘 열다섯이다**:
`.cjs .css .cts .java .js .jsx .mjs .mts .py .pyi .sql .ts .tsx .vue .xml`.
`grammarSchema` 는 열아홉 문법을 허용하지만 `go`·`rust`·`swift`·`dart`·`c`·`cpp`·`c_sharp` 은
**사전이 없어 확장자가 하나도 안 붙는다** — `langs.rs` 에 Go·Rust 문법이 링크돼 있어도
`.go`·`.rs` 파일은 열리지 않는다.

### 2.2 화면은 무엇을 보여 주나

| 화면 | 0장일 때 | 문구 |
|---|---|---|
| 코스 | `data.chapters.length === 0` 가지 | 「아직 챕터가 없습니다 — 리포를 읽으면 기능마다 챕터가 섭니다.」 |
| 필사 코스 | `enterCourse` 가 `null` → `setEmpty('files')` | 「코스에 담는 것은 문법을 아는 파일뿐입니다. 지금 이 리포에는 그런 파일이 없습니다 — **아직 읽지 않았거나, 바이너리·생성물만 있거나, 파일이 하나뿐입니다.**」 |

**답: 빈 코스다. 오류도 아니고 「기타」 한 덩어리도 아니다.** 그리고 필사 코스의 문구가 대는
이유 셋 중 **맞는 것이 하나도 없다.** 사용자는 Go 리포를 읽혔고, 바이너리도 아니고, 파일도
많다. 앱은 이유를 알고 있는데(확장자가 표에 없다) 말하지 않는다.

### 2.3 왜 티어 A 가 남지 않나

티어 A 넷 중 언어 어휘를 뺀 셋이 전부 **언어 사용처에 얹혀서** 산다.

- `cs/` 43개 — 자기 캡처가 없고 자기를 `prereq` 로 가리키는 언어 개념의 **창을 빌린다**
  (D157 ② · `packages/course/src/borrow.ts`). 빌릴 창이 없으면 안 선다.
- `proto/` 10개 — 근거 낱말이 보이는 **블록**이 자리다. 블록은 `_blocks.scm` 이 만들고,
  그것은 파싱된 파일에서만 나온다.
- `arch/` 6개 · `exec/` 1개 — 그래프와 AST 에서 **계산**한다. 둘 다 파일 0장이면 입력이 없다.
- 0장(`zero-chapter.ts`)도 같다 — 주석이 못박아 두었다: 「리포에 사용처가 **아예 없는** 개념은
  넣지 않는다.」
- `queue.new_candidates` 의 둘째 UNION 가지(D154)는 「사용처 없이 **카드가 이미 구워진**
  개념」만 통과시킨다. 카드를 굽는 재료가 사용처이므로 순환이 끊긴다.

**즉 티어 A 는 「언어 어휘가 하나라도 서면 따라오는 것」이지 「언어와 무관하게 되는 것」이
아니다.** 정본 §5 의 문장은 실제 동작보다 한 칸 넓게 약속하고 있다.

### 2.4 반쪽 리포는 더 조용하다

읽히는 언어와 안 읽히는 언어가 섞이면 앱은 **읽힌 절반만으로 코스를 세우고 아무 말도 하지
않는다.** `IngestDone` 에 `files`·`changed`·`captures`·`warnings` 는 있어도 **「표에 없어서
건너뛴 파일 수」가 없고**, `RepoProbe` 에도 언어 분포가 없다. 사용자 리포로 재면:

| 리포 | 주 언어 | 코드 파일 | 읽히는 파일 | 안 읽히는 것 |
|---|---|---|---|---|
| `file_converter` | **rs** | 89 | 45 (51%) | rs 43 — 앱의 본체가 통째로 |
| `PySpace` | **rs** | 22 | 12 (55%) | rs 8 |
| `bunhine_web` | **astro** | 92 | 48 (52%) | astro 26 · html 18 |
| `ai-pm` | ts | 1,029 | 700 (68%) | **rs 280** |
| `ECC` | js | 556 | 507 (91%) | sh 32 · rs 16 |
| `adelie` | py | 142 | 139 (98%) | rb 1 · html 1 |
| `MonggleMonggle` | java | 210 | 209 (100%) | html 1 |
| `MindExtract`·`andrej-karpathy-skills`·`bunhine0452` | — | 0 | 0 | 문서만 |

**코드 파일 2,140장 중 1,660장(78%)이 읽힌다.** 그런데 `file_converter` 를 연 사용자는
「러스트로 만든 변환기」를 배우려는 것이지 그 앞의 React 화면을 배우려는 것이 아니다.
**주 언어가 읽히는 리포는 코드가 있는 7개 중 4개(57%)** 다.

### 2.5 그래서 필요한 것

「어느 프로젝트든 지원한다」의 최저선은 카드가 아니라 **정직한 보고**다. 세 조각이면 선다.

1. **언어 센서스** — 인제스트가 확장자별로 「읽음 / 표에 없어 건너뜀」을 세어 돌려준다.
   Rust 쪽은 `extension_of()` 가 이미 확장자를 계산하고 있으므로 카운터 하나(`BTreeMap`
   증가 + `IngestDone` 필드 하나)이고, 어림 **10~15줄**이다. 예산 31줄 안에 든다.
2. **인제스트 뒤 한 줄** — 「`.rs` 43장을 못 읽었습니다. 러스트 사전은 아직 없습니다.」
   `course.emptyFiles` 의 이유 셋에 넷째를 더하는 것이 아니라, **넷째가 맞을 때는 넷째만**
   보여야 한다.
3. **문법 없이도 되는 최소 티어 A** — 안 덮은 언어에서도 `cs/`·`proto/` 를 낼 수 있게 하려면
   창을 빌릴 자리가 필요하다. 가장 싼 답은 **정규식 블록 폴백**이다(T1 이 이미 문법 없는 언어에
   같은 폴백을 쓴다 — 정본 §5). 「함수처럼 생긴 줄부터 들여쓰기가 돌아올 때까지」를 블록으로
   치면 `proto/` 의 근거 낱말 검색과 `cs/` 의 창 빌리기가 둘 다 산다. **이것은 정본이 약속한
   내려앉음을 실제로 구현하는 유일한 조각이고, 없으면 §5 의 문장을 고쳐야 한다.**

3번을 하지 않기로 정한다면 정본 §5 의 「A 로 내려앉는다」는 **「A 는 그 언어의 어휘가 한 장이라도
서야 따라온다. 안 덮은 언어에서는 앱이 그 사실을 말한다」**로 고치는 것이 정직하다.
결정은 사용자 몫이다 (§6 후보 ②).

## 3. 기여 표면 — 개념 한 장은 데이터, 언어 한 장은 데이터가 아니다

정본 §5 는 「기여 표면이 데이터라 커뮤니티가 언어를 늘린다」고 적었다. **개념 한 장에 대해서는
참이고, 언어 한 장에 대해서는 거짓이다.**

### 3.1 지금 무엇이 설명돼 있나

`CONTRIBUTING.md` §「Contributing to the grammar dictionary」(72~172행, 101행)는 **개념 한 장을
더하는 데 충분하다.** 두 파일 구조, `dict:` 세 층, `pnpm dict:lint`, 검사기 넷의 분담표
(무엇을 기계가 보고 무엇이 사람 몫인지), 모델로 초안을 뽑는 규칙(D144), 저작 부채 래칫 표까지
있다. 「사람이 볼 것은 둘뿐 — `meaning` 의 값 주장과 진단의 반사실」이라는 문장은 리뷰 시간을
어디에 쓸지까지 정해 준다. 이 절은 손댈 것이 없다.

**모자란 것은 그 위 한 층이다 — 언어 하나를 여는 법.** §1 의 표 29줄 중 `CONTRIBUTING.md` 가
언급하는 것은 5·6 둘뿐이다.

### 3.2 `dictionary/README.md` 판정 — **모자라다. 게다가 낡았다**

20줄이고, `CONTRIBUTING.md:88` 이 「the directory contract」로 가리키는 문서인데:

| 적힌 것 | 지금 사실 |
|---|---|
| 「`lang` 은 `ts·py·go·rs·swift·dart·sql·common·react·arch`」 | 실제는 `arch common cs css exec java mybatis proto py react spring sql ts` 열셋. `go`·`rs`·`swift`·`dart` 는 **없고**, `java`·`css`·`cs`·`proto`·`exec`·`spring`·`mybatis` 는 **빠져 있다** |
| 「내용은 M1 에서 채운다 … 지금은 번들 리소스 경로가 성립하도록 폴더만 있다」 | 개념 **185장 · 24,495줄** + 쿼리 93장 1,219줄이 서 있다 |
| `_lang.yaml` = 「version · grammars · extensions」 | `grammar_abi`·`essential`·`alternatives`·`thin_threshold`·`detect`·`framework` 가 더 있다 |

**써야 할 것 목록** (이 문서의 범위이므로 §4 의 자동화와 함께 채운다):

1. **네임스페이스 종류 넷을 가른다** — ① 문법 네임스페이스(`_lang.yaml` + `.scm`) ② 계산
   네임스페이스(`common/`·`arch/`·`exec/`·`cs/`·`proto/` — `queries: []`, 사용처를 빌리거나
   계산한다) ③ 프레임워크(`react/`·`spring/` — `detect` 게이트로 감지 실패 시 로드 안 함)
   ④ 배관 전용(`mybatis/` — 개념 0, 시스템 쿼리만). 넷의 저작 비용이 다르다: 언어 개념은 평균
   **203~221줄**, 계산 네임스페이스는 **87~95줄**(쿼리도 예시도 없어 절반).
2. **`_lang.yaml` 필드 표** — `grammars`(문법 키, `lang` 과 다른 축 · D19) ·
   `grammar_abi`(대조는 `cargo test` 가 한다) · `extensions`(**키가 `lang` 이 아니라 `grammar`**
   다 — D157 ④가 지적한 자리) · `essential`(**여기 이름이 있는데 파일이 없으면 사전 전체가 안
   뜬다**) · `thin_threshold` · `detect`/`framework`.
3. **캡처 규약** — `@site` 는 패턴당 하나, `@hole`·`@pick.N`·`@ctx.*` 의 뜻, `_imports.scm` 의
   `(#set! form "…")` 로 쓰는 `form` 값 목록(오늘 33종: `static`·`require`·`route-*`·
   `http-*`·`field`·`local`·`call`·`call-self`·`same-package`·`entry-scheduled`·`ddl-*`·
   `mapper-of`·`column-of`·`reads-table`·`from`·`dynamic`). 이 목록이 없으면 새 언어의
   `_imports.scm` 을 쓸 수 없다 — 지금은 `dictionary/java/_imports.scm` 을 읽어 유추하는 것이
   유일한 길이다.
4. **골든은 선택이라는 것** + 두는 법(`crates/parse/tests/support/mod.rs` 의 `DIRS` 한 줄,
   기대 파일은 `UPDATE_GOLDEN=1 cargo test -p chickadee-parse --test golden` 이 쓴다).
5. **언어 하나를 여는 체크리스트** — §1 표를 「필수 8 / 선택 21」로 줄인 것.
6. `app_data_dir/dict-user/<lang>/` 우선순위(이미 적혀 있다 — 유지).

### 3.3 남는 진실

`CONTRIBUTING.md:74` 은 「this is the part … that needs no Rust」라고 적는다. 개념에 대해서는
맞다. **언어에 대해서는 새 문법이면 Rust 두 곳(§1 의 1·2)을 지나야 하고, 그 문은 러스트 예산
31줄이 지키고 있다.** 문법이 이미 링크된 언어(Go·Rust)라면 참이 되고, 그 사실을 README 에
적으면 커뮤니티가 **어느 언어부터 손대야 싼지**를 알 수 있다.

### 4.2 줄어드는 양 — 자바로 역산

| | 지금 | `new-language.mjs` 뒤 |
|---|---|---|
| 손대는 **자리** 수 | 29 | **11** |
| 그중 「찾아야 하는」 자리 | 20 (배관·화면·시험) | **3** (`_imports.scm` · 해석기 · 러너) |
| 배관 코드 줄 수 | ~120줄이 20파일에 흩어짐 | 0 (스크립트가 씀) |
| 사전 본문 | 개념 × 210줄 | 그대로 (LLM 초안 + 사람 검수) |

**줄지 않는 것이 본체다.** 개념 스무 장이면 4,200줄이고 그것은 사람이 읽어야 하는 글이다.
자동화가 줄이는 것은 **줄 수가 아니라 「어디를 고쳐야 하는지 찾는 비용」**이고, 병렬 세션
넷이 도는 지금 그 비용이 실제 비용이다 — F1·F2·F3 이 각자 §1 의 표를 다시 만들면 세 번 만드는
것이다.

시간으로 어림하면(자바 커밋 넷의 범위로 역산, **어림값이고 실측이 아니다**):
배관 20자리를 찾아 고치는 데 반나절~하루, 스크립트가 있으면 몇 분. 개념 저작은 그대로.

### 4.3 스크립트가 하지 말아야 할 것

- **`essential` 을 채우지 않는다.** 이름만 있고 파일이 없으면 사전 전체가 안 뜬다 —
  빈 목록으로 두고 개념을 쓸 때 한 줄씩 늘린다.
- **`DEBT_RATCHET` 을 올리지 않는다.** 래칫은 「채운 뒤에 잠그는 것」이고 기계가 미리 올리면
  방벽이 없어진다.
- **문법 크레이트를 `default` 에 자동으로 넣지 않는다.** `Cargo.toml` 의 주석이 적어 둔 대로
  「빌드를 깨는 커뮤니티 문법은 다른 언어를 안 건드리고 뺄 수 있어야」 하고, 예산이 31줄이다.

## 6. 결정 등록부에 올릴 행 — 초안

**등록부에 아직 올리지 않았다.** 착수 결정은 사용자 몫이므로 여기에 초안만 둔다. 번호는
병렬 세션 넷의 결과를 합칠 때 오케스트레이터가 배정한다(오늘 마지막은 D180).
