# 구현 계획 — 「자바 말고 다른 언어와 프로젝트도」

2026-09-05, 사용자 요청 「자바 말고도 다른 언어와 프로젝트들도 지원할 수 있는 걸 찾아보고
**구현할 계획을 세워** 달라」에 답하는 네 문서다. 병렬 세션 넷이 같은 날 같은 트리에서 각자
실측하고 썼다.

**넷 다 계획이지 착수가 아니다.** 결정 등록부(`docs/00-overview.md` §4.2.1)에 행을 올리지
않았고, 각 문서의 마지막 절에 **올려야 할 행의 초안**이 있다. 착수 결정은 사용자가 한다.

이 폴더는 마일스톤 회고(`docs/handoff/`)와 다르다 — 저쪽은 끝난 일이고 여기는 아직 안 정해진
일이다. 정본은 여전히 `.oculpm/discussion/vibe-code-study-app/discussion.md` 의 「결론」이고,
설계는 `docs/00-overview.md` 부터 읽는다.

## 넷이 같이 가리키는 것

세 축이 따로 재고 같은 결론에 닿은 자리가 있다.

- **러스트 예산이 31줄 남았다** (`bash scripts/check-rust-budget.sh` → 2,769/2,800).
  새 문법 하나가 `langs.rs` 에서 3줄이므로 **어느 언어에 그 줄을 쓸지가 결정거리**다.
  Go·Rust 는 문법이 이미 링크돼 있어 **Rust 코드 0줄**이고, C·C++·C#·Swift·Astro·Ruby 는 든다.
- **진입점이 없으면 기능 챕터가 안 선다.** 파이썬 축이 `adelie`·`ECC` 에서, JS 축이 다섯 중
  넷에서 같은 것을 쟀다. HTTP 라우트를 전제한 `entryUnits` 가 CLI·데스크톱 앱에서 빈 배열을 낸다.
- **프레임워크(티어 B)보다 언어 어휘(티어 A)가 먼저 값을 낸다.** 파이썬 축의 셈이 가장
  분명하다 — 중심 16장이 덮음을 두 배로 올리는데 프레임워크 사전은 그 절반의 절반도 못 올린다.
- **같은 함정이 축 둘에 걸려 있다.** 러스트 축이 `await f<T>(x)` 에서 `function:` 자리에
  `await_expression` 이 온다는 것을 재다 찾았는데, **이미 있는 `dictionary/ts/_imports.scm` 의
  HTTP 패턴 다섯에도 같은 구멍이 있다** — `await api.get<T>("/x")` 가 조용히 안 걸린다.
  JS 축이 「다섯 리포 중 넷에서 진입점 0개」를 잰 것과 같은 뿌리일 수 있다.

## 착수한다면 이 순서 (오케스트레이터가 넷을 합쳐 제안)

각 축 문서가 자기 안에서 순서를 매겼고, 아래는 **축을 가로지르는** 순서다. 근거는 셋 —
① 러스트 예산 31줄이 병목이라 그것을 쓰는 조각을 먼저 정해야 한다 ② 배관을 먼저 고치면 축
셋이 고칠 자리가 20 → 3 으로 준다 ③ **Rust 코드 0줄로 얻는 것부터 가져간다.**

| # | 무엇 | 크기 | 얻는 것 | Rust |
|---|---|---|---|---|
| 0 | 확장자 표 여섯 벌 → 한 벌 · `await` 캡처 구멍 메우기 · `py/arithmetic` 오검출 | ~20줄 | 지금 있는 버그 셋. 축 셋의 전제 | 0 |
| 1 | **Tauri 기능 경로** (러스트) | ~60줄 | 간선 **392**, 리포 셋에 기능 챕터 | **0** |
| 2 | **CLI 진입점 씨앗** (파이썬) | ~24줄 | `adelie`·`ECC` 챕터 0 → 7 | 0 |
| 3 | **`fetch` + 파일 라우트** (JS) | ~25줄 | `bunhine_web` 진입점 0 → 11 | 0 |
| 4 | 언어 센서스 + 정직한 문구 | ~15줄 | 정본 §5 의 「내려앉음」을 참으로 | 10~15 |
| 5 | `rs/` 사전 3부 34장 | 큼 | 리포 둘이 열린다(덮음 78% → 94%) | 0 |
| 6 | `py/` 중심 16장 | 큼 | `adelie` 덮음 37.6% → 75.9% | 0 |
| 7 | `new-language.mjs` 골격 | 중간 | 다음 언어의 자리 29 → 11 | 0 |
| 8 | 러너 둘(node · cargo) · `react/` 아홉 · Astro | 큼 | 5단이 세 언어에서 판정된다 | 10~30 |

**0~3 이 Rust 0줄에 약 130줄이고, 그것만으로 사용자 리포 일곱 중 다섯에 기능 챕터가 선다.**
5~6 이 사전 저작이라 가장 크고, 그 앞의 넷은 저작 없이 배관만 고치는 일이다.

**먼저 갈리는 결정 하나** — 4번(언어 센서스)에 러스트 15줄을 쓰면 8번의 러너·Astro 가 예산
2,800 을 넘긴다. 예산을 열 것인가(D68·D129 가 두 번 연 선례), 아니면 정본 §5 의 「내려앉음」
문장을 사실에 맞게 고칠 것인가. **이 하나가 4·8 의 규모를 정한다.**
