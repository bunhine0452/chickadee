## §11 학습법 — 이 언어를 이해한다는 것

### §11.1 이 언어의 기계 — 한 문장과 그림 하나

> **대입은 언제나 복사다. 슬라이스·맵·채널은 복사돼도 같은 것을 만지는 손잡이이고,
> `go` 를 적은 줄 뒤로는 순서가 내 것이 아니다.**

두 층이다 — **복사와 손잡이**(값 층), **스케줄러**(시간 층). 초보가 Go 에서 틀리는 자리는 거의 전부
첫 층이고, 두 번째 층은 실코드에 드물다(§1 실측 — `go func` 이 `cli/cli` 429파일 중 **19파일 4.4%**).

**§9 오개념 열둘을 이 기계에 붙여 본다. 여섯이 붙고 여섯이 안 붙는다.**

| §9 의 어느 항목 | 기계의 어느 조각 |
|---|---|
| 4 `append` 뒤 원본 · 5 슬라이스 창 · 10 값 리시버 · 11 `defer` 인자 | **복사와 손잡이** — 넷 |
| 2 제로 값 · 8 nil 인터페이스 | **제로 값**(복사의 따름 — 「값 없는 이름」이 없다) — 둘 |
| 1 `:=` 재선언·가리기 · 12 반복 변수 | 스코프 규칙 — **기계가 아니다** |
| 3 조건 자리에 `bool` 만 · 9 인터페이스 암묵 만족 | 타입 규칙 — **기계가 아니다** |
| 6 맵 순회 순서 | 런타임이 **일부러** 흔든다 — 스케줄러가 아니다 |
| 7 `err` 을 안 봐도 컴파일이 안 멈춘다 | 규약 — 기계가 아니다 |

**여섯 / 열둘.** SQL 은 열둘 중 열둘이 기계 넷으로 설명됐는데(`sql-learning.md` §11.1) Go 는 절반이다.
남는 여섯은 **언어 설계**(스코프·타입·규약)이고 기계 모형으로는 안 잡힌다. 이것이 Go 편의 성질이다 —
「동작 원리부터」가 답하는 범위가 SQL 보다 좁고, 나머지 절반은 **명세 조항을 읽어 주는 것**이 답이다.
그리고 그 여섯이 §11.3 에서 T1 을 통과하는 자리들이다.

**그림.** `diagrams.md` 는 **메모리 줄**의 언어를 C·C++·Rust·Go 로 적어 두었고 모델이
`{ base, stride, slots: {addr, value, name?}[] }` 다. **슬라이스에는 한 칸 모자란다** — 슬라이스는 그 줄 위의
**창**(`ptr`·`len`·`cap`)이고, `append` 가 원본을 고치나 마나는 `cap` 경계가 정한다. 창 없이 그리면 §9 ④⑤ 를
못 그린다. **새 그림이 아니라 메모리 줄의 필드 하나**를 신청한다(§11.6).

**49번째로 동시성 뒤**, 우리는 §4 심화 25번째다. 넷이 다 다르다. 갈리는 이유가 보인다 — `defer` 는
**문법으로는 쉽고 의미로는 어렵다**. 「나중에 부른다」는 한 줄이고 「인자는 지금 계산된다」는 §9 ⑪ 이다.
앞에 두는 교재는 앞을 가르치고 뒤에 두는 교재는 뒤를 가르친다. **우리는 뒤쪽이고, §4 ㉕ 의 설명이
「인자는 지금 계산되어 저장된다」로 시작하니 자리가 맞다.**

넓게 적어 두었던 것이 전부 탈락하고, 좁힌 판이 통과한다.

#### §11.3.1 고루틴 비결정 — 새 형식이 아니라 `table` 의 배치다

코디네이터의 물음: 답이 **집합**이 되면 넷으로 안 되나.

**답의 모양이 바뀌는 것이 맞고, 그래서 T1 을 통과할 후보다** — 아홉 언어에서는 「이 줄 뒤 값은」에 답이
하나인데 Go 의 `go func` 뒤에는 답이 여럿이다. 값이 **달라지는** 것이 아니라 값의 **개수**가 달라진다.
`siblings` 는 「같은 식의 다른 언어 답」을 하나씩 나르는 구조라 이 차이를 못 나른다.

**그런데 뒤집으면 `table` 이다.** 「가능한 출력을 전부 적어라」는 답이 집합이라 채점이 어렵다. 물음을
뒤집어 **후보 출력 K개를 주고 칸마다 「가능 / 불가능」**을 채우게 하면 칸마다 답이 하나이고
`table` 채점기(칸 단위 값 일치 · 부분 점수)가 그대로 돈다. **그리고 뒤집은 쪽이 재려는 것에 더 가깝다** —
학습자가 아는 것은 「무엇이 나올 수 있나」가 아니라 **「무엇이 절대 안 나오나」**이고, 그 금지가 곧
명세의 `synchronized before` 관계다. `WaitGroup` 을 쓴 판에서 「고루틴 출력이 `done` 보다 뒤에 오는 것」은 불가능이다.

**`trace-table` 로는 안 된다 — 이유 한 줄.** `trace-table` 은 시간 축이 **하나**이고 앞 회차의 정답으로
뒤 회차를 채점하는 이월 채점이 그 위에 선다. 고루틴은 레인이 둘 이상이고 **레인 사이의 순서가 답**이라
「앞」이 정의되지 않는다. 이월 채점이 기준으로 삼을 것이 없다.

**그림 신청 — 「나란한 걸음」.** 레인마다 걸음 사다리 하나, 레인 사이에 채널 연산이 만드는 간선.
모델 스케치: `{ lanes: { name: string; steps: FoldStep[] }[]; edges: { from: [number,number]; to: [number,number]; kind: 'send' | 'recv' | 'wg' | 'mutex' }[] }`.

`diagrams.md` 가 「두 언어 나란히 비교 그림」을 **「배치이지 그림이 아니다 — 컴포넌트가 할 일이 없다」**로
거절했다. 이것은 다르다: **간선이 내용이고 간선은 코드에서 계산된다**(채널 연산의 짝). 원칙 ②
(데이터에 없는 것을 그리지 않는다)를 지킨다 — 사다리 둘을 격자에 넣는 것으로는 간선을 못 그린다.
Go 하나가 요구하지만 Rust(`.await`)·C#(`Task`)이 뒤에 같은 것을 요구할 것이라 아홉 중 하나짜리는 아니다.

#### §11.3.2 「컴파일 오류」가 답인 판 — 함정 하나

Go 는 답이 값이 아니라 **컴파일 정지**인 자리가 많다: `if n {`(§9 ③) · 슬라이스 `==`(0-8) ·
`var a int; var b int64; a + b`(0-1) · 선언만 하고 안 쓴 변수.

**형식은 이미 있다.** `packages/cards/src/fundamentals.ts:58` 의 `FundValue` 에 `{ t: 'event'; name; accept }`
변형이 실재하고 `EVENTS` 가 `undefined behavior`·`panic` 을 싣는다. `compile error` 를 한 줄 더하면 끝이다.

**함정**: Go·Swift 에서 「컴파일 오류」가 자주 정답이면 **모르면 그것을 찍는다.** 4지선다를 내린 이유
(소거법, 정본 §1)가 자유 텍스트에서 되살아난다. 대책 — 사건 답을 낸 뒤 한 걸음 더 묻는다:
**「무엇을 적으면 도나」**(`build` 또는 `order`). `int64(a) + b` 를 적어야 통과하므로 찍기가 안 통한다.
이것은 Go 특유가 아니라 **정적 타입 언어 공통**이고 Swift 편이 같은 것을 요구한다.

### §11.4 연구된 오개념과 그 진단

#### §11.4.1 연구가 없다

**Go 학습자의 오개념을 잰 실증 연구를 못 찾았다.** progmiscon.org 는 Python·Java·JavaScript·Scratch
넷뿐이고(swift.md §10 이 이미 잰 것과 같은 사실), Qian & Lehman 2017 의 문헌 검토도 명령형·객체지향
언어가 대상이다. go.md §9 의 열둘은 **연구 목록이 아니다** — 명세·FAQ·설문·실증 버그 연구에서 모은 것이고,
그 사실이 §9 머리에 이미 적혀 있다.

**2차로 쓰는 것 넷** — 아래를 근거로 쓰되 **1차 연구가 아니라고 표시**한다.

| 출처 | 종류 | 무엇을 받쳐 주나 |
|---|---|---|
| Go 언어 명세 · Go Memory Model | **1차 · 명세** | §9 ①②⑥⑩⑪⑫ — 조항이 그대로 답이다 |
| Go FAQ (`#nil_error` · `#inheritance`) | **1차 · 공식** | §9 ⑧⑨ |
| Go Developer Survey 2023 Q1 · 2024 H1 | **1차 · 설문** | §9 ⑦ — 「오류를 통째로 무시하기 쉽다」 응답 19% |
| Harsanyi, *100 Go Mistakes and How to Avoid Them* (100go.co) | **2차 · 실무서** | 100개 / 11장. 자료형 13 · 문자열 6 · 함수와 메서드 6 · **동시성 17**(기초 6 + 실전 11) · 제어 구조 6 |
| Tu 외, ASPLOS 2019 *Understanding Real-World Concurrency Bugs in Go* | **1차 · 실증** | 동시성 버그의 분포. 다만 **학습자가 아니라 프로덕션 코드**다 |

**`100 Go Mistakes` 의 분포가 §9 와 어긋난다.** 그쪽은 100개 중 **17개가 동시성**인데 우리 §9 열둘 중
동시성은 0이다(⑥ 맵 순회는 런타임이지 동시성이 아니다). 어긋남의 이유는 대상이 다르기 때문이다 —
그 책은 **실무 Go 개발자**를 겨냥하고 §9 는 **바이브 코딩으로 나온 코드를 읽는 사람**을 겨냥한다.
§1 실측(`go func` 이 파일의 4.4%)이 후자 쪽 근거이고, **§9 를 동시성으로 채우지 않은 것이 맞다.**
`100 Go Mistakes` 에서 가져올 것은 자료형 13개 쪽이고 그것은 이미 §9 ④⑤ 에 있다.

#### §11.4.2 어떤 오답이 나오면 어느 오개념인가

`fundamentals.md` §5 의 계산된 진단이 Go 에서 **얼마나 잡히나** — 오개념마다 대표 오답을 적고 분류를 붙인다.

| §9 # | 물음 | 대표 오답 | `fundamentals.md` 분류로 잡히나 |
|---|---|---|---|
| 0-1 정수 폭 | `int8(127) + 1` | `128` | ✓ `other-language`(파이썬은 무한 정수라 128 이다) |
| 0-5 우선순위 | `1 << 2 + 3` | `32` | ✓ `other-language`(C·자바·C# 이 32) |
| 0-3 바이트와 rune | `len("가나다")` | `3` | ✓ `other-language`(파이썬·Swift·C# 이 3) |
| 0-6 암묵 변환 없음 | `var n int = 1; var f float64 = n` | `1` | ✕ — **`compile error` 라는 답이 필요하다**(§11.3.2) |
| ③ 조건 자리 | `if n {` 뒤 무엇 | 「참이면 돈다」 | ✕ — 같은 이유 |
| ④ `append` | `append(xs,9)` 뒤 `len(xs)` | `3` | ✕ — **`variants` 가 필요하다**(아래) |
| ⑤ 슬라이스 창 | `s := xs[1:3]; s[0]=9` 뒤 `xs[1]` | 원래 값 | ✕ — 같은 이유 |
| ⑪ `defer` 인자 | `i:=0; defer p(i); i=9` 뒤 출력 | `9` | ✕ — **`9` 는 Swift 의 답이다**(§11.4.3) |

**여덟 중 셋만 `siblings` 로 잡힌다.** 나머지 다섯 중 둘은 `event` 값 하나로 풀리고(§11.3.2),
**셋은 `variants` — 같은 코드의 한 글자 다른 판 — 을 요구한다**: `cap` 이 다른 판, 창을 안 잡은 판,
`defer func(){}()` 로 감싼 판. SQL 이 같은 결론에 닿았고(`sql-learning.md` §11.4.2) 거기서는 러너가 있어
계산되는데 **Go 에는 러너가 없으므로 그 세 값을 손으로 카탈로그에 적어야 한다.** 카탈로그 부채가 셋이다.

#### §11.4.3 Go 의 `defer` 와 Swift 의 `defer` — 판정 기준이 도는 것을 보인다

같은 낱말이고 답이 다르다. Go 는 `defer p(i)` 의 `i` 를 **그 줄에서 계산해 저장**하므로 `0` 이고,
Swift 는 `defer { print(i) }` 가 **블록이라 캡처**하므로 `9` 다(이 세션에서 `swift` 6.3.3 으로 실행해
`5-defer 9` 를 받았다 — `swift-learning.md` §11.7).

**넓게 적으면 둘 다 탈락한다** — 「`defer` 뒤 무엇이 찍히나」는 두 언어에 다 서고 답만 다르다.
**좁히면 둘 다 통과한다** — Go 의 「인자가 언제 계산되나」는 Swift 에 물음이 없고(인자를 안 받는다),
Swift 의 「블록이 무엇을 캡처하나」는 Go 에 물음이 없다(`defer func(){…}()` 로 감싸야 비로소 생긴다).
같은 쌍이 양쪽에서 판정 기준을 통과하는 것이 `pedagogy.md` §4 규칙이 실제로 도는 증거다.

### §11.5 우리 앱에서 그 학습법이 서는 자리

#### §11.5.1 다섯 단

| 단 | Go 에서 | 근거 |
|---|---|---|
| 1 읽기 | 선다. 문법이 오늘 붙어 있고(`lang-go` 기본 켜짐, abi 14) 캡처가 난다 | go.md §0.7 |
| 2 추적 | **경로는 선다** — `resolveGo`·`goLeadFiles` 가 이미 배선돼 있다. `pedagogy.md` §1.2 가 지적한 「값을 굴리는 추적이 없다」는 **`trace-table` 로 채운다** — `:=` 가리기(§11.3 마지막 줄)와 `defer` 스택이 그 재료다 | `resolve-imports.ts:269` |
| 3 예측 | 선다. §11.3 의 통과 다섯이 전부 3단 재료다 | — |
| 4 수정 | **AST 제약까지만.** 러너가 없다 — `which go` → not found | D175 규칙 ① |
| 5 재구현 | 같음. 게이트 밖 | 같음 |

**Go 의 2단은 SQL 과 정반대다.** SQL 은 경로가 없어서 값을 굴릴 수밖에 없었고, Go 는 경로가 있어서
값 굴리기를 안 해도 2단이 서 버린다 — 그래서 `pedagogy.md` §1.2 의 빈자리가 **Go 에서는 조용히 남는다.**
`trace-table` 을 여는 것이 그 자리를 채우는 일이고, Go 에서 그 재료가 가장 날카롭다(`:=` 재선언 규칙은
아홉 언어에 대응이 없다).

#### §11.5.2 「내 코드가 교재」 — Go 는 성립하지 않는다

사용자 리포에 `.go` 가 **0개**다(README §10 실측). §1 의 밀도 수치는 `cli/cli`(87,875줄)와
`lazygit`(115,321줄) — **남의 리포**다. 정본 §1 의 「내가 만든 코드가 교재」는 사용자가 Go 리포를
가져올 때 비로소 선다.

**그때까지 서는 것과 안 서는 것.** 0부 8 + 1부 5 는 합성 예제로 온전히 서고, 2부 20 의 **「네 리포의 여기가
그것이다」가 통째로 빈다.** D177 규칙 ①(개념마다 내 코드의 자리를 짚는다)이 못 지켜지므로 **D158 경로**
— 「네 코드엔 없다」를 명시하는 `makeAbsentCard` 의 `AbsenceReason` 을 써야 한다. 그런데 go.md §0.7 이
그 함정을 이미 적었다: `AbsenceReason` 은 `framework`·`library`·`scale`·`idiom` 넷이고 **「우리가 못 읽는다」와
「네 코드에 없다」가 섞인다**(D137 이 막으려던 자리). Go 는 「못 읽는다」가 아니라 **「리포 자체가 없다」**라
다섯째 사유가 필요하다.

#### §11.5.3 3부가 0판이다 — 앞보다 뒤가 문제다

go.md §0.5 가 이미 쟀다 — 3부 네임스페이스 후보가 없고(`net/http`·chi·gin 중 무엇을 덮을지 미정),
정본 §5 의 티어 B 에 Go 가 한 줄도 없다. 그러면 코스가 2부 끝에서 **곧장 기능 챕터로** 넘어가는데,
기능 챕터는 HTTP 간선과 기능 폐포 탐지가 있어야 서고 Go 에는 그 규칙이 없다.

**즉 Go 코스는 33판 17일을 걷고 나서 갈 데가 없다.** 학습법 쪽 판단으로는 **이것이 Go 편의 가장 큰
구멍**이고 0장 상한이나 형식 논의보다 크다.

#### §11.5.4 0장 상한 폐지(D184)의 결과 — Go 쪽 판단

**Go 는 아무것도 안 바뀐다.** 0부 이전 22, 0부 이후 **24 / 24** 로 상한에 정확히 붙되 넘긴 적이 없다
(go.md §0.5 — Swift 25→29 · C# 24→26 만 넘쳤다). 폐지로 잘릴 뻔한 판이 0개다.

**학습법 쪽 문제인가 — 아니다.** 프롤로그가 24판 12일로 고정되고, 그 24판에 0부 여덟이 든다는 것이
D184 의 실질이다. §11.1 이 센 대로 §9 열둘 중 여섯이 그 여덟으로 설명되므로 앞에 오는 것이 맞다.
`pedagogy.md` §5 가 「15~17일이 동기 연구와 충돌하는지는 직접 근거로 판정 불가」라고 닫았고,
Go 는 17일(0부 4 + 1부 3 + 2부 10)로 그 범위 안이다.

**남는 위험은 하나** — `pedagogy.md` §5 의 권고(상한 대신 「내 코드를 짚는 판」의 비율 게이트)를 Go 에
걸면 **분자가 0이다.** 리포에 `.go` 가 없으므로 어떤 문턱을 두어도 Go 는 못 넘는다. 성질 게이트를 만들면
**Go 를 예외로 둘 규칙이 함께 필요하다.**
