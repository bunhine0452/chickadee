## §11 학습법 — 이 언어를 이해한다는 것

> 2026-09-05 추가. **C 의 기계 위에 얹는다** — [`c-learning.md`](./c-learning.md) §11.1 이 기계
> 둘(자리 · 약속)을 세웠다. 판정 기준은 `docs/program/pedagogy.md` §4(T1 이식 · T2 조항 ·
> T3 사전). **셋 중 근거가 가장 센 절이다** — Crichton 외 OOPSLA 2023 이 오개념을 실측하고
> 교재를 고쳐 효과를 쟀고, Zhu 외 ICSE 2022 가 101명 조사로 같은 자리를 독립적으로 가리킨다.

### §11.1 이 언어의 기계 — 「주인 하나」로는 안 된다

**후보 ⓐ 「값마다 주인이 하나다.」 — 틀린 모형이다.** §9 의 「이동한 값은 메모리에서 사라진다」를
못 막는다. 주인이 옮겨 간다고만 말하면 값이 따라간다고 읽힌다.

**후보 ⓑ — 이것을 쓴다.** 값마다 주인이 하나이고, **이름은 그 값에 대한 권한을 든다 —
읽기(R) · 쓰기(W) · 소유(O). 빌리면 권한이 빌린 쪽으로 옮겨 가고, 빌림이 끝나면 돌아온다.**

ⓑ 가 Crichton 외의 모델이다. 그들은 이것을 「메모리로 들어가는 **경로**에 붙는 흐름 민감 권한」
이라 부르고, 컴파일러 플러그인(Aquascope)으로 그림을 만들어 The Book 4장을 통째로 갈아 끼웠다.

**§9 의 오개념 12 중 이 문장이 덮는 것.**

| 오개념 | 권한 모형이 설명하나 |
|---|---|
| 이동한 값은 사라진다 | ○ — 값은 그대로 있고 **O 권한만** 옮겨 간다 |
| `&` 는 C 의 주소 연산자다 | ○ — 빌림은 주소 얻기가 아니라 권한 이전이다 |
| `mut` 은 「이 값이 변한다」 | ○ — W 는 **이름**에 붙는다 |
| 빌림 검사기가 막는 건 스타일이다 | ○ — 권한 없이 쓰면 나는 UB 를 막는다 |
| `.clone()` 을 붙이면 해결된다 | △ — 권한이 왜 회복되는지는 말하고 **의도가 왜 깨지는지**는 안 말한다 |
| **`'a` 를 적으면 값이 더 오래 산다** | **✗ — 수명은 권한 모형에 없다** |
| `Rc<RefCell<T>>` 로 규칙을 벗어난다 | ✗ — 규칙이 실행 시로 옮겨간 것 |
| `unsafe` 는 검사를 끈다 | ✗ |
| 세미콜론 · 숫자 조건 · `String`/`&str` · 이터레이터 게으름 | ✗ — 0부와 다른 층 |

**12 중 넷 반.** 권한 모형은 소유권 오개념의 절반쯤을 덮고 **가장 큰 구멍이 수명**이다. 그리고
두 연구가 독립적으로 같은 자리를 잰다.

| 연구 | 표본 | 수명 자리 | 나머지 |
|---|---|---|---|
| Crichton 외 형성 평가 | **N = 36** · StackOverflow 프로그램 8개 · 네 범주 | **lifetime parameters Q1 10~38%** | dangling pointer 77% · overlapping borrows 60~85% · illegal borrow promotion 80~88% |
| Zhu 외 온라인 조사 | **Rust 프로그래머 101명** | 「수명 규칙 위반의 컴파일러 오류를 **항상** 이해했다」 **10.0%** | 소유권 규칙 위반은 **39.6%**(유의하게 갈린다) |

**그림 — Brown 의 permissions 는 우리 「소유권 화살표」 명세와 다르다.**

| | Brown / Aquascope | `diagrams.md` §3 명세 5 |
|---|---|---|
| 무엇에 붙나 | **place** — 대입 왼쪽에 올 수 있는 것 전부(`x` · `*y` · `v[0]` · `s.f`) | **owner**(이름) |
| 무엇을 그리나 | 권한 셋 R/W/O 의 **줄마다 상태** | 화살표 — 누가 무엇을 들고 누가 빌렸나 |
| 시간 축 | 코드 줄 옆, 흐름 민감 | `steps[]` 스냅숏 |
| 표기 | 획득 `+` · 상실 `/` · **채운 글자** = 있음 · **빈 글자** = 기대했는데 없음 · `‒` = 없음 · `•` = 무관 | 없다 — 방향뿐 |
| 값은 어디 | **별도의 런타임 그림**(스택·힙 상자)으로 나눈다 | 같은 그림에 섞인다 |

**다르고, 우리 쪽이 실측으로 골라진 모형이 아니다.** Brown 은 새 4장 이후 Ownership Inventory
점수가 **48% → 57%**(N = 342 · p < 0.001 · d = 0.56)로 올랐고, 요약 평가 문항 중 **그림 읽기가
83~93% 로 가장 높았다**(UB·역참조 같은 추상 추론은 44~47%). 그림이 실제로 옮긴 것은 그림이
그리는 것이다. **신청: 「소유권 화살표」를 「권한 줄」로 바꾼다**(§11.6 에 모델).

**베끼지 않는다.** 표기(`+`·`/`·채운 글자)는 아이디어이지 지문이 아니므로 우리 규약으로 다시
만든다. `diagrams.md` 원칙 3(색은 뜻에만)과는 안 부딪힌다 — R/W/O 가 이미 글자라 색이 필요 없다.

### §11.2 최고의 교재가 수렴한 순서

| 교재 | 값·타입 | 흐름 | **소유권** | 수명 |
|---|---|---|---|---|
| The Rust Programming Language | 3장 Common Programming Concepts | 3.5 | **4장** | 10.3 |
| **Brown 실험판**(rust-book.cs.brown.edu) | 3장 — **안 건드렸다** | 3.5 | **4장 — 통째로 새로 씀**(3절 18소절) | 10.3 |
| Rustlings | 01 variables · 04 primitive_types | 03 if | **06 move_semantics** | **16 lifetimes** |
| Programming Rust 2판 | 3장 Fundamental Types | — | 4장 Ownership and Moves · 5장 References | 5장 |

**넷 다 소유권 앞에 「값과 식」을 둔다.** C·C++ 의 다섯이 2장을 타입에 준 것과 같은 자리다
(`c-learning.md` §11.2 · `cpp-learning.md`.2).

**The Book 3장이 우리 0부와 같은가 — 아니다. 우리 쪽이 셋 더 깊다.**

| §0.1 개념 | The Book 3장이 다루나 |
|---|---|
| `let-binding` · `mut-binding` · `boolean-literal` · `comparison` · `arithmetic` | ○ 3.1 · 3.2 · 3.5 |
| `integer-type` | ○ 3.2 — 폭·부호 표가 있다 |
| `overflow` | ○ 3.2 — 「디버그 모드에서는 패닉, `--release` 에서는 2의 보수 감싸기」를 명시한다 |
| `float-type` | 부분 — f32/f64 두 줄. **`PartialOrd`·NaN 이 없다** |
| `char-and-byte` | 부분 — 3.2 에 `char` 4바이트 한 줄, `s.len()` 은 8.2 |
| **`cast-as`** | **✗ — `as` 가 3장에 안 나온다** |
| **`operator-precedence`** | **✗ — 부록 B 의 연산자 표뿐이다** |

**열하나 중 여덟이 3장에 있고 셋이 없다.** 그리고 **없는 셋이 우리 실측이 가장 크게 잡은
자리다** — `as` 563곳 대 `try_into`/`TryFrom` 12곳으로 **47배**(§0.7), 그리고 `x as u8 + 1` 의
결합(§0.1 #10). **The Book 3장의 구멍이 정확히 AI 가 짠 코드가 가장 자주 쓰는 자리**이고,
그것이 우리 0부가 3장의 복제가 아니라는 근거다.

**Brown 실험판이 우리 순서에 미치는 것 — 셋.**

**① 소유권을 2부에 두는 것은 안 건드려도 된다.** Brown 은 3장을 그대로 두고 **4장만** 갈아
끼워 9%p 를 얻었다. 문제는 순서가 아니라 **4장의 내용**이었다는 뜻이고, §0.6 의 사슬
(0부 값과 식 → 1부 문과 흐름 → 2부 소유권)은 The Book 과 같은 자리다. **순서 변경 없음.**

**② 소유권 판의 첫 장이 「정의되지 않은 동작」이어야 한다.** Brown 4.1 의 첫 소절이 UB 다 —
「왜 이 프로그램이 거부되나」의 답이 「거부 안 하면 무슨 일이 나나」이기 때문이다. §0.3 은
「Rust 에서는 `rs/unsafe-block` 밖에 UB 가 안 나온다」고 적었고 **참이지만 교육적으로
뒤집힌다**: UB 를 안 보여 주면 빌림 검사기가 스타일 규칙으로 보이고, 그것이 §9 의 첫 행이다.
**신청: `rs/move`(2부의 첫 소유권 개념)의 선행에 `cs/undefined-behavior` 를 건다.** 그 장은
`cs.md` 에 이미 있다(심화 · 깊이 4 · 선행 `memory-address` · 사용 언어 열에 `rs/unsafe` 가 적혀
있다). **0부가 아니라 2부의 선행이다** — 0부에 걸면 깊이 4 짜리가 프롤로그로 끌려 올라온다.
C 의 UB 와 층이 다르다: C 는 「내 코드가 UB 를 낸다」, Rust 는 **「컴파일러가 막은 것이
무엇이었나」**다. 같은 `cs/` 장을 두 언어가 반대 방향에서 쓴다.

**③ 문항이 「거부되나」에 치우치면 안 된다.** Crichton Table 1 — Q1(거부 예측) **64%** ·
Q2a(반례 만들기) **31%** · Q2b(반례 정당화) **15%**. §9 가 이미 인용했고 여기 새로 붙는 것은
Brown 요약 평가의 **그림 읽기 83~93% 대 추상 추론 44~47%** 다. **그림을 붙여도 추상 추론은
안 따라온다.** 「`meaning:`·`why_gate:` 를 ‘그럼 어떻게 되나’ 쪽으로 기울인다」는 §9 의 결론이
이 수치로 더 세진다.

### §11.3 이 언어에 특유한 연습 형태

| 후보 | T1 | T2 | T3 | 판정 | 형식 |
|---|---|---|---|---|---|
| ① 「컴파일러 오류를 읽고 고치기」(넓게) | ✕ | ✕ | — | **탈락 — 일반론**(Becker 외 2019) | — |
| ①′ **`E0502` 판정**(같은 값을 가변·불변으로 동시에 빌림) | ○ | ○ | ○ | **통과** — `pedagogy.md` §4 가 이미 그렇게 판정했다 | `table` + 4지(아래) |
| ② 빌림 검사 예측 「이 줄이 컴파일되나」 | 부분 | 갈린다 | ○ | **오류 코드를 적으면 통과, 「컴파일되나」로 적으면 탈락** | `table` 두 칸 |
| ③ 수명 표기 채우기 | ○ | ○ | ○ | **T 셋은 통과하는데 형식이 위험하다** | `cut` 으로 바꾼다 |
| ④ 「지금 이 이름은 무슨 권한을 갖나」 | ○ | ○ | ○ | **통과 · 새 제안** | `trace-table`(열 = **place**) |
| ⑤ 디버그·릴리스 넘침 예측 | ○ | ○ | ○ | 통과 — §0.3 이 이미 잡았다 | `value` |

**①′ 이 왜 통과하나 — 다른 아홉에서 물음이 성립하지 않는 이유가 의미론에 있다.** Rust 의
거부는 **두 종류**다: ⓐ 내 프로그램이 실제로 안전하지 않다 ⓑ **안전한데 검사기가 정밀도를
잃었다.** Brown 4.3 이 그 물음을 첫 문장으로 세운다 — 「소유권 오류를 고칠 때 스스로에게 물어야
한다: 내 프로그램이 실제로 안전하지 않은가?」 여섯 사례 중 둘(필드 단위 빌림 · 배열 원소 빌림)이
ⓑ다. **빌림 검사기가 보수적이라는 것이 언어 정의의 일부**라서 ⓑ 갈래가 있고, 타입 오류가
「내가 틀렸다」 하나뿐인 언어에는 그 갈래가 없다. C 컴파일러는 반대로 **안전하지 않은 프로그램을
통과시킨다**(`c-learning.md` §11.1 의 기계 ②).

**② 를 `value` 의 `bool` 하나로 내면 안 된다.** 이유 둘. ⓐ Crichton Q1 이 **64%** 다 —
「되나 안 되나」만 물으면 이미 절반 넘게 맞히는 것을 또 묻고, 못 하는 것(Q2a 31%)은 안 묻는다.
ⓑ `bool` 한 칸은 **동전 던지기로 50%** 다. `fundamentals.md` 가 4지선다를 내린 이유(소거법)가
두 칸짜리에서 더 세게 걸린다.

**권고 — `table` 두 칸.** ① 컴파일되나 ② **어느 줄이 문제인가**. 둘째 칸이 Zhu 외의 「규칙을
어긴 토큰 표시」 과제와 같은 것이고 **그 과제의 평균 점수가 0.39~0.75 로 바닥도 천장도 아니라
변별이 난다**(101명). `table` 은 칸마다 부분 점수가 있다(`fundamentals.md` §4). 세 칸째(이유)는
자유 텍스트라 채점이 안 된다 — 그것은 **왜 게이트**이고 앱이 이미 그 자리를 갖고 있다
(`exercises.md` §1: 「채점 없이 자기 말만 받는다. 그것이 목적이다」).

**「이 줄이 컴파일되나 + 이유」가 `order`·`trace-table` 로 되나 — 안 된다.** `order` 는 답이
순열이라 자리가 아니고, `trace-table` 은 「시간 × 무엇」의 격자라 **한 줄에 대한 판정 둘**을 담는
모양이 아니다. 그 둘은 기존 **`table`**(식 × 물음)이 이미 맞다 — 행이 스니펫, 열이
(컴파일되나 · 어느 줄 · 어느 오류 코드)다. **새 형식이 필요 없다.**

**③ 은 T 셋을 통과하는데 형식이 위험하다.** 수명은 근거가 가장 센 자리인데(§11.1 의 두 연구)
Crichton 형성 평가에서 **수명 인자가 빠진 함수의 반례를 만든 사람이 0명**이었다. 「빈 `'_` 를
채워라」를 시키면 학습자는 **생략 규칙 셋을 외워서 맞힌다** — 이해 없이 통과하고, 정본 §1 의
「읽기는 인식이지 지식이 아니다」가 그대로 걸린다. **권고: 채우기 대신 「이 표기를 지우면 무엇이
깨지나」** — 3단 `cut` 유형이 이미 그 모양이고, 오답 「안 깨진다」를 고르면 실제로 거부되는
**호출부**를 보여 준다. 채점은 파일·줄 선택이라 결정론이다.

**④ 는 새 제안이고 Brown 의 그림을 문항으로 뒤집은 것이다.** 그림이 권한을 **보여 주면**
83~93% 가 읽는다. 같은 격자를 **비워 두고 채우게** 하면 그것이 강제된 능동 출력이다(정본 §1).
형식은 `trace-table` 인데 **열이 「변수」가 아니라 「place」**여야 한다 — `x` 와 `*x` 와 `v[0]` 이
서로 다른 권한을 갖는 것이 이 언어의 요점이라 열이 변수면 그 구분이 격자에서 사라진다.
C 가 「시간 × 주소」, C++ 이 「시간 × 객체」로 낸 신청과 **같은 확장의 셋째 축**이고, 여기서는
**칸도 값이 아니다** — R/W/O 세 글자다. `trace-table` 의 칸 타입을 `FundValue` 로 고정하면
셋 중 둘이 못 선다.

**「고치기」를 4단에 그대로 두면 거짓 어긋남이 난다.** 빌림 오류는 고침이 여럿이다 —
`.clone()` · 수명 줄이기 · 소유 넘기기 · 구조 바꾸기. `exercises.md` §3 이 「4단은 편집 범위를
좁혀 답의 폭을 줄인다」고 정했는데 **Rust 에서는 한 줄로 안 되는 오류가 많다.** 권고:
「고쳐라」가 아니라 **「어느 고침이 의도를 지키나」** — 넷을 주고 오답 하나가 **「컴파일은 되는데
뜻이 바뀐다」**(= `.clone()`)다. Crichton 형성 평가에서 16명 중 2명이 정확히 그 오답을 냈다
(겹치는 빌림을 입력 벡터 복제로 「해결」). **4지선다이지만 소거법이 안 통한다 — 넷 다
컴파일되기 때문이다.**

**「컴파일러 오류를 그대로 보여 주면 된다」는 실측으로 반박된다.** Zhu 외 RQ-3: **강화된 오류
메시지를 본 참가자가 원본 메시지를 본 참가자보다 「규칙이 어떻게 위반됐는지 설명하기」에서
유의하게 잘했다**(프로그램 PC-1). §9 의 「오류 코드를 그대로 적는 것이 다른 언어에 없는
자산」은 유지되되, **코드만 적고 메시지를 그대로 흘리는 것으로는 부족하다** — 카드가 그 위에
「무엇이 무엇을 빌렸나」를 얹어야 하고 그것이 ④의 격자다.

### §11.4 연구된 오개념과 그 진단

**§9 에 더할 행 둘.** 둘 다 Crichton 외 OOPSLA 2023 의 실측이다 — 이 세 문서에서 **1차 실측
근거가 붙는 유일한 오개념**이다.

| # | 무엇을 믿나 | 실제로는 | 근거 |
|---|---|---|---|
| 13 | 거부된 프로그램은 실행하면 반드시 터진다 | 거부는 **증명 실패**다. 실제로 안전한데 검사기가 정밀도를 잃어 거부하는 경우가 있다(Brown 4.3 여섯 사례 중 둘) | 「학습자가 컴파일러의 수용을 실제 안전성과 혼동한다」 |
| 14 | `unsafe` 함수를 **부르는 줄**이 위험한 줄이다 | 매달린 포인터를 돌려주는 함수를 부르기만 하고 **값을 안 쓰면 아무 일도 안 난다.** UB 는 쓰는 자리에서 난다 | 참가자 다수가 그렇게 믿었다 |

**진단 — 어떤 오답이 나오면 이 오개념인가.**

| 오개념 | 문항 | 그 오답 | 잡히나 |
|---|---|---|---|
| 13 거부 = 반드시 터진다 | ②의 두 칸 | ① 「컴파일 안 됨」 **정답** + ② 줄 번호 **정답** | **정답을 맞히면서 성립하는 오개념이다.** 두 칸으로는 안 잡히고 **반례 문항**(Q2a)이 있어야 잡힌다 |
| `.clone()` 이면 해결 | 「어느 고침이 의도를 지키나」 | `.clone()` 갈래 | **잡힌다** — 그 갈래가 곧 진단이다 |
| 이동한 값은 사라진다 | ④의 격자 | 이동 뒤 원래 place 의 R 을 「없음」이 아니라 **빈 글자**로 | 잡힌다 — 「값은 있고 권한이 없다」가 격자의 두 표기로 갈린다 |
| `'a` 를 적으면 더 산다 | ③의 `cut` | 「안 깨진다」 | 잡힌다 |

**`fundamentals.md` §5 의 아홉 분류는 Rust 소유권에 안 닿는다** — 아홉이 전부 **값 오답**의
분류인데 여기 오답은 값이 아니다(권한 · 줄 번호 · 고침의 선택). C·C++ 이 낸 넷
(`ub-as-value`·`promotion`·`off-by-one`·`count-off`)도 마찬가지다. **`rs` 전용 오답 카탈로그가
필요하다** — 오류 코드 여섯(E0382·E0499·E0502·E0505·E0596·E0597) × 대표 오답 넷. 사전이 아니라
카탈로그인 이유는 `fundamentals.md` §8 의 규칙 그대로다: 개념마다 다르지 않고 **오류 코드마다**
다르다.

**0부 쪽은 반대로 잘 잡힌다.** `1i32 + 1i64`(E0308) · `if 1`(E0308) · `300u32 as u8`(44) 셋은
전부 값 오답이라 `siblings` 가 그대로 돈다 — 「그 답은 C 의 규칙이다」가 사람 저작 없이 나온다.
**§0 은 기존 기계로 서고 소유권만 새 카탈로그가 든다.**

### §11.5 우리 앱에서 그 학습법이 서는 자리

**셋 중 재료가 있는 유일한 언어다.** `rust-axis.md` 가 리포 넷(`ai-pm` 280장 · `file_converter`
45 · `PySpace` 8 · `ECC` 16)을 실측했고 §0.7 이 폭 붙은 타입 이름 2,885곳 · `as` 563곳을 셌다.

| 단 | 무엇을 묻나 | 재료 | 상태 |
|---|---|---|---|
| 1 읽기 | 짚기 · 값 적기 | 사전 + 리포 사용처 | **선다 — 열 언어 중 실측이 가장 두껍다** |
| 2 추적 | 「먼저 도는 줄」 | `exec-facts` | 선다. **권한 추적은 없다** — 아래 |
| 3 예측 | 「이 줄을 지우면」 | 가드 카탈로그 | **Rust 항목 0개.** 후보 셋 — `?` 뒤의 `Err` 갈래 · `if let Some` · `.ok_or()` |
| 4 수정 | `fix:` 커밋 | 커밋 원장 | **안 쟀다** — 이 리포에 빌림 오류 수정 커밋이 몇 개인지 안 셌다 |
| 5 재구현 | 스펙 카드 | 원본 블록 | 선다. `mustHold` 에 **`&mut` 시그니처**가 들어가야 한다 |

**2단의 빈자리가 Rust 에서는 「권한 추적」이다.** `pedagogy.md` §1.2 가 「연구의 tracing 은 값과
상태를 손으로 굴리는 것인데 앱의 2단은 경로 추적이고 값을 굴리는 것이 하나도 없다」고 적었다.
셋이 그 구멍을 서로 다른 이름으로 메운다 — **C 는 주소와 칸, C++ 은 객체의 생사, Rust 는
place 의 권한.** 셋 다 「값과 상태의 추적」이고 셋 다 지금 2단에 없다. **`trace-table` 의 열이
「변수」로 고정되면 셋 다 못 선다.** Rust 는 칸까지 값이 아니다.

**소유권에는 노드가 없다**(§8 ③). `rs/move` 는 사용처 0 이고 D154 합성 경로로 간다. 그래서
**0부·1부는 리포에서 카드가 구워지고 소유권은 합성**이다 — 「내 코드가 교재」가 Rust 안에서
절반만 참이다. 정직하게 적으면 §11.3 의 ①′·②·④ 는 전부 합성 재료를 쓴다. 다만 C·C++ 과
결정적으로 다른 것 하나 — **그 합성 판이 예고할 사용처가 리포에 있다.** `as` 563곳이 `cast-as`
판의 「네 코드의 여기가 그것이다」를 채우고, `.clone()` 47곳 + `Arc`/`Mutex` 10곳이 소유권 판의
`alternatives`(「AI 가 대신 쓴 것」)를 채운다. D158 의 「네 코드엔 없다」가 Rust 에서는 예외다.

**0장 상한 폐지(D184)의 결과 — Rust 에서.** **셋 중 값이 가장 크다.** §5 가 22/24 였으니
0부가 28 로 밀면 넷을 잘라야 했고, 넷째 정렬 키는 **id 알파벳순**이다. `rs/cast-as` 는 `c` 로
시작해 살아남았을 것이고 `rs/overflow` 는 `o` 라 위태로웠다 — **어느 개념이 프롤로그에 드는지를
이름의 첫 글자가 정하는 상태**였다. 실측이 `as` 를 47배 편차로 지목한 언어에서 그것이 운에
걸려 있었다는 뜻이다. 상한이 없으면 `essential` ∧ 깊이 ≤ 2 가 전부 들어가 28판 = 14일이고,
**그 14일은 The Book·Rustlings 의 앞부분과 어긋나지 않는다** — Rustlings 는 소유권(06) 앞에
다섯 묶음을 두고 The Book 3장도 하루에 안 끝난다. **판단: Rust 에서 문제가 아니다.**

**권한 줄 모델 스케치.**

```ts
{ steps: { code: string;
           places: { path: string;              // "x" · "*y" · "v[0]" · "s.f"
                     r: PermState; w: PermState; o: PermState }[];
           expects?: { path: string; needs: ('r' | 'w' | 'o')[] }[] }[] }
// PermState = 'has' | 'gained' | 'lost' | 'missing' | 'none'
```

`places` 가 이름이 아니라 **경로**인 것이 지금 명세와의 유일한 구조 차이이고, 나머지(`gained`·
`lost`)는 `ValueCell.changed` 가 이미 하는 일의 확장이다. `expects` 는 「이 연산이 무슨 권한을
요구하나」이고 `predict` 단계에서 **가려지지 않는다** — 물음이 무엇인지는 보여야 한다
(`diagrams.md` §4 의 「구조는 남고 값이 사라진다」 규칙 그대로).
