## §11 학습법 — 이 언어를 이해한다는 것

> 둘(자리 · 약속)을 세웠고 이 절은 **C++ 이 그 위에 더한 것만** 적는다. 판정 기준은

### §11.1 같은 기계 + 무엇이 더해졌나

**한 문장.** 같은 바이트 위에서 **값이 자기 자원을 스스로 책임진다** — 만들어질 때 잡고 범위를
벗어날 때 놓는다. 이름 하나가 곧 그 값이고, 대입은 통째 복사이며, **그 복사에 사용자 코드가 낀다.**

| 축 | C 에서 세운 것 | C++ 이 더한 것 | 그림 |
|---|---|---|---|
| 자리 | 주소가 붙은 바이트 | **같다** | 메모리 줄 |
| 이름 | 바이트를 읽는 방법 | **참조** — 두 번째 이름. 부르는 쪽 `f(v)` 에는 표시가 없다 | 값 상자 |
| 수명 | 프레임이 걷히면 사라진다 | **걷힐 때 코드가 돈다**(소멸자), 그것도 **역순으로** | 스택 프레임 |
| 복사 | struct 대입은 통째 복사 | 그 복사에 **사용자 코드가 낀다**(복사 생성자) | 스택 프레임 |
| 이동 | 없다 | `std::move` 는 **아무것도 안 옮긴다** — 표를 붙일 뿐 | 값 상자 |
| **약속** | 규격 밖은 UB | **그대로 물려받는다.** §0.2 가 「C++20 이 표현을 2의 보수로 고정했지만 넘침은 여전히 UB」라고 이미 적었다 | 없음 |

**§9 의 오개념 12개를 이 문장의 조각으로 나눈다.**

| 조각 | 오개념 | 수 |
|---|---|---|
| **수명** — 벗어나면 코드가 돈다 | 4(`delete p` 가 `p` 를 지운다) · 5(안 쓰면 아무 일도 없다 → 얕은 복사) · 6(virtual 없는 소멸자) | 3 |
| **값 의미론** — 이름 하나가 곧 값 | 2(값 전달은 통째 복사) · 7(슬라이싱) · 11(`v2 = v1` 뒤 `v1`) · 12(`auto` 가 참조·`const` 를 떨어뜨린다) | 4 |
| **참조** — 두 번째 이름 | 3(`&` 의 두 뜻) | 1 |
| **이동** — 표시일 뿐 | 1(`std::move` 가 옮긴다) | 1 |
| **C 의 기계가 이미 설명** | 8(`7 / 2`) · 9(`if (x = 5)`) · 10(`int x;`) | 3 |

**12 중 아홉이 C++ 고유 조각 넷에서 나고 셋은 C 에서 이미 섰다.** 이것이 「같은 기계 + 델타」의
수치다. C 쪽 셈(기계 ① 여섯 · 기계 ② 둘 · 규칙표 넷)과 나란히 놓으면 두 언어의 어려움이 어디로
갈리는지 보인다 — **C 는 자리, C++ 은 수명과 복사**다.

**그림 — 스택 프레임에 칸이 하나 모자란다.** `diagrams.md` §3 이 「C++ 2부 열둘 중 다섯이 스택
프레임을 쓴다」고 이미 적었다. 그런데 지금 모델 `{ frames: { fn, args, locals }[] }` 에는 **「걷힐
때 무엇이 도는가」를 그릴 자리가 없다.** C 에서는 프레임이 사라지는 것이 전부라 그 칸이 필요
없었고, C++ 은 사라지는 **순서대로 코드가 돈다.** 신청: `unwind: { name: string; order: number }[]`
— §11.6.

### §11.2 최고의 교재가 수렴한 순서

| 교재 | 값·타입·식 | 흐름 | 컨테이너 | **원시 포인터** | 동적 할당 |
|---|---|---|---|---|---|
| Stroustrup, *PPP* 3판 (2024) | **2장** Objects, Types, and Values | 3장 Computation | **3.6 `vector`** | **16장** Arrays, Pointers, and References | 15장 Free Store |
| learncpp.com | 4장 Fundamental Data Types · 5 Constants and Strings · 6 Operators · 10 Type Conversion | 8장 Control Flow | 16장 `std::vector` · 17장 array | **12장** Compound Types: References and Pointers | 19장 |

**PPP3 도 C 의 셋과 같다 — 2장이 타입과 값이다.** K&R(2장)·Seacord(2~4장)와 합치면
**넷이 2장을 값·타입·식에 준다**(`c-learning.md` §11.2). 0부가 §2 앞인 근거가 C++ 에서 한 번 더 선다.

**갈리는 것 — 원시 포인터를 컨테이너보다 먼저 보나 나중에 보나.**

- **PPP3: `vector`(3.6) → 포인터(16장).** 열두 장 차이다. 이유가 적혀 있다 — 이 책은 「남이 쓰고
  유지할 만한 프로그램」을 목표로 하고 「모호한 언어 기술 세부보다 **근본 개념과 기법**」에
  집중한다고 표지 설명이 말한다.
- **learncpp: 포인터(12장) → `std::vector`(16장).** 역순이다. **이유는 안 적혀 있다** — 각 장이
  배치 근거를 대지 않는다(사이트 전체를 읽지 않았으므로 「확인 못 함」이다).
- **C++ Core Guidelines 는 교육 지침이 아니다.** In.not 이 「이 지침은 C++ 튜토리얼 처리의
  대체물이 아니다」라고 못박고 대상은 In.target 「모든 C++ 프로그래머」다. 그러므로 **「Core
  Guidelines 가 원시 포인터를 늦게 가르치라고 했다」는 못 쓴다.** R 절(자원 관리)은 코드 규칙이지
  교육 순서가 아니다. 이번 조사의 유일한 **부정** 결과이고, 적어 두는 이유는 그 주장이 흔하기
  때문이다.

**어느 쪽이 근거가 있나 — 둘 다 실험 근거가 없다.** 간접 근거가 각각 하나씩 있고 방향이 반대다.

| 쪽 | 간접 근거 | 강도 |
|---|---|---|
| 늦게(PPP3) | §9 오개념 12 중 **넷**(4·5·6·7)이 원시 포인터 + 수동 자원 관리에서만 난다. `vector` 를 먼저 주면 그 넷이 뒤로 밀린다 | 이 문서의 셈 — 실험 아님 |
| 일찍(learncpp) | Bruce-Lockhart & Norvell — **입문 C++ 교재 절반이 얕은/깊은 복사를 안 다룬다.** 늦추면 **아예 안 가르치게 되는** 위험이 그 수치다 | **2차 확인**(§10 이 원문 미열람이라고 적었고 이번에도 못 봤다) |

**우리 배치는 늦은 쪽이다.** §5 의 깊이에서 `std-vector`·`std-string` 이 1 이고
`smart-pointer`·`new-delete` 가 4 다 — 세 칸 차이. 다만 그 배치는 순서를 고른 것이 아니라
**prereq 그래프가 낸 것**이라 PPP3 와 우연히 같아졌다. **근거로는 약하다.**

### §11.3 이 언어에 특유한 연습 형태

| 후보 | T1 | T2 | T3 | 판정 | 형식 | 그림 |
|---|---|---|---|---|---|---|
| ① 복사·이동 **횟수 세기** | ○ | ○ `[class.copy.ctor]` | ○ | **통과 — 가장 깨끗하다** | `table` 세 칸(복사 N · 이동 M · 소멸 K) | 스택 프레임 |
| ② 소멸자 호출 **순서** 적기 | 부분 | ○ | ○ | **부분 — 「결정적 소멸이 있는 언어군」**(C++·Rust) | `trace-table` (열 = **객체**) | 스택 프레임 + `unwind` |
| ③ 슬라이싱 예측 | ○ | ○ `[class.derived]` | ○ | **통과** | `value` | 메모리 줄 |
| ④ 수명 끝 예측(매달린 참조) | 부분 | ○ | ○ | 부분 — C·Rust 에도 있다 | `value`(줄 번호) | 스택 프레임 |
| ⑤ `auto` 가 무엇을 떨어뜨리나 | ○ | ○ `[dcl.type.auto.deduct]` | ○ | **통과** | `table` | 값 상자 |

**① 이 왜 통과하나 — T1 을 뒤집으면 셀 것이 사라진다.** 자바·파이썬·JS·C# 은 대입이 참조
복사라 횟수가 늘 0 이고, C 는 복사가 `memcpy` 라 관측할 사용자 코드가 없고, Rust 는 이동이
기본이고 복사가 `Clone` 의 명시 호출이라 **세는 것이 아니라 읽는 것**이다. **복사 횟수가 관측
가능한 값이 되려면 복사 생성자가 부수 효과를 가질 수 있어야 하고, 그것이 C++ 값 의미론의
정의다.** 「다른 언어에서 성립하지 않는 이유가 이 언어의 의미론에 있다」의 요구를 이 문장이 채운다.

**① 의 함정 — 복사 생략.** C++17 부터 prvalue 초기화의 생략이 **의무**다. 그러면 정답이
「구현에 달렸다」가 되는 자리가 생기고 **그것은 C 의 UB 와 같은 모양의 문제**다. 처방도 같다 —
`c-learning.md` §11.4 가 제안한 `ub-as-value` 의 C++ 판으로 분류 `elided` 하나. 그리고 문항
생성기가 **C++17 이후 의무 생략 자리를 피해야 한다.** 명시적 제약이고, 안 지키면 학습자가
「내가 틀렸다」로 배운다.

**② 는 C++ 특유가 아니다.** Rust 도 `drop` 이 선언 역순이다. 정확한 이름은 **「결정적 소멸이 있는
언어군」**(C++·Rust)이고, `pedagogy.md` §4 가 「C 메모리 그리기」를 「주소가 보이는 언어군」으로
판정한 것과 같은 자리다 — **그 판정의 두 번째 사례**다. 좁히면 통과하는 판이 하나 있다:
**예외가 던져진 뒤의 소멸 순서**(스택 되감기). Rust 는 `panic = "abort"` 로 되감기를 끌 수 있고,
**예외로 되감는 것은 C++ 뿐**이다. §3 의 `cpp/exception-handling` 이 이미 「던지면 사이의 지역
객체 소멸자가 전부 불린다」를 적어 두었다.

**② 의 형식이 `trace-table` 인데 열이 「변수」가 아니다.** 필요한 것은 **시간 × 객체**이고 칸은
값이 아니라 상태 셋(살아 있음 · 소멸 중 · 소멸됨)이다. `c-learning.md` §11.6 이 「시간 × 주소」로
낸 신청과 같은 것이고 **셋째 축이 여기서 는다.**

**`order`(Parsons)로 소멸 순서를 내면 안 되나 — 안 된다.** 정답 순열이 **선언 순서의 역이라
규칙 하나로 계산된다.** 학습자가 규칙만 외우면 조각을 옮겨 100% 가 나오고, 그것이
`pedagogy.md` §3.3 이 `subgoal` 을 뺀 이유(고르게 하면 재려던 것을 안 잰다)와 같은 결이다.
`trace-table` 은 **회차마다 어느 객체가 아직 살아 있나**를 묻기 때문에 규칙 하나로 안 접힌다 —
예외·조기 `return`·임시 객체가 섞이면 격자가 규칙을 벗어난다. **새 형식은 필요 없다.**

### §11.4 연구된 오개념과 그 진단

**이번 조사에서 C++ 오개념의 1차 문헌을 새로 못 찾았다.** progmiscon.org 에 C++ 이 없는 것은
§9 가 이미 확인했고, Milne & Rowe(2002)·Bruce-Lockhart & Norvell 은 §10 이 「2차·초록만」이라고
적은 그대로이며 이번에도 원문을 못 봤다. **§9 는 12행 그대로 둔다** — 근거 없이 행을 늘리지 않는다.

할 일이 있는 쪽은 **진단**이다.

| 오개념 | 문항 | 그 오답 | 아홉 분류로 잡히나 |
|---|---|---|---|
| 8 `7 / 2` | 그 값 | `3.5` | **잡힌다** — `other-language`(파이썬) |
| 10 `int x;` 는 0 | 그 값 | `0` | 안 잡힌다 — C 와 같은 이유(`c-learning.md` §11.4) |
| 2 값 전달은 복사다 | **복사 횟수** | `0` | **안 잡힌다** — 값 오답이 아니라 **횟수 오답**이다 |
| 11 `v2 = v1` 뒤 `v1` | 「`v1` 이 바뀌나」 | `true` | 안 잡힌다. 파이썬 리스트에서 참이라 `other-language` 로 **잘못 잡힐 위험**이 있는데, 파이썬에 `std::vector` 가 없어 `siblings` 를 못 굽는다 — 그래서 실제로는 `unknown` 이다 |
| 12 `auto x = v[0]` | 「`x` 를 고치면 `v[0]` 이 바뀌나」 | `true` | 안 잡힌다 |
| 7 슬라이싱 | 가상 함수 호출 결과 | 파생 쪽 답 | 안 잡힌다 |

**새 분류 하나를 제안한다 — `count-off`.** 세는 문항에서 하나 적거나 많게 셌다. 진단문을 사람이
안 적어도 된다: 정답지가 복사 N · 이동 M · 소멸 K 를 **따로** 세므로 **어느 칸이 틀렸는지가 곧
진단**이다(「이동을 복사로 셌다」·「임시 객체의 소멸을 안 셌다」). `c-learning.md` §11.4 의
셋(`ub-as-value` · `promotion` · `off-by-one`)에 넷째로 붙고, **그 셋 중 앞의 둘은 C++ 에도 그대로
걸린다** — §0.2 가 부호 있는 넘침과 암묵 변환 두 자리를 C 와 같다고 적었다.

### §11.5 우리 앱에서 그 학습법이 서는 자리

**실측이 C 보다 나쁘다.** §0.7 — `.cpp`·`.cc`·`.cxx`·`.hpp` 가 **0장**이다. C 는 빌드 산출물이라도
14장이 잡히는데 C++ 은 그것도 없다.

| 단 | C++ 에서 무엇을 묻나 | 재료 | 상태 |
|---|---|---|---|
| 1 읽기 | 짚기 · 값 적기 · 횟수 세기 | 사전 + 카탈로그 | 선다(합성) |
| 2 추적 | 「먼저 도는 줄」 | `exec-facts` | 선다. **생사 추적은 없다** — 아래 |
| 3 예측 | 「이 줄을 지우면」 | 가드 카탈로그 | **C++ 항목 0개** |
| 4 수정 · 5 재구현 | `fix:` 커밋 · 스펙 카드 | — | **안 선다 — 파일이 0장** |

**2단의 값 추적이 C++ 에서는 「생사 추적」이다.** `pedagogy.md` §1.2 가 잡은 구멍(연구의 tracing 은
값과 상태를 굴리는 것인데 앱의 2단은 경로다)이 C 에서는 「주소와 칸」으로, C++ 에서는 **「누가
언제 죽나」**로 나타난다. 같은 `trace-table` 확장이 둘을 다 받는다.

**판단 — C++ 은 코스를 열지 않는다.** C 에는 「기계 설명」이라는 남는 자리가 있는데
(`c-learning.md` §11.5) **C++ 에는 그것이 없다.** C++ 이 더하는 넷(수명 · 값 의미론 · 참조 · 이동)은
`cs/` 층(기계)이 아니라 **언어 설계** 층이고, 그 층은 다른 언어가 각자 자기 어휘로 가르친다 —
Rust 의 소유권, 파이썬의 컨텍스트 매니저, 자바의 try-with-resources. C 를 남기는 근거였던
「열 언어 중 여기서만 기계가 보인다」가 C++ 에는 성립하지 않는다.

**예외 하나 — 사용자 리포에 `.cpp` 가 실제로 있으면 연다.** 게임 엔진·네이티브 확장이 그 자리다.
그때 근거는 리포이지 이 문서가 아니고, §8 의 「확인 못 함」 넷(특히 `Widget w(x);` 의 실제 파싱과
`.h` 를 어느 문법으로 읽나)이 착수 전 실측 목록이 된다. **그래서 `cpp.md` 는 명세로 완성해 두고
착수 순위를 마지막에 둔다** — `README.md` §10 의 저작 순서에 넘긴다.

**0장 상한 폐지(D184)의 결과 — C++ 에서.** 이득이 셋 중 가장 작다. §5 가 21/24 로 마진 셋을
갖고 있었으므로 **상한이 있어도 C++ 은 안 잘렸다.** 대신 D184 가 **새 문제 하나를 만든다** —
§0.1 의 열셋 중 여섯이 C 와 **같은 개념**인데(`integer-type` · `overflow` · `float-type` ·
`char-literal` 계열) `universal` 이 대부분 `null` 이라 D4 전이가 안 돈다. §6 의 「`c/` 와의 관계」가
「같은 `universal` 이 아니라 **같은 개념**」이라고 적어 둔 그 자리다. 상한이 없어져 양쪽 프롤로그에
전부 들어가면 **C 를 먼저 한 사용자가 C++ 프롤로그에서 같은 것을 두 번 본다.** 판단: **문제이되
C++ 만의 문제가 아니고**, 답은 상한이 아니라 §6 의 미결(같은 개념을 어떻게 잇나)에 있다.
D184 는 그 미결을 앞당겼을 뿐 만들지 않았다.
