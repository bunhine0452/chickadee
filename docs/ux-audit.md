# UX 감사 — 앱을 실제로 돌려 찾은 불편 (D170)

**결정 등록부** D170. 사용자 요청: 「지금 UX 관련해서도 불편함이 많아 이를 조사하고 chickadee 를
정교한 학습 소프트웨어가 될 수 있도록」.

2026-09-05, mockIPC 하네스(`tests/support/*` · D108)로 앱을 띄워 첫 실행 → 리포 등록 → 인제스트 →
홈 → 세션(T0 두 장 · 사다리 1~4단 · 오답 · 정답 · T2 영향 반경 · 요약) → 설정 → 서가 → 클론 코스
→ 야간반 → 최소 창(1000×680)을 눌렀다. 화면마다 스크린샷과 계측(13px 미만 활자 · 가로 넘침 ·
이름 없는 단추 · 포커스 · 스크롤 오프셋)을 남겼고, 그 파일 이름을 근거 열에 적었다. 계측 결과
13px 미만 활자 0 · 가로 넘침 0 · 이름 없는 단추 0 — 정본 §6 의 활자 규칙은 지켜지고 있다.
문제는 규칙 밖에서 났다.

**한계.** 시드는 `tiny`(파일 5 · 커밋 0) 하나라 대지·스티커·노드 상세·T1 필사 판은 화면으로
못 봤고 코드로만 봤다. 실제 Tauri 창은 병렬 세션 다섯이 같은 트리를 고치는 중이라 띄우지 않았다
— 감사 주행은 `HEAD` 워크트리에서 했다. 코스 화면(D162·D171)은 아직 없어 이 감사의 대상이 아니다.

## 3. 코스(D162)로 넘어가면 지금 화면과 부딪히는 자리 — A7(코스 화면)에 넘긴다

코스는 단위가 **기능**이고 진도가 **단(stage)**이다. 지금 화면은 단위가 판이고 진도가 겹이다.
아래는 그대로 두면 두 축이 한 화면에서 서로 다른 말을 하게 되는 자리다.

| 자리 | 지금 | 코스에서 |
|---|---|---|
| 홈 「오늘의 인쇄」 | 판 N장 · 분 | 「오늘 챕터의 다음 단」 + 「만기 재검」 두 줄. 판 수는 그 안의 수치 |
| 작업 띠 진행바 | 판 단위 시간 비례 | 단 단위(읽기·추적·예측·수정) 시간 비례. 관문(어휘 6판)은 앞에 붙는 칸 |
| 판 머리 「N판 · T0 · 의미형 · 새 판」 | 트랙·유형 | 「로그인 · 2단 추적 · hop」 — 챕터·단·유형. `T0/T1/T2` 알약은 단 뒤로 |
| 잉크 겹(스티커·레일·요약) | 주 진도 | 1·2단 어휘 판정기로 강등(D162 ④). 시각은 남기되 진도 자리에서 뺀다 — 얼마나 지울지는 **사용자 결정**(`docs/program/mastery.md` §8) |
| 마스트헤드 「코스」 단추 | 클론 코스(D120 · T1 필사) | 이름이 겹친다. 새 코스가 「코스」면 클론 코스는 「통째 필사」로 |
| 요약 「오늘 움직인 잉크」 | 겹 변화 목록 | 「오늘 오른 단」이 먼저, 겹은 그 아래 |
| T2 지도 판 | 대지 단위 종 여섯 | 코스 2단 `hop` 과 3단 `contract` 가 같은 지도를 쓴다. 지도 컴포넌트(`DependencyMap`)는 재사용, 판 껍데기는 단의 것 |
| 「모르겠어요」 사다리 | T0 4단 | 단마다 처방이 다르다(`mastery.md` §5) — 2단은 경로 접기, 4단은 프롬프트. 사다리 껍데기에 단별 몸통 |
